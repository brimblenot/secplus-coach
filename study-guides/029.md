## Malicious Updates

Software updates are one of the most trusted actions a user or system can take — and that trust is exactly what sophisticated attackers exploit. This lesson covers how malicious updates work, the major real-world attacks that used them, and the defenses that can break the chain.

---

### Why update channels are high-value targets

A **malicious update** is a software update that has been tampered with — either at the vendor's infrastructure, in transit, or in a dependency — so that installing it delivers malware instead of (or alongside) a legitimate fix.

The attack is powerful because of the **chain of trust**: users have been conditioned to install updates, security tools often apply less scrutiny to update traffic, and the update arrives through the same channel that has worked safely hundreds of times before.

**How to evaluate whether an update prompt is legitimate:**
- ✅ Prompt appears *inside* the application when you first open it → reasonable trust
- ❌ Popup appears while browsing a random website → red flag (fake "drive-by" update page)
- ✅ Download directly from the official vendor site, not third-party mirrors
- ✅ Valid digital signature from a known **CA** (Certificate Authority — a trusted entity that issues cryptographic certificates proving identity) → meaningful signal, but *not a guarantee* — signing infrastructure can itself be compromised

> Think of the update channel like a pharmacy's pill bottle with a tamper-evident seal: the seal is strong evidence of legitimacy, but if someone got into the pharmacy before the bottle was sealed, the seal means nothing.

### The SolarWinds Orion attack (2020)

**SolarWinds Orion** is a network monitoring and management platform used by thousands of large organizations, including US government agencies.

**What happened:**
- Attackers (**Cozy Bear** — a Russian intelligence-affiliated **APT**, or Advanced Persistent Threat group — a state-level attacker that maintains long-term, stealthy access to targets) compromised SolarWinds' **build pipeline** — the automated process that compiles source code into a finished software package
- They inserted a backdoor called **SUNBURST** directly into the Orion source code, so it was compiled into the legitimate binary
- SolarWinds signed the result with their real **code-signing certificate** — a cryptographic credential that proves a file came from a specific publisher — so it passed every standard authenticity check
- ~18,000 organizations installed the trojanized update; victims included the US Treasury, DOJ, DHS, and NSA

**SUNBURST's evasion techniques:**
- Stayed **dormant for ~2 weeks** to escape sandbox tools (which only observe behavior for short periods)
- Disguised its **C2** — command-and-control — traffic as normal Orion network communication
- Checked for security analysis tools and avoided activating in monitored environments

> SolarWinds is like a poisoned water supply: the attacker didn't break into each house — they got into the treatment plant, so every house that trusted the tap got contaminated.

### ASUS ShadowHammer (2019)

Attackers compromised ASUS's **Live Update server** — the infrastructure that pushes firmware and driver updates — and distributed a malicious update signed with ASUS's real certificate to ~1 million users.

**The precision twist:** The malware checked each infected machine's **MAC address** — a hardware identifier unique to each network adapter — against a hardcoded list of ~600 specific targets. Only those machines received the active payload. Everyone else saw a routine, silent update — making detection extremely difficult.

### 3CX supply chain attack (2023) — second-order compromise

This attack cascaded through *two* supply chains:
1. Attackers compromised **X_TRADER** (financial trading software) and injected a trojan
2. A 3CX employee installed the compromised X_TRADER; attackers used that foothold to infiltrate **3CX**'s development environment
3. 3CX's legitimate **VoIP** — Voice over IP — enterprise desktop app builds were then trojanized and pushed to 3CX customers worldwide

> Like a poisoned ingredient supplier: the restaurant (3CX) didn't know their flour supplier (X_TRADER) was already compromised, so every meal (update) they served carried the contamination forward.

### Dependency confusion and package registry attacks

Modern software relies on **package managers** — tools that automatically download and install open-source code libraries from central registries such as **npm** (JavaScript), **PyPI** (Python), **Maven** (Java), and **RubyGems** (Ruby).

**Dependency confusion** exploits how package managers resolve names when both a private internal registry and a public registry are configured:

- Attacker publishes a malicious package to a *public* registry using the *same name* as a company's private internal package, but with a *higher version number*
- The package manager prefers the higher version — from the public registry — and installs the malicious one instead
- Security researcher **Alex Birsan** demonstrated this against Microsoft, Apple, PayPal, Netflix, Tesla, and Shopify in 2021, achieving remote code execution inside their build systems

**Typosquatting in registries** mirrors domain typosquatting: attackers publish packages with names nearly identical to popular ones (`colourama` vs. `colorama`, `request` vs. `requests`). A developer's small typo installs malware.

**Maintainer hijacking (event-stream, 2018):** An attacker contributed to a legitimate, popular npm package, earned maintainer privileges, then injected code targeting Bitcoin wallet credentials from one specific cryptocurrency app.

> Dependency confusion is like a vending machine that prefers the snack at the top slot — an attacker just put their snack one slot higher than yours.

### Malicious browser extension updates

Browser extensions often request broad permissions at install time — read and modify content on all websites. A **malicious browser extension update** delivers new malicious functionality through the browser's own update mechanism *without requiring the user to re-approve permissions*, because the extension already has them.

### Defenses across the software supply chain

| Defense | What it is and what it does |
|---|---|
| **SBOM** (Software Bill of Materials) | A complete inventory of every library, component, and dependency in a product, with versions and origin; required for federal software vendors by US Executive Order 14028 |
| **Code signing** | Cryptographic signature from the vendor proves the file hasn't been altered — necessary but not sufficient, since signing keys can be stolen |
| **Cryptographic hash verification** | Comparing a downloaded file's **SHA-256** hash — a fixed-length fingerprint of the file's contents — against a hash the vendor published through a *separate* channel; detects tampering even when a signature is valid |
| **Private package registries with namespace controls** | Ensures internal package names cannot be satisfied by a public registry package |
| **Dependency scanning** (Snyk, Dependabot, OWASP Dependency-Check) | Continuously checks project dependencies against public **CVE** — Common Vulnerabilities and Exposures — databases and alerts on known-vulnerable versions |
| **Reproducible builds** | Verifying that compiling the same source code always produces bit-for-bit identical output; any variation signals something unexpected was introduced into the build environment |
| **Binary authorization** | Policies that allow only pre-approved, cryptographically signed software artifacts to execute in an environment |

---

### Recap
- Malicious updates exploit the **chain of trust** in update channels; even digitally signed packages can be malicious if the signing infrastructure is compromised
- **SolarWinds/SUNBURST** showed that compromising the **build pipeline** lets attackers reach tens of thousands of organizations through a single trusted mechanism
- **Dependency confusion** abuses package manager resolution logic to substitute a public malicious package for a private internal one
- **SBOM** + **cryptographic hash verification** + **reproducible builds** address the parts of the supply chain that code signing alone cannot protect

### Exam flags
- The **SolarWinds** attack mechanics — build pipeline compromise, SUNBURST dormancy, legitimate code-signing certificate — are high-probability scenario questions
- **Dependency confusion** vs. **typosquatting** — know the difference: confusion exploits name resolution priority; typosquatting exploits developer typos
- **SBOM** as a supply chain defense and its link to US federal mandates (EO 14028)
