## Secure Infrastructures (Domain 3)

Modern networks can't rely on a single wall to keep attackers out — phishing, stolen credentials, and supply chain attacks all get inside that wall. This lesson covers how layered design, segmentation, and access controls work together to limit damage when (not if) something gets through.

---

### Defense in depth

**Defense in depth** is the principle of stacking multiple, independent security controls so an attacker who bypasses one immediately faces another.

- No single control is trusted to stop everything
- Layers span physical → network → host → application → data → monitoring
- Each layer provides independent protection; together they create a resilient posture

> Think of it like a medieval castle: moat, drawbridge, outer wall, inner wall, keep — an attacker who crosses the moat still has four more obstacles.

---

### Network segmentation and the DMZ

**Network segmentation** divides a network into distinct zones, limiting how far an attacker can move after an initial breach (reducing the "blast radius").

The foundational three-zone model:

| Zone | Trust level | Typical contents |
|------|-------------|-----------------|
| Internet | Untrusted | External traffic |
| **DMZ** (Demilitarized Zone) — a semi-trusted middle zone | Semi-trusted | Public web, email, DNS servers |
| Internal network | Trusted | Corporate systems, databases |

**Key DMZ firewall rules:**
- Internet → DMZ: allowed only on specific ports (80/443 for web)
- Internal → DMZ: allowed (admins manage DMZ servers)
- DMZ → Internet: allowed for legitimate purposes (email delivery, updates)
- **DMZ → Internal: BLOCKED** — prevents a compromised web server from pivoting deeper into the network

> A compromised DMZ server is like a burglar trapped in your airlock — they got past the front door but can't reach the house.

---

### Screened subnets

A **screened subnet** is a protected zone sandwiched between an outer firewall (facing the internet) and an inner firewall (facing the trusted internal network).

- An attacker must compromise **both** firewalls to reach internal systems
- This two-firewall design is the core pattern for high-security architecture

---

### Implicit deny and least privilege

**Implicit deny** means all traffic is blocked by default unless a firewall rule explicitly permits it — the opposite of "allow all, block known bad."

- New services require a deliberate, reviewed decision to allow
- Prevents unknown attack types from slipping through unchecked

**Least privilege for network traffic** means firewall rules allow only the minimum necessary: specific source IPs, destination IPs, protocols, and ports for a defined business function — not broad "allow everything from the office" rules.

---

### Security zones

**Security zones** are logical groupings that extend segmentation across the whole infrastructure with named policies between zones.

Common zones: Internet, DMZ, Screened, Internal, Server, Database, Management, **IoT** (Internet of Things — connected devices that typically have poor built-in security).

- Zone-based policies are easier to audit than rules written per individual host
- Naming conventions (trusted, untrusted, screened) make intent immediately clear and reduce misconfiguration

---

### Bastion hosts and privileged access

A **bastion host** (also called a **jump server** or **jump host**) is a hardened, minimal system that acts as the single controlled entry point for administrative access into a protected network segment.

- Runs only software necessary for its function — nothing extra
- Requires **MFA** (multi-factor authentication) to connect
- All sessions are logged and ideally recorded for forensic use
- **Just-in-time access** — access is granted for a defined time window, then automatically revoked

**PAM** (Privileged Access Management) solutions such as CyberArk and BeyondTrust provide enterprise bastion functionality with session recording and ticketing integration.

> A bastion host is like a secure reception desk: every visitor must check in here first, show ID, and is escorted — no one walks directly to the back office.

---

### Zero trust

**Zero trust** is a security model built on "never trust, always verify" — it removes the implicit trust that traditional networks gave any device already inside the perimeter.

- Every access request is authenticated and authorized against a specific policy, regardless of network location
- Authorization is evaluated **per-request**, not granted once for a session
- **ZTNA** (Zero Trust Network Access) is the technology implementation, replacing traditional **VPN** (Virtual Private Network — a tunnel granting broad internal network access after a single login)
- Where VPN grants broad network access after one authentication, ZTNA grants access only to specific authorized applications, continuously re-evaluated

---

### Cloud VPC design

A **VPC** (Virtual Private Cloud) is an isolated private network within a cloud provider, mirroring on-premises segmentation concepts.

| Component | Function |
|-----------|----------|
| **Public subnet** | Routes to internet gateway; hosts load balancers, web servers |
| **Private subnet** | No direct internet route; hosts databases, backend servers |
| **Security group** | Stateful firewall at the instance level |
| **Network ACL** | Stateless filtering at the subnet level |
| **VPC Flow Logs** | Captures traffic metadata for monitoring and forensics |

---

### Layer 2 switch security

These controls protect the switching layer against local network attacks:

- **Port security** — limits MAC addresses per port; shuts port if exceeded
- **Sticky MAC learning** — switch dynamically learns and saves the expected device's **MAC address** (hardware identifier burned into a network interface), enforcing that only that device can connect
- **DHCP snooping** — **DHCP** (Dynamic Host Configuration Protocol — assigns IP addresses to devices) snooping validates DHCP messages and blocks offers from untrusted ports, preventing rogue DHCP servers from redirecting traffic
- **Dynamic ARP Inspection** — **ARP** (Address Resolution Protocol — maps IP addresses to MAC addresses) inspection validates ARP packets against the DHCP snooping table, dropping spoofed responses

---

### Physical and out-of-band management

- Cabling runs through locked conduits; wiring closets are locked and access-logged
- **Out-of-band management** networks are dedicated, separate from production — admins can still reach devices even if the production network is down or compromised
- Dedicated management interfaces (**IPMI**, **iDRAC**, **iLO** — hardware-level remote console interfaces) provide console access independent of the primary network

---

### Recap

- **Defense in depth** stacks independent layers so no single failure is catastrophic
- The **DMZ** hosts public-facing servers; the critical rule is DMZ → Internal is blocked
- **Implicit deny** blocks all traffic by default; only explicitly approved traffic flows
- A **bastion host** is the single, hardened, logged entry point for admin access
- **Zero trust / ZTNA** replaces implicit perimeter trust with per-request, continuous verification

### Exam flags

- Screened subnet two-firewall architecture and why DMZ-to-internal traffic must be blocked
- ZTNA vs. VPN: what ZTNA grants (specific apps, continuous evaluation) vs. what VPN grants (broad network access after one auth)
- Layer 2 controls: which tool (port security, DHCP snooping, Dynamic ARP Inspection) solves which attack
