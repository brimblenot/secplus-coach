## Secure Communication (Domain 3)

Every time data crosses a network, it can be intercepted, read, or altered. This lesson covers the encrypted protocols and architectures — VPNs, IPsec, TLS, SSH, and secure file transfer — that protect data in transit, and the specific scenarios where each one belongs.

---

### Virtual Private Networks (VPNs)

A **VPN** — Virtual Private Network — creates an encrypted tunnel over an untrusted network (usually the public internet) so private traffic can travel securely between endpoints, as if the two sides shared a local network.

**Two main types:**

| Type | Who it connects | Requires client software? | Always-on? |
|---|---|---|---|
| **Site-to-site VPN** | Two full networks (e.g., branch ↔ HQ) | No — gateways handle it | Yes |
| **Remote access VPN** | One user ↔ corporate network | Yes (client-based) or browser (clientless) | No — user-initiated |

- **Client-based remote access** — installs VPN software (e.g., Cisco AnyConnect) on the endpoint; authenticates to a VPN gateway.
- **Clientless remote access** — uses a web browser over SSL/TLS; no software install needed; common for contractor/unmanaged-device access.
- Site-to-site VPNs often replace expensive **MPLS** — Multiprotocol Label Switching, a dedicated private WAN circuit — with cheaper internet bandwidth.

*Analogy: A site-to-site VPN is like a locked pneumatic tube between two buildings — packages travel through public space, but no one outside can open them.*

### IPsec — the protocol suite behind most VPNs

**IPsec** — Internet Protocol Security — is a suite of protocols that provide encryption, authentication, and integrity at the network layer. It has three components:

| Component | What it does | Encrypts? |
|---|---|---|
| **AH** (Authentication Header) | Proves the packet came from the right sender and wasn't modified | ❌ No |
| **ESP** (Encapsulating Security Payload) | Encrypts payload AND authenticates | ✅ Yes |
| **IKE** (Internet Key Exchange) | Negotiates which algorithms to use; exchanges keys | — |

- **ESP** is what actually provides VPN confidentiality — AH alone is almost never used in VPNs.
- **IKEv2** — the current key-exchange version — is more efficient and supports **MOBIKE**, which lets a VPN session survive an IP address change (e.g., switching from Wi-Fi to cellular).

**Two IPsec modes:**

| Mode | What gets encrypted | Used for |
|---|---|---|
| **Transport mode** | Payload only — original IP header stays visible | Host-to-host (e.g., two data center servers) |
| **Tunnel mode** | Entire original packet (header + payload) wrapped in new packet | All VPN gateways; hides real source/destination IPs |

*Exam flag: tunnel mode hides original IP addresses; transport mode does not.*

**Diffie-Hellman** — a key-exchange algorithm that lets two parties derive a shared secret over an untrusted channel without ever transmitting it. Larger DH group numbers = stronger security. Groups 14, 19, 20, 21 (elliptic-curve) are recommended today.

**Perfect Forward Secrecy (PFS)** — a property where fresh Diffie-Hellman keys are negotiated for each session, so compromising long-term credentials cannot expose past sessions.

*Analogy: DH is like two people mixing private paint colors in public — each adds a secret shade, and the final combined color can't be reverse-engineered by onlookers.*

### SSL/TLS VPN vs. IPsec VPN

**SSL/TLS VPN** uses **TLS** — the same protocol securing HTTPS — instead of the IPsec suite.

| | SSL/TLS VPN | IPsec VPN |
|---|---|---|
| Port | TCP 443 | UDP 500/4500, ESP protocol 50 |
| Firewall-friendly | ✅ Almost always open | ❌ May be blocked or break NAT |
| Common use | Remote access (hotels, coffee shops) | Site-to-site and enterprise remote access |

*Analogy: SSL/TLS VPN sneaks through firewalls disguised as normal HTTPS — like wearing a postal service uniform to walk past security unchallenged.*

---

### Split tunneling vs. full tunneling

| | Full tunneling | Split tunneling |
|---|---|---|
| What goes through VPN | All traffic | Only corporate-destined traffic |
| Corporate visibility | ✅ Full — web filtering, IPS, DLP apply | ❌ Internet traffic bypasses controls |
| Bandwidth use | Higher | Lower |
| Security risk | Lower | Malware could use direct internet path to reach C2 server while VPN is active |

**Always-on VPN** — VPN established automatically at boot and kept active at all times, so users never accidentally operate on an untrusted network without protection.

### TLS — securing internet traffic

**TLS** — Transport Layer Security — encrypts the vast majority of internet traffic. **HTTPS** is HTTP running over TLS.

**TLS version security:**

| Version | Status | Notes |
|---|---|---|
| TLS 1.3 | ✅ Current, preferred | Requires PFS; removes RSA key exchange and CBC ciphers; faster handshake |
| TLS 1.2 | ⚠️ Acceptable | Must be carefully configured to avoid weak ciphers |
| TLS 1.0 / 1.1 | ❌ Deprecated | Vulnerable to BEAST, POODLE, CRIME |
| SSL 2.0 / 3.0 | ❌ Never use | Severely vulnerable |

**TLS 1.3 key changes:**
- RSA key exchange is removed because it did NOT provide PFS — if the server's private key was ever stolen, all past sessions could be decrypted retroactively.
- Only **AEAD** — Authenticated Encryption with Associated Data — ciphers allowed: **AES-GCM** and **ChaCha20-Poly1305**.
- Fewer handshake round trips = faster connections.

**Three TLS security properties:**
1. **Confidentiality** — symmetric encryption (AES-GCM) of the payload.
2. **Integrity** — AEAD detects any ciphertext tampering.
3. **Authentication** — server's digital certificate verified against trusted **CAs** (Certificate Authorities — trusted third parties that sign and vouch for certificates).

### SSH — secure remote administration

**SSH** — Secure Shell — is the encrypted protocol for remote command-line access to other machines. It replaces **Telnet**, which transmitted everything — including usernames and passwords — in cleartext over TCP port 23.

- SSH runs on **TCP port 22**.
- Provides: encrypted shell sessions, file transfer (SCP/SFTP), and **port forwarding** — tunneling other protocols through an encrypted SSH connection.

**Two SSH authentication methods:**

| Method | How it works | Security |
|---|---|---|
| **Password auth** | Password sent encrypted inside established SSH session | Vulnerable to brute force and credential theft |
| **Public key auth** | Admin's public key stored in server's `authorized_keys` file; private key never leaves the client | Immune to brute force and password capture |

- **SSH key management** — tracking which keys are authorized on which servers, rotating them regularly, revoking them when staff leave — is a critical and often neglected practice.

*Analogy: SSH public key auth is like leaving a padlock (public key) at the server's door — only the person with the matching key (private key) can open it, and the key never gets handed over.*

---

### Secure file transfer protocols

**SFTP** — SSH File Transfer Protocol — encrypted file transfer running over SSH on TCP port 22. Despite the name, it has nothing to do with FTP; it's a completely separate protocol built on SSH.

**FTPS** — FTP Secure — standard FTP extended with TLS encryption. Two modes:

| Mode | How TLS starts | Port |
|---|---|---|
| **Explicit FTPS** | Client connects on FTP port 21, then upgrades via AUTH TLS command | 21 |
| **Implicit FTPS** | TLS established immediately | 990 |

- SFTP is generally preferred for new deployments — SSH is simpler to deploy and SFTP requires only one port through a firewall, whereas FTPS (like plain FTP) uses separate control and data channels that complicate firewall rules.

*Analogy: SFTP is like shipping files inside a locked SSH armored truck; FTPS is like bolting a TLS lock onto an old FTP wagon — it works, but the wagon's quirky door-and-cargo-hatch setup still causes problems at checkpoints.*

---

### Recap

- **Site-to-site VPN** = always-on, no client software, gateway handles encryption; **remote access VPN** = user-initiated, requires client or browser.
- **IPsec tunnel mode** encrypts the entire original IP packet including headers; **transport mode** encrypts payload only and leaves headers visible.
- **TLS 1.3** mandates PFS and AEAD ciphers; TLS 1.0/1.1 are deprecated; SSL is dead.
- **SSH public key auth** is immune to password brute-force; **Telnet** sends credentials in cleartext.
- **SFTP** runs on SSH/port 22; **FTPS** is FTP+TLS and uses ports 21 or 990.

### Exam flags

- **IPsec mode comparison**: know that tunnel mode hides original source/destination IPs and is used for VPN gateways; transport mode does not hide them and is used for host-to-host.
- **TLS version deprecations**: TLS 1.0/1.1 deprecated (BEAST, POODLE, CRIME); TLS 1.3 removes RSA key exchange and CBC ciphers; know why (no PFS, vulnerable to known attacks).
- **Split tunneling risk**: malware on a split-tunnel client can reach a C2 server through the direct internet path while the VPN is active, bypassing corporate security controls.
