## Mitigation Techniques

Mitigation is the practice of reducing the impact, likelihood, or scope of a security event — before or after it happens. This lesson maps the key mitigation techniques the exam tests: what each one is, when to use it, and how they fit together.

---

### Patching

**Patching** is the process of applying vendor-released fixes to correct vulnerabilities in operating systems, applications, firmware, and device drivers.

- **Patch management** steps: inventory → test in non-production → deploy in maintenance window → verify → document
- **Automated tools**: **WSUS** (Windows Server Update Services — Microsoft's tool for pushing OS/app updates across a Windows environment); **MECM** (Microsoft Endpoint Configuration Manager — broader enterprise patch and device management); **Ansible** — an agentless configuration management tool used to deploy patches across mixed/Linux environments
- **Critical/zero-day vulns**: skip normal schedule → emergency patch with expedited or skipped testing when exploit risk outweighs stability risk

> Think of patching like recalling and replacing a faulty car part: if the part is actively causing crashes in the field, you replace it immediately rather than waiting for the next scheduled service.

---

### Encryption

**Encryption** transforms readable data into ciphertext so that an attacker who obtains the data cannot read it without the decryption key.

| Layer | Tool/Standard | What it protects |
|---|---|---|
| Full disk | **BitLocker** (Win), **FileVault** (macOS), **LUKS** (Linux) | Stolen/lost device |
| File-level | **EFS** (Windows Encrypting File System — encrypts individual files/folders) | Specific sensitive files |
| In transit | **TLS** (Transport Layer Security — encrypts data moving over a network) | Data intercepted on the wire |
| Application-level | App-specific encryption | Data within an app regardless of disk state |

> A stolen encrypted laptop is like a locked safe someone grabbed off the shelf — they have the box, but nothing usable inside.

---

### Monitoring

**Monitoring** provides the visibility needed to detect attacks, investigate incidents, and verify controls are working.

- **SIEM** (Security Information and Event Management) — aggregates and correlates logs from OS, network devices, firewalls, and auth systems; alerts analysts to suspicious patterns (e.g., failed logins → success from new location)
- **EDR** (Endpoint Detection and Response) — monitors host-level activity: process execution, file changes, registry modifications, network connections; behavioral, not just signature-based
- **NDR** (Network Detection and Response) — monitors network traffic for anomalous patterns
- **UEBA** (User and Entity Behavior Analytics) — baselines normal behavior per user/system; alerts on significant deviation; effective against insider threats and compromised accounts using valid credentials

> A SIEM is like a security operations center watching every camera feed at once; UEBA is the analyst who notices that a specific employee's badge is now swiping into the server room at 3 a.m. when they never have before.

---

### Isolation, containment, and quarantine

These three concepts work together during incident response but mean distinct things:

**Isolation** removes a compromised system from network access while preserving controlled access for investigation.
- Implemented via firewall rule changes or physically unplugging the cable
- Stops: attacker C2 (Command and Control — the channel attackers use to send instructions to compromised systems), lateral movement, and active data exfiltration

**Containment** is the broader incident response objective that isolation supports.
- Also includes: changing compromised credentials everywhere they were used, disabling unneeded services, adding emergency firewall rules, and preserving forensic evidence

**Quarantine** is the automated version — an **EDR** platform detects a suspicious host and moves it to a restricted network segment automatically, blocking all traffic except back to the EDR management system.

> Isolation is manually locking the door; quarantine is the building's automated security system sealing the room the moment a sensor trips.

---

### Compensating controls and exceptions

**Compensating controls** are alternative security measures used when a primary control cannot be applied — most commonly with legacy systems that cannot be patched.

- Example: unpatchable legacy system → restrict it to only required IPs/ports, add an application-layer firewall, and increase monitoring
- Formal concept in **PCI DSS** (Payment Card Industry Data Security Standard — a compliance framework for organizations handling card data) with documented approval process

**Exceptions and exemptions** are the formal process for acknowledging a control is NOT being applied.
- Must document: business owner acknowledgment, residual risk, entry in the **risk register** (the organization's tracked log of accepted risks), a review date, and ideally compensating controls
- Should be time-limited with a plan to reach full compliance

> A compensating control is like a construction detour: the main road is closed, so you add extra signage, guardrails, and a speed limit on the alternate route until the road reopens.

---

### Application removal and isolation

**Application removal** eliminates software entirely, permanently removing its attack surface: binaries, config files, open ports, scheduled tasks — all gone. This is more complete than simply disabling a service, because disabling leaves files and scheduled tasks in place that an attacker could still leverage.

**Application isolation** (sandboxing) runs an application in a restricted environment that limits what it can access even if exploited.
- Browser tab sandboxing, iOS/Android per-app sandboxes, **Windows AppContainer**, **macOS App Sandbox**, and application virtualization (streaming the UI to the client without installing the app locally)

> Removal is demolishing an unused building so no one can break in; sandboxing is keeping the building but surrounding it with a security perimeter so a break-in can't reach anything else.

### Deny listing vs. allow listing

**Deny listing** (blacklisting) blocks known-malicious applications, IPs, domains, or file hashes.
- **Reactive** — only blocks threats already identified; new/unknown malware isn't blocked until it's added

**Allow listing** (whitelisting) permits only explicitly approved applications, IPs, or behaviors; everything else is blocked by default.
- **Proactive** — blocks novel malware, zero-days, and living-off-the-land tools (attackers using built-in system tools to avoid detection) even before they're known, because they're simply not on the approved list
- Windows tools: **WDAC** (Windows Defender Application Control) and **AppLocker** — both enforce hash-, certificate-, or path-based rules
- Operational challenge: maintaining the approved list as software updates and changes

| | Deny listing | Allow listing |
|---|---|---|
| Stance | Block known bad | Permit known good only |
| Novel threats | ❌ Not blocked | ✅ Blocked by default |
| Maintenance burden | Low | High |

> Deny listing is a nightclub bouncer with a list of banned people — anyone not on the list walks in. Allow listing is a bouncer with a guest list — if your name isn't on it, you're not getting in, period.

---

### Scanning

**Scanning** is automated discovery and assessment of vulnerabilities and configuration weaknesses.

- **Credentialed scans** — authenticate to the target and inspect software versions and configs directly; more accurate
- **Uncredentialed scans** — only observe what's exposed over the network; less accurate
- **Web application scanners** — probe for SQLi (SQL injection), XSS (cross-site scripting), and access control misconfigurations
- **Configuration compliance scans** — compare settings against baselines like **CIS Benchmarks** (Center for Internet Security's published secure configuration standards)

> A credentialed scan is like an inspector with a building key who checks every room; an uncredentialed scan is an inspector who can only observe what's visible from the sidewalk.

---

### Least privilege and access creep

**Least privilege** means accounts have only the permissions they currently need — no more. **Access creep** is the gradual accumulation of excess permissions as users change roles, get added to projects, and never have old access removed.

- **Access recertification** campaigns periodically require managers to review and confirm each permission assignment is still appropriate, revoking anything that isn't

> Access creep is like a hotel guest who keeps getting extra keycards for different floors over multiple stays and never turns any of them in — eventually they have access to the whole building.

---

### Recap

- **Patching** eliminates known vulnerabilities; critical exploits require emergency patching outside normal schedules
- **Encryption** (at rest + in transit) ensures stolen data is unreadable; **monitoring** (SIEM, EDR, UEBA) ensures attacks are visible
- **Isolation** stops an active attack (C2, lateral movement, exfiltration); **quarantine** is the EDR-automated version
- **Allow listing** is proactive and blocks unknown threats by default; **deny listing** is reactive and only blocks known-bad items
- **Compensating controls** replace primary controls that can't be applied; **exceptions** formally document accepted risk with a review date

### Exam flags

- **Allow listing vs. deny listing**: know which is proactive vs. reactive and why allow listing blocks zero-days that deny listing cannot
- **Isolation vs. containment vs. quarantine**: know what each stops and which one is automated by the EDR platform
- **Compensating controls**: know the legacy-system scenario and that PCI DSS formally recognizes this mechanism
