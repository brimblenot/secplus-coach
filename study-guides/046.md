## DNS Attacks

DNS is the internet's phone book — and because every device trusts it implicitly, attackers have built an entire playbook around abusing it. This lesson covers the major DNS attack types, how each one works mechanically, and the defenses the exam expects you to know.

---

### How DNS works (the foundation)

**DNS** — the **Domain Name System** — translates human-readable names like `www.example.com` into IP addresses. Without it, users would type raw IPs for everything.

Key participants in a lookup:

| Role | What it does |
|---|---|
| **Recursive resolver** | Receives client query; does the full lookup on the client's behalf |
| **Root name server** | Points the resolver toward the right TLD server |
| **TLD server** | Handles suffixes like `.com`, `.org`, `.gov` |
| **Authoritative name server** | Holds the actual records for a specific domain |

- DNS uses **UDP port 53** for normal queries
- DNS uses **TCP port 53** for zone transfers and large responses
- DNS's original design had **no built-in security** — that's why attacks are so varied

---

### DNS cache poisoning (DNS spoofing)

**DNS cache poisoning** — also called **DNS spoofing** — is an attack where a forged DNS answer is injected into a recursive resolver's cache, causing the resolver to serve a malicious IP to every client that asks for that name until the **TTL** (time-to-live — the expiration timer on a cached DNS record) runs out.

- The attacker races to reply to an outstanding query *faster* than the legitimate authoritative server
- The **Kaminsky attack** (2008) showed that predictable transaction IDs and UDP source ports made this race very winnable — a flood of forged replies had a high chance of one being accepted
- Fix: **randomize both transaction IDs and source ports**, massively increasing guessing difficulty
- **DNSSEC** (covered below) eliminates cache poisoning entirely for protected domains

> Think of a poisoned resolver like a city's corrupted 411 directory: one bad entry gets read back to millions of callers until someone notices and corrects it.

---

### DNS hijacking

**DNS hijacking** redirects DNS queries to an attacker-controlled resolver *before* they ever reach a legitimate server — different from cache poisoning, which corrupts a legitimate resolver's data after the fact.

Common mechanisms:

| Vector | How it works |
|---|---|
| **Router compromise** | Attacker changes DNS server settings pushed via **DHCP** (the protocol that auto-assigns network config to clients) to point to a rogue resolver |
| **Malware / hosts file** | Malware edits local DNS settings or the **hosts file** — a static name-to-IP mapping file the OS checks *before* issuing any DNS query; on Windows at `C:\Windows\System32\drivers\etc\hosts` |
| **Registrar-level hijacking** | Attacker steals registrar credentials and changes the authoritative name servers for an entire domain globally |

The **2016 Brazilian bank attack** is the textbook example: attackers changed registrar settings for 36 domains, becoming the bank's entire internet presence for six hours and harvesting customer credentials.

> Registrar hijacking is like stealing the deed to a building — you don't break in, you just change who the city records say owns it.

### DNS tunneling

**DNS tunneling** encodes arbitrary data inside DNS queries and responses to create a covert communication channel through firewalls that allow DNS traffic.

- Attacker controls a domain and its authoritative server
- Client software encodes data (often **Base64** — a scheme that converts binary data into text characters) into subdomain strings, e.g., `aGVsbG8=.attacker.com`
- The authoritative server decodes the subdomain and encodes replies back in DNS answer records
- Used for **data exfiltration** and **C2** (command-and-control — the channel between malware and its operator) in environments that block direct internet access

**Detection signals** (behavioral, not content-based):

- Unusually high query volume from one host
- Abnormally long or random-looking subdomains
- High proportion of **TXT record** queries (TXT records can carry more data than standard A records)
- Queries to recently registered domains with no legitimate traffic history

> DNS tunneling is like smuggling contraband inside letters — the postal service (firewall) checks that envelopes exist, not what's written inside them.

### Domain generation algorithms (DGA)

A **DGA** — **domain generation algorithm** — is malware logic that uses a seed value (often the current date) to algorithmically produce hundreds of candidate C2 domain names daily, so that blocking any single known domain doesn't kill the C2 channel.

- The attacker knows the algorithm and pre-registers just the one domain the malware will actually contact each day
- Defenders must block an ever-changing list; most generated domains are never registered
- Primary defenses: **machine learning** models that spot statistically abnormal domain name patterns, and **threat intelligence feeds** sharing known DGA families

> DGA is like a spy using a one-time pad for rendezvous points — both sides generate the same list from a shared formula, and outsiders can't predict where to intercept them.

---

### Subdomain enumeration

**Subdomain enumeration** is a reconnaissance technique to map all of an organization's subdomains (e.g., `mail.`, `vpn.`, `dev.`, `staging.`, `api.`) before launching targeted attacks.

Discovery methods:

| Method | Mechanism |
|---|---|
| **Brute force** | Try common subdomain names against the target domain |
| **Zone transfer abuse** | Exploit misconfigured servers (see below) |
| **Certificate transparency logs** | Public records of every TLS certificate issued — reveal every subdomain that ever got a cert |
| **OSINT tools** | Tools like **Amass**, **Sublist3r**, and **theHarvester** (open-source intelligence tools for automated subdomain discovery) |

Goal: find less-hardened services that aren't as well protected as the main public site.

---

### DNS zone transfer abuse

A **zone transfer** (using query type **AXFR** — the DNS command to request a full copy of a zone's records) is designed to sync data from a primary name server to authorized secondary servers.

- A zone transfer response contains **every DNS record** for the domain: A, MX, NS, CNAME records — a complete internal map
- Misconfigured servers allow *any* IP to request a full zone transfer, handing attackers a perfect reconnaissance payload
- **Defense**: configure **ACLs** (access control lists — allowlists restricting who can make requests) on all authoritative servers to permit AXFR only from explicitly listed secondary server IPs

> An unrestricted zone transfer is like leaving your entire office directory — every server, every mail system, every alias — taped to the front door.

---

### Typosquatting and homograph attacks

**Typosquatting** — also called **URL hijacking** or **brandjacking** — registers domains with deliberate misspellings to capture mistyped traffic (e.g., `profess0rmesser.com`, `professormeser.com`).

- Fake domains serve phishing pages, deliver malware, or redirect users to competitors

A **homograph attack** is a variant using visually identical Unicode characters from non-Latin scripts to register a domain that *looks* identical in the browser bar but resolves to a different IP.

> Typosquatting is like opening a store called "Nïke" across the street from Nike — customers who aren't looking carefully walk in thinking they're at the real place.

---

### Fast flux DNS

**Fast flux DNS** is a technique to make C2 infrastructure resistant to takedown by constantly rotating DNS records.

| Variant | What rotates | Effect |
|---|---|---|
| **Single-flux** | A record IP addresses (very short TTL — sometimes minutes) | Compromised proxy hosts cycle in/out; taking down one IP has minimal impact |
| **Double-flux** | A records *and* authoritative name servers | Also rotates the DNS layer itself, making infrastructure harder to disrupt at the DNS level |

> Fast flux is like a drug operation that uses a rotating roster of drop points — by the time law enforcement raids one address, it's already moved.

---

### DNSSEC

**DNSSEC** — **DNS Security Extensions** — adds **digital signatures** to DNS responses so that a validating resolver can verify the records are genuine and unmodified.

- Does **not** encrypt DNS traffic — it provides **authentication and integrity**, not confidentiality
- Creates a **chain of trust** from the IANA root (the top of the DNS hierarchy, managed by the Internet Assigned Numbers Authority) → TLD registries → individual domain operators
- A cache poisoning attempt fails against a DNSSEC-validating resolver because the forged record cannot carry a valid cryptographic signature
- Deployment is growing but not yet universal

> DNSSEC is like a notarized document — anyone can read it, but the signature proves it hasn't been altered since the authority signed it.

---

### DNS over HTTPS and DNS over TLS

Both protocols encrypt DNS queries between the client and resolver to prevent eavesdropping and manipulation by network intermediaries (e.g., ISPs, on-path attackers).

| Protocol | Port | Key characteristic |
|---|---|---|
| **DoH** (DNS over HTTPS) | TCP 443 | Traffic blends with normal HTTPS; impossible to block by filtering port 53 alone |
| **DoT** (DNS over TLS) | TCP 853 | Dedicated port; easier for network operators to identify and control at the boundary |

Neither protocol replaces DNSSEC — DoH/DoT protect the *client-to-resolver* link; DNSSEC protects the *resolver-to-authoritative* data chain.

> DoH is like whispering your question to a librarian in a private booth — nobody in the library can hear what you asked, even if they can see you walked in.

---

### Recap

- **Cache poisoning** injects forged records into a resolver's cache; defenses are source-port randomization and DNSSEC
- **DNS hijacking** reroutes queries to an attacker-controlled resolver via router compromise, malware/hosts file, or registrar credential theft
- **DNS tunneling** encodes data in subdomains to create a covert channel; detected by query volume, subdomain length, and TXT record patterns
- **DGA** generates daily rotating C2 domains from an algorithm; defeated by ML-based detection and threat intel feeds
- **DNSSEC** adds cryptographic signatures for integrity/authentication; **DoH/DoT** add encryption for client-to-resolver privacy

---

### Exam flags

- **DNS cache poisoning vs. DNS hijacking** — know the difference: poisoning corrupts a legitimate resolver's cache; hijacking redirects queries to a rogue resolver entirely
- **DNSSEC vs. DoH/DoT** — know what each protects: DNSSEC = data integrity/authentication (no encryption); DoH/DoT = query confidentiality (no record authentication)
- **Zone transfer misconfiguration** — know that unrestricted AXFR exposes every record in a domain and that the fix is IP-based ACLs on authoritative servers
