## Wireless Security Settings

Wireless security has gone through four major protocol generations — each one patching flaws the previous one left open. This lesson covers every protocol, mode, and supporting technology the Security+ exam expects you to know, from WEP's fatal flaw to WPA3's forward secrecy.

---

### The protocol evolution: WEP → WPA → WPA2 → WPA3

**WEP** — **Wired Equivalent Privacy** — was the original 802.11 security protocol, intended to give wireless networks the same protection as a physical cable. It used the **RC4 stream cipher** (a cipher that encrypts data one bit at a time using a keystream) with a **24-bit IV** — **Initialization Vector**, a random value mixed with the key to vary each packet's encryption.

- The 24-bit IV space is only ~16 million values; on a busy network it runs out fast, forcing **IV reuse**
- Reusing an IV with RC4 leaks the keystream, letting attackers mathematically recover the pre-shared key
- **aircrack-ng** — a passive wireless cracking tool — can crack WEP in minutes from captured traffic
- **Status: never use. Categorically forbidden.**

> Think of WEP like a combination lock with only four digits — someone watching enough door-open events can deduce the combination.

---

**WPA** — **Wi-Fi Protected Access** — was a stopgap fix that ran on old WEP hardware via firmware updates. It replaced RC4's broken key schedule with **TKIP** — **Temporal Key Integrity Protocol** — which generates a fresh encryption key for every packet derived from a master key, and added the **Michael algorithm** as a **MIC** (Message Integrity Check) to detect tampering.

- Weaknesses were later found in both TKIP and the Michael MIC
- **Status: deprecated. Do not deploy.**

---

**WPA2** brought a complete cryptographic overhaul by introducing **CCMP** — **Counter Mode with CBC-MAC Protocol** — which replaced RC4 with **AES** (**Advanced Encryption Standard**, a NIST-approved block cipher used to protect classified government data).

- **KRACK** — **Key Reinstallation Attack** (2017) — exploited the **WPA2 four-way handshake** (the exchange where client and AP negotiate a session key) to let an attacker in the communication path decrypt traffic; fixed by patches
- WPA2-Personal handshakes can be captured and cracked **offline** via dictionary/brute-force — the attacker captures the handshake, then tries passwords at full hardware speed with no lockout
- **Status: still widely deployed; acceptable with strong passphrase and patches**

---

**WPA3** is the current standard and should be used in all new deployments. It replaces the WPA2 handshake with **SAE** — **Simultaneous Authentication of Equals** — based on the **Dragonfly** variant of **Diffie-Hellman key exchange** (a method where two parties derive a shared secret without ever transmitting it).

- The session key is **never sent over the air** — captured association frames contain no crackable hash, so offline attacks are impossible
- Provides **forward secrecy** — each session generates a unique key, so compromising the passphrase later cannot decrypt previously captured sessions (WPA2 lacks this: a captured handshake cracked later exposes that session)
- **WPA3-Enterprise** mandates a **192-bit security suite** for high-sensitivity environments
- **Protected Management Frames** (PMF) are **mandatory** in WPA3, blocking spoofed deauthentication frames that attackers use to force reconnections

> WPA3-SAE is like a secret handshake where both sides independently calculate the same result — an eavesdropper watching the handshake can't reverse-engineer the passphrase from it.

### Personal mode vs. Enterprise mode

| Mode | Also labeled | Authentication | Best for | Key weakness |
|---|---|---|---|---|
| **Personal** | PSK / Pre-Shared Key | One shared passphrase | Home, small business | One leaked password exposes everyone; remediation = change passphrase on every device |
| **Enterprise** | 802.1X | Unique per-user credentials via RADIUS | Business | Requires authentication infrastructure |

---

### 802.1X and the three-role framework

**802.1X** — the IEEE standard for **port-based network access control** — is the framework Enterprise mode runs on. Three roles participate:

- **Supplicant** — the client device trying to connect
- **Authenticator** — the access point or switch; holds the port in an **unauthorized state** (passing only 802.1X traffic) until authentication succeeds
- **Authentication server** — typically a **RADIUS** server (**Remote Authentication Dial-In User Service**, the centralized AAA server) that validates credentials against a directory like **Active Directory**

On success, the authenticator moves the port to **authorized** and can assign the client to a specific **VLAN** (**Virtual LAN**, a logical network segment) based on user identity.

> The authenticator is the bouncer: it won't let you past the velvet rope until RADIUS (the club owner in the back) confirms your name is on the list.

---

### EAP methods inside 802.1X

**EAP** — **Extensible Authentication Protocol** — is the flexible framework that carries the actual credentials between supplicant and RADIUS server. Four methods to know:

| Method | Tunnel? | Client cert required? | Notes |
|---|---|---|---|
| **EAP-TLS** | TLS | **Yes** | Strongest; both sides use digital certificates; eliminates passwords entirely |
| **PEAP** (Protected EAP) | TLS | No | Uses **MSCHAPv2** (Microsoft's challenge-response password auth) inside the tunnel; most common in Windows environments |
| **EAP-TTLS** (Tunneled TLS) | TLS | No | Like PEAP but supports more inner methods (CHAP, PAP, MS-CHAPv2); better for multi-vendor environments |
| **EAP-FAST** | PAC-based tunnel | No | Cisco-proprietary; uses a **PAC** (Protected Access Credential, a pre-provisioned cryptographic token) instead of certificates |

*All tunnel-based methods (PEAP, EAP-TTLS, EAP-FAST) protect credentials inside an encrypted channel before the inner authentication runs.*

---

### CCMP and TKIP details

**CCMP** uses AES in two modes simultaneously:
- **Counter mode** — provides **confidentiality** (encryption)
- **CBC-MAC** — **Cipher Block Chaining Message Authentication Code**, provides **integrity** (detects tampering)
- **CCMP-256** uses 256-bit AES keys; required for WPA3-Enterprise 192-bit suite

**TKIP** — deprecated, RC4-based, legacy only. Never configure it in new deployments.

---

### RADIUS and the AAA framework

**AAA** — **Authentication, Authorization, and Accounting** — describes the three jobs RADIUS performs:

- **Authentication** — verifies identity (credentials, certificates)
- **Authorization** — determines access rights, often via VLAN assignment based on group membership
- **Accounting** — logs session start/end, data transferred, and user identity for auditing and billing

The access point acts as the **RADIUS client**, forwarding requests to the RADIUS server, which in turn consults a backend directory like Active Directory.

---

### Additional wireless security best practices

- **Disable WPS** — **Wi-Fi Protected Setup** uses an 8-digit PIN verified in two halves, leaving only ~11,000 effective combinations; trivially brute-forceable
- **Strong unique passphrase** — at least 20 random characters for WPA2-Personal to resist offline cracking
- **802.11w** — the IEEE amendment that defines **management frame protection**, preventing spoofed deauth frames; mandatory in WPA3, optional in WPA2
- **Separate SSIDs + VLANs** — segment corporate, guest, and IoT devices on the same physical AP infrastructure
- **WIDS/WIPS** — **Wireless Intrusion Detection/Prevention System** — detects rogue APs, evil twins, and deauth floods
- **Hidden SSIDs** — suppressing the SSID beacon looks invisible to casual users, but the SSID appears in **probe request/response frames** whenever a legitimate client connects; not a real security control
- **5 GHz band** — shorter range than 2.4 GHz makes external monitoring harder, but this is a minor secondary consideration

---

### Recap

- **WEP** is broken (IV reuse + RC4), **WPA/TKIP** is deprecated, **WPA2/CCMP** is current-acceptable, **WPA3/SAE** is the current best standard
- WPA3-SAE prevents offline key cracking and adds forward secrecy; WPA2 handshakes can be captured and cracked offline
- 802.1X Enterprise mode uses **Supplicant → Authenticator → RADIUS server**; Personal mode uses one shared passphrase for everyone
- **EAP-TLS** is strongest (mutual certificates); **PEAP** is most common in Windows (password inside TLS tunnel)
- **WPS** is critically weak (~11,000 PIN combinations); always disable it

### Exam flags

- **WPA3-SAE vs. WPA2 offline cracking** — know exactly why SAE prevents offline attacks (no crackable hash transmitted) and what forward secrecy means
- **802.1X roles** — supplicant, authenticator, RADIUS server; know which holds the port unauthorized and which makes the access decision
- **EAP method selection** — exam scenarios will ask which method fits: EAP-TLS (certificates both sides), PEAP (Windows/password), EAP-FAST (Cisco/PAC)
