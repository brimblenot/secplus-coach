## Blockchain Technology

Blockchain appears in Security+ as both a defensive tool and an attack-relevant technology. This lesson covers how blockchains work, how they stay tamper-proof, and where they show up in real cybersecurity applications.

---

### What a distributed ledger actually is

A **distributed ledger** is a record-keeping system where every participant (called a **node** — a computer that holds a full copy of the ledger) stores an identical copy of the same database simultaneously. No single authority owns or controls it.

- Any node can read the ledger
- Changes must be approved by the network through a **consensus mechanism** — an agreed-upon process for deciding which version of the ledger is correct
- No single server to hack or corrupt — but agreement is harder when participants don't trust each other

> Think of it like every accountant in a firm keeping an identical copy of the books — no one person can quietly alter a number, because everyone else's copy would disagree.

---

### How blocks chain together

A **blockchain** is a specific type of distributed ledger organized as a linked sequence of blocks, each containing a batch of transactions and a cryptographic pointer to the block before it.

Each **block** contains:
- A **timestamp** — when the block was created
- The **hash** — a fixed-length fingerprint produced by a one-way mathematical function — of the **previous block's header**, which is the cryptographic link
- A **nonce** — a number-used-once field that miners vary during the proof-of-work process
- A **Merkle root** — a single hash that summarizes every transaction in the block (built by repeatedly hashing pairs of transaction hashes up to a single value)
- The actual transaction data

**Why this creates tamper-evidence:** if you alter any transaction in block #500, block #500's hash changes → that breaks the pointer stored in block #501 → block #501's hash changes → and so on through every subsequent block. Every other node sees that your chain's hashes don't match their copy and rejects it.

> Think of each block as a wax seal stamped over the previous one — break one seal and every seal after it is visibly wrong.

### Consensus mechanisms

| Mechanism | How a block is earned | Security guarantee | Key weakness |
|---|---|---|---|
| **Proof of Work (PoW)** | Miners race to find a nonce that makes the block's hash fall below a target — pure trial and error | Attacker must out-compute the entire honest network | Energy-intensive; smaller chains vulnerable to 51% attack |
| **Proof of Stake (PoS)** | **Validators** — participants who lock up cryptocurrency as collateral — are chosen probabilistically based on their **stake** (locked collateral) | Attacker must acquire >50% of all staked currency — prohibitively expensive | Different economic model; newer and less battle-tested |

**51% attack** — when a single attacker controls more than half of a PoW network's total **hash rate** (combined computational power), they can rewrite history and **double-spend** — spend the same coin twice. Practical against small chains; impractical against Bitcoin.

**Slashing** — the PoS penalty where a misbehaving validator loses their staked collateral, making cheating economically self-destructive.

> PoW is like a lock-picking race where the winner must show their work — cheating means re-picking every lock that came after. PoS is like requiring a huge cash deposit: misbehave and you forfeit it.

---

### Public vs. private blockchains

| Type | Who can join | Speed | Use case |
|---|---|---|---|
| **Public (permissionless)** | Anyone | Slower — global consensus needed | Bitcoin, Ethereum; full decentralization |
| **Private (permissioned)** | Authorized entities only | Faster — fewer, trusted nodes | Enterprise auditability without decentralization |
| **Consortium** | A group of organizations | Middle ground | Shared industry ledgers |

### Smart contracts

A **smart contract** is self-executing code deployed directly on a blockchain that automatically enforces an agreement when predefined conditions are met — no human intermediary required.

- Example: automatically releases payment when a shipment is confirmed received
- **Security risk:** bugs in smart contract code are **immutable** — once deployed, they cannot be patched, and exploitable flaws have cost hundreds of millions of dollars in real-world hacks

> A smart contract is like a vending machine: drop in the right input and it dispenses the output automatically — but a design flaw in the machine can't be fixed without replacing it entirely.

### Security applications of blockchain

**Supply chain provenance** — hardware components are registered on a blockchain at each transfer (manufacturer → distributor → customer). Each transfer is signed by the transferring party, giving the end customer a verifiable, tamper-evident history. Valuable for defense and medical devices where counterfeit parts are a safety risk.

**Certificate Transparency (CT)** — a system requiring all publicly trusted **Certificate Authorities (CAs)** — organizations that issue TLS certificates used to authenticate websites — to submit every certificate they issue to public, append-only **CT logs** built on Merkle trees. Browsers verify inclusion. Domain owners monitor logs (e.g., via **Certstream** — a tool providing a real-time feed of newly logged certificates) to detect unauthorized certificate issuance.

**Document notarization** — a document's hash is recorded in a blockchain transaction, proving the document existed at that moment without storing the document itself. Tamper-evident timestamping with no single controlling party.

**Non-repudiation** — every transaction is signed with the sender's **private key** (the secret half of a cryptographic key pair). Since the signature is permanently recorded on the immutable ledger, the sender cannot later deny initiating it.

**Digital identity** — **self-sovereign identity** systems let individuals hold verified credentials issued by trusted organizations on a blockchain and present them selectively, without relying on a central identity provider.

### Ransomware and cryptocurrency

Ransomware operators demand cryptocurrency because:
- Transactions are **pseudonymous** — wallet addresses aren't inherently tied to real identities
- Payments are **irreversible** once confirmed
- No personal banking information is required

**Bitcoin** is pseudonymous, not anonymous — every transaction is publicly visible, so law enforcement can trace payment flows and link wallet addresses to identities through exchanges.

**Monero** — a **privacy-focused cryptocurrency** that uses **ring signatures** (a technique that mixes a sender's transaction with others to obscure who actually sent it) and **stealth addresses** (one-time addresses that prevent linking transactions to a recipient's public address) to provide much stronger anonymity than Bitcoin.

---

### What blockchain does NOT fix

- **Stolen private keys** — the blockchain can't tell the difference between you and an attacker using your stolen key; endpoint security is still required
- **Smart contract bugs** — immutable code means immutable vulnerabilities
- **Scalability** — public blockchains are slow compared to centralized databases

---

### Recap

- A blockchain's tamper-evidence comes from chained hashes: altering one block invalidates every block after it, and other nodes reject the mismatch
- PoW security = computational cost; PoS security = economic cost of accumulating stake; a 51% attack breaks PoW by controlling majority hash rate
- Smart contracts automate agreements on-chain but are immutable once deployed — bugs become permanent exploits
- Certificate Transparency uses Merkle-tree-based logs to detect unauthorized TLS certificate issuance
- Bitcoin is pseudonymous (traceable); Monero uses ring signatures and stealth addresses for stronger anonymity

### Exam flags

- **51% attack definition and conditions** — what percentage of hash rate is needed, what the attacker can do (double-spend, censor), and why it's impractical on Bitcoin but has happened on smaller chains
- **Certificate Transparency** — what it is, what Merkle trees have to do with it, and how domain owners use CT log monitoring to detect rogue certificate issuance
- **Ransomware + cryptocurrency** — why Bitcoin is pseudonymous not anonymous, and what makes Monero harder to trace (ring signatures, stealth addresses)
