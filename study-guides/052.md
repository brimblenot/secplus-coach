## Cryptographic Attacks (Domain 2)

Modern cryptography is mathematically strong — breaking AES-256 directly is computationally infeasible. So attackers target the *implementation*, the protocols, the key management, and the hardware instead. This lesson covers every major class of cryptographic attack you need to know for Security+.

---

### Brute force and the search space

**Brute force** is an attack that tries every possible key or password until finding the correct one. Its feasibility depends entirely on how many possibilities exist — the **search space**.

- A 256-bit symmetric key has 2²⁵⁶ possibilities — computationally infeasible forever
- A 6-character lowercase password has ~308 million possibilities — crackable in seconds on a modern **GPU** (Graphics Processing Unit — a massively parallel processor used for both graphics and cracking)
- **Password length** is the single most important factor: each extra character multiplies the search space by the character-set size

> Think of brute force like trying every combination on a combination lock. A 3-digit lock falls in minutes; a 10-digit lock takes a lifetime.

---

### Dictionary, hybrid, and spraying attacks

**Dictionary attacks** use pre-assembled word lists rather than exhaustive character combinations.

- **rockyou.txt** — a wordlist derived from a 2009 breach of the RockYou platform that exposed 14 million plaintext passwords; the baseline wordlist in most cracking workflows
- Targeted wordlists add org-specific words: employee names, products, locations
- Tools like **Hashcat** and **John the Ripper** — password-cracking programs — check billions of hashes per second on GPU hardware

**Hybrid attacks** layer rule-based transformations on top of a dictionary:

- Append/prepend numbers or symbols (`password1!`)
- Apply capitalization patterns (`Password`)
- Substitute look-alike characters — **leet substitutions** — (`p@ssw0rd`)
- Combine multiple words

These rules focus cracking effort on how humans *actually* build passwords, which is far more predictable than policy language implies.

**Password spraying** inverts the usual attack: instead of many passwords against one account (which triggers lockout), it tries *one password against every account*, then waits before the next attempt.

- Targets seasonal/predictable passwords: `Summer2024!`, `CompanyName2024`
- Never exceeds the lockout threshold on any single account → nearly invisible to lockout-based defenses
- Highly effective in large **Active Directory** — Microsoft's enterprise directory and authentication service — environments

> Spraying is like a thief who tries the same master key on every door in a hotel, never rattling any one door enough to trigger an alarm.

---

### Credential stuffing

**Credential stuffing** automates replaying username/password pairs stolen from one breached service against other services, exploiting widespread password reuse.

- Attackers need no vulnerability in the target's own systems — only a breach elsewhere
- **Multi-factor authentication (MFA)** — requiring a second proof of identity beyond the password — is the most effective defense because the stolen credential pair alone is insufficient

---

### Rainbow tables and salting

A **rainbow table** is a precomputed lookup table mapping hash values back to the plaintext inputs that produced them — so instead of computing hashes during an attack, the attacker just looks up the target hash in the table in seconds.

- Effective against unsalted hashes of common algorithms like **MD5** and **NTLM** — older hashing algorithms still found in legacy systems
- **Password salting** completely defeats rainbow tables: a **salt** is a random value unique to each user that is mixed with the plaintext *before* hashing, so two identical passwords produce different hashes
- To attack a salted database, the attacker would need a separate rainbow table for every possible salt — infeasible; they must fall back to per-hash brute force or dictionary attacks

> A rainbow table is like a pre-printed answer key for a test. A salt is like giving every student a uniquely worded version of the same question — one answer key can't cover all of them.

---

### Birthday attacks and hash collisions

The **birthday attack** is a probabilistic method for finding *any* two inputs that produce the same hash output — called a **hash collision** — by exploiting the mathematics of the birthday problem.

- In a group of just 23 people, there is ~50% probability two share a birthday, despite 365 possible birthdays
- Collisions become likely after roughly 2^(n/2) attempts for an n-bit hash — far fewer than 2^n
- **MD5** (128-bit output) has demonstrated practical collisions
- **SHA-1** (160-bit output) — Google's **SHAttered** project (2017) produced two different PDF files with the same SHA-1 hash
- **Attack consequence:** find two documents with the same hash → get one legitimately signed → substitute the malicious one → the signature appears valid

**Collision attacks** are the applied version: the 2008 MD5 CA attack created a fraudulent certificate authority certificate sharing an MD5 hash with a legitimately signed cert, allowing arbitrary trusted certificates to be issued.

---

### Hash length extension attacks

**Hash length extension** exploits the **Merkle-Damgård construction** — the internal block-chaining structure used by MD5, SHA-1, and SHA-256 — where state is carried between processing blocks.

- An attacker who knows a hash output and the message *length* (but not the message content) can compute the valid hash for the original message **with extra data appended**
- This forges authentication tokens built by concatenating a secret with a message and hashing the result
- **Defense:** use **HMAC** (Hash-based Message Authentication Code — applies the hash twice with key mixing) which is not vulnerable to length extension

---

### Downgrade attacks

A **downgrade attack** forces two communicating parties to negotiate a weaker protocol or cipher than they would otherwise use.

| Attack | Full Name | What It Exploited |
|--------|-----------|-------------------|
| **POODLE** | Padding Oracle On Downgraded Legacy Encryption | Fallback to SSLv3; CBC padding oracle in SSLv3 |
| **BEAST** | Browser Exploit Against SSL/TLS | CBC weakness in TLS 1.0; chosen-boundary attack |
| **CRIME** | Compression Ratio Info-leak Made Easy | TLS compression; chosen-plaintext attack on compressed traffic |
| **DROWN** | Decrypting RSA with Obsolete and Weakened eNcryption | SSLv2 export-grade key exchange to decrypt TLS traffic |

- **SSLv2, SSLv3, TLS 1.0, TLS 1.1** should all be disabled; **TLS 1.2** is the minimum, **TLS 1.3** is preferred

> A downgrade attack is like a bank robber jamming a vault's modern lock so staff must fall back to an old combination lock — then cracking the old one.

---

### Padding oracle attacks

**Padding oracle attacks** target **CBC mode** — a block cipher chaining mode where each block's decryption depends on the previous ciphertext block — that leaks whether decryption produced valid padding via error messages or timing.

- Attacker submits modified ciphertext → observes "padding error" vs. "content error" → learns plaintext byte by byte, *without the key*
- POODLE is one example of a padding oracle attack
- **Defense:** use **AES-GCM** — an authenticated encryption mode that verifies integrity *before* decryption, never revealing padding information

---

### Side-channel attacks

A **side-channel attack** recovers cryptographic keys by measuring *physical* properties of the device performing cryptographic operations — not by breaking the math.

- **Timing attacks** — observe small variations in operation duration that reveal key bits
- **Power analysis** — measure power consumption during operations, which correlates with values being processed
- **Electromagnetic analysis** — capture RF emissions from the device
- Most relevant to hardware security modules, smart cards, and embedded devices

> Side-channel attacks are like figuring out a safe's combination by listening to the clicks — you're not picking the lock, you're reading the machine's body language.

---

### Quantum computing threats

Quantum computers pose a longer-horizon threat to current cryptography.

- **Shor's algorithm** — a quantum algorithm that efficiently solves integer factorization and discrete logarithm problems — breaks **RSA** and **Diffie-Hellman** key exchange entirely
- **Grover's algorithm** — a quantum search algorithm providing a quadratic speedup — effectively halves symmetric key security (AES-256 drops to ~128-bit strength against a quantum attacker)
- **NIST** (National Institute of Standards and Technology — the U.S. standards body) has standardized **CRYSTALS-Kyber** for key encapsulation and **CRYSTALS-Dilithium** for digital signatures as **post-quantum** algorithm replacements

---

### Recap

- **Brute force** is bounded by search space; length matters more than complexity; salting forces per-hash brute force by defeating rainbow tables
- **Password spraying** evades lockout by trying one password across all accounts; **credential stuffing** replays breach pairs across services — MFA defeats both
- **Birthday attacks** find hash collisions in ~2^(n/2) tries; MD5 and SHA-1 have demonstrated practical collisions with real signature-forging consequences
- **Downgrade attacks** (POODLE, BEAST, CRIME, DROWN) force weak protocols; fix is disabling SSLv2/3 and TLS 1.0/1.1
- **Shor's algorithm** breaks RSA/DH; **Grover's** halves symmetric strength; CRYSTALS-Kyber and CRYSTALS-Dilithium are the NIST post-quantum standards

---

### Exam flags

- **Password spraying vs. brute force vs. credential stuffing** — know what distinguishes each and which defense applies (MFA for stuffing, lockout-aware detection for spraying)
- **Rainbow tables vs. salting** — know that salting defeats rainbow tables by making precomputation infeasible, and that unsalted MD5/NTLM hashes are the target
- **Downgrade attack names** — POODLE, BEAST, CRIME, DROWN and their associated legacy protocols; TLS 1.2 minimum / TLS 1.3 preferred as the universal fix
