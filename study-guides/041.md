## Viruses and Worms

Viruses and worms are foundational malware categories that every Security+ candidate must know cold. This lesson covers how each type spreads, the major subtypes, landmark incidents, and the defenses that counter each.

---

### The one difference that matters: propagation

- **Virus** — malware that **attaches to a host file** (executable, document, script, or boot sector) and **requires user action** (running the file, opening the document) to activate and spread.
- **Worm** — malware that **self-replicates autonomously** across networks, exploiting vulnerabilities in services or systems, with **no host file and no user action** required.

> Think of a virus like a biological virus: it needs a living cell (host file) to reproduce. A worm is more like a fax machine that dials every number in a phonebook by itself.

---

### Virus subtypes

**File-infecting virus** — appends malicious code to or overwrites executable files (`.exe`, `.dll`, `.com`). Spreads each time an infected executable runs.

**Macro virus** — embeds in documents that support macro execution, especially **Microsoft Office** files using **VBA** (Visual Basic for Applications — a scripting language built into Office). Became widespread in the late 1990s because email clients auto-opened attachments and Office ran macros without confirmation.

- **Melissa** — infected Word documents, emailed itself to the first 50 Outlook contacts, overloaded mail servers globally.
- **ILOVEYOU** (LoveLetter) — spread via VBScript email attachments, overwrote music/image files; ~$10B in damage.

**Boot sector virus** — infects the **MBR** (Master Boot Record — the first sector of a storage device that launches the OS) or **VBR** (Volume Boot Record). Runs *before* the OS loads, so standard antivirus never initializes in time to catch it. Requires bootable scanning tools or removal from a separate clean system.

- **Petya** ransomware used MBR overwriting to lock entire systems.

**Multipartite virus** — infects *both* executables and boot sectors simultaneously. Removing only one site lets the other reinfect — you must clean both at once.

**Polymorphic virus** — encrypts its payload; uses a **decryption stub** (a small routine that decrypts the payload at runtime) that re-encrypts with a *different key* on each new infection, producing a different byte sequence every time. Traditional **signature-based antivirus** — which works by matching files against a library of known fixed byte patterns — is defeated because no two copies look alike. Detection requires **heuristic analysis** (behavior-based inspection) or recognizing structural patterns in the stub itself.

**Metamorphic virus** — goes further: rewrites its *entire* code on each infection using semantically equivalent transformations (reordering instructions, substituting equivalent sequences, inserting dead code). No decryption stub exists to catch. Makes even heuristic detection extremely difficult.

| Virus type | What changes per infection | Defeats signature matching? |
|---|---|---|
| Polymorphic | Encrypted body + new key | Yes |
| Metamorphic | Entire code rewritten | Yes (harder to detect) |

**Stealth virus** — intercepts OS file-system calls; shows security tools the *original clean file* while serving the *infected version* to the OS at execution time.

### Worms and landmark incidents

Because worms spread at network speed with no human help, they can infect thousands of systems in minutes.

| Worm | Year | Propagation method | Notable detail |
|---|---|---|---|
| **Morris Worm** | 1988 | fingerd, sendmail, rsh vulnerabilities on Unix | First internet worm; first CFAA conviction; created CERT |
| **ILOVEYOU** | 2000 | Email + IRC; VBScript attachment | ~$10B damage; ~10% of internet-connected PCs |
| **Code Red** | 2001 | IIS web server vulnerability | Defaced websites; DDoS'd White House IP |
| **Slammer** | 2003 | MS SQL Server vulnerability | Doubled every 8.5 sec; infected most vulnerable hosts in ~10 min |
| **Conficker** | 2008 | MS08-067 (Windows Server Service) + autorun | 9–15M machines; botnet never fully weaponized |
| **Stuxnet** | 2010 | 4 zero-days; targeted Siemens PLCs | First cyber weapon causing physical damage; destroyed Iranian centrifuges |
| **WannaCry** | 2017 | EternalBlue (MS17-010 SMB exploit) + ransomware | 200K+ systems, 150 countries; crippled UK NHS |
| **NotPetya** | 2017 | EternalBlue + Mimikatz credential theft | Wiper disguised as ransomware; ~$10B damage; attributed to Russian GRU |

**EternalBlue** — an exploit developed by the NSA targeting a vulnerability in **SMB** (Server Message Block — Windows file/printer sharing protocol), identified as **MS17-010**. Microsoft patched it *two months* before WannaCry hit. **Mimikatz** — a credential-extraction tool that NotPetya used to harvest passwords from memory and spread laterally beyond the initial SMB exploit.

> Stuxnet is the worm equivalent of a surgical strike: instead of spreading as broadly as possible, it waited until it found one specific target — Iranian uranium enrichment centrifuges — and quietly sabotaged them while lying to the monitoring systems.

### Defenses

**Against viruses:**
- Updated antivirus signatures + behavioral/heuristic engines (needed for polymorphic/metamorphic variants)
- Disable Office macros for untrusted documents
- Aggressive email filtering; sandbox document analysis
- Application allowlisting — only pre-approved executables can run

**Against worms:**
- **Patch management** — the single most important control; WannaCry/NotPetya exploited a vulnerability patched *two months prior*
- **Network segmentation** — limits lateral spread if a worm gains a foothold
- Host-based and perimeter firewalls blocking targeted ports
- Disable unnecessary network services
- **IDS/IPS** (Intrusion Detection/Prevention Systems — tools that monitor network traffic for attack signatures) with worm propagation signatures

---

### Recap

- Viruses need a host file + user action; worms need neither — they self-propagate via network vulnerabilities.
- Polymorphic viruses re-encrypt each copy; metamorphic viruses rewrite their entire code — both defeat traditional signature matching.
- WannaCry and NotPetya both used the EternalBlue MS17-010 exploit against *unpatched* systems — patch management was the preventable fix.
- Stuxnet was the first worm used as a precision cyber weapon, targeting physical industrial hardware via Siemens PLCs.
- Worm defenses = patch management first, then network segmentation and firewalls.

### Exam flags

- **Virus vs. worm propagation distinction** — expect scenario questions asking you to classify malware based on whether it needs a host file or user action.
- **Polymorphic vs. metamorphic** — know what each changes per infection and why signature-based antivirus fails against both.
- **WannaCry / NotPetya / Stuxnet details** — the exam tests exploit name (EternalBlue, MS17-010), the patch availability timing, and Stuxnet's physical-damage PLC targeting.
