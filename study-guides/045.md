## Denial of Service (DoS) and DDoS

Denial of service attacks target **availability** — the "A" in the CIA triad — by exhausting a system's resources rather than breaking into it. This lesson covers how DoS evolves into DDoS, the three attack categories, specific techniques, and defenses.

---

### What denial of service actually is

A **denial of service (DoS) attack** is a deliberate attempt to exhaust a target's resources — bandwidth, CPU, memory, connection slots — so legitimate users cannot reach it.

- **Goal:** make service unavailable, not steal data
- **Target pillar:** Availability (CIA triad)
- Can be **intentional** (attacker) or **accidental** (network loop, huge file download, burst pipe)

> Think of it like a mob of people blocking a store entrance — nobody inside is harmed, but real customers can't get in.

---

### From DoS to DDoS

A single-source attack is limited: one machine has capped bandwidth, and a defender can block one IP. So attackers evolved.

A **distributed denial of service (DDoS) attack** coordinates hundreds, thousands, or millions of devices worldwide to flood a target simultaneously — making source-based filtering nearly useless.

Those devices are organized into a **botnet** — a network of machines infected with malware and controlled remotely by an attacker. The operator issues one command; every bot attacks at once.

- **Zeus botnet** — a documented real-world botnet with over 3.6 million compromised machines at its peak
- Asymmetric power: modest attacker infrastructure can overwhelm organizations with far greater resources

> A botnet is like a flash mob where the organizer texts one message and thousands of strangers show up to block traffic.

---

### Three DDoS attack categories

| Category | Targets | Goal |
|---|---|---|
| **Volumetric** | Network bandwidth | Saturate the pipe |
| **Protocol** | Server/device processing resources (firewalls, load balancers) | Exhaust connection-handling capacity |
| **Application layer (Layer 7)** | Web app logic | Disrupt service with low bandwidth |

---

### Volumetric attacks and amplification

**UDP flood** — sends large numbers of **UDP** (User Datagram Protocol — connectionless transport layer protocol) packets to random ports, forcing the target to generate **ICMP** (Internet Control Message Protocol — used for network diagnostics/error messages) "Destination Unreachable" replies, consuming bandwidth in both directions.

**ICMP flood (ping flood)** — overwhelms the target with echo-request packets.

**Amplification** is the key force-multiplier technique: the attacker sends a *small* spoofed request (with the victim's IP as source) to a third-party server, which sends a *much larger* response directly to the victim.

| Amplification type | Protocol exploited | Amplification factor |
|---|---|---|
| **DNS amplification** | DNS "all records" query to open resolvers | Up to ~4,000× |
| **NTP amplification** | **NTP** (Network Time Protocol) `monlist` command — returns last 600 clients | ~51,000× |
| **Memcached amplification** | **Memcached** — a UDP-based caching system — exposed publicly | Similar extreme range |

- **Smurf attack** — sent ICMP echo requests to a broadcast address with victim's IP spoofed; every host on the segment replied to the victim. Now largely mitigated on modern networks.

> Amplification is like sending one fake complaint letter to a call center using someone else's return address — and 4,000 angry reply letters get mailed to that person.

---

### Protocol attacks

**SYN flood** exploits the **TCP three-way handshake** — the SYN → SYN-ACK → ACK sequence that establishes a TCP connection. The attacker sends massive numbers of SYN packets with spoofed source IPs. The server allocates a **half-open connection** entry for each and waits for an ACK that never comes. When the connection table fills, no new legitimate connections can be accepted.

**Defense — SYN cookies:** Instead of storing half-open state, the server encodes connection parameters into the sequence number of its SYN-ACK. Resources are only allocated when a valid ACK arrives carrying that encoded value — spoofed SYNs never complete, so the table never fills.

> A SYN flood is like thousands of people calling a restaurant to "reserve a table" and never showing up — real diners can't get a reservation.

---

### Application layer attacks

**HTTP GET/POST flood** — sends huge numbers of valid-looking HTTP requests. Because they appear legitimate, simple volumetric blocks don't stop them.

**Slowloris** — opens many simultaneous connections and sends *partial* HTTP headers slowly, just fast enough to avoid timeout, but never completing the request. Most web servers cap simultaneous connections; Slowloris fills that pool with incomplete ones, blocking legitimate users — with very little bandwidth required.

**Slow POST attack** — sends a POST with a large declared body size, then delivers the body one byte at a time, holding connections open indefinitely.

**DNS query flood** — floods authoritative name servers so a domain's names stop resolving, taking down all services under that domain without touching the servers directly.

---

### Permanent DoS (phlashing)

**Permanent denial of service (phlashing)** aims to physically destroy the target, not just disrupt it. An attacker with access to a device's firmware update mechanism pushes a malicious firmware image that corrupts the hardware, requiring physical replacement. Demonstrated against industrial and network devices.

---

### DDoS-as-a-weapon variations

- **Booter/stresser services** — **DDoS-for-hire** platforms that let anyone buy attacks cheaply, lowering the barrier to entry significantly
- **DDoS smokescreen** — attackers launch DDoS to distract security teams while a separate intrusion or data theft happens elsewhere
- **RDoS (ransom DDoS)** — extortionists threaten a DDoS attack unless a ransom is paid

---

### Defenses

| Defense | What it does |
|---|---|
| **Rate limiting** | Caps requests per IP/second to blunt unsophisticated floods |
| **Traffic scrubbing** | Routes traffic through scrubbing centers (e.g., Cloudflare, Akamai, AWS Shield) that filter attack traffic via ML/behavioral analysis before forwarding clean traffic |
| **Blackholing (null routing)** | ISP drops all traffic to victim's IP — stops attack but also stops legitimate users; last resort |
| **Anycast diffusion** | Spreads attack traffic across many distributed nodes so no single point is overwhelmed |
| **SYN cookies** | Eliminates half-open state storage; defeats SYN floods |
| **Ingress filtering (BCP38)** | ISPs block packets with spoofed source IPs leaving their networks, undermining amplification |
| **Web application firewall (WAF)** | **WAF** — a firewall that inspects HTTP traffic — detects Layer 7 patterns like Slowloris and HTTP floods |
| **Load balancing** | Distributes traffic across multiple servers so no single host is overwhelmed |
| **Over-provisioning** | Extra capacity absorbs moderate attacks while still serving legitimate users |

---

### Recap

- **DoS** targets availability; **DDoS** distributes the attack across a botnet to defeat source-based filtering
- **Amplification** (DNS, NTP, Memcached) lets attackers generate traffic many thousands of times their input by spoofing the victim's IP
- **SYN flood** exhausts TCP connection tables; **SYN cookies** fix this by removing the need to store half-open state
- **Slowloris** causes Layer 7 DoS with minimal bandwidth by holding connections open with incomplete HTTP headers
- **Phlashing** permanently destroys hardware via malicious firmware; **RDoS** combines extortion with DoS threats

### Exam flags

- **Amplification factors and mechanisms** — know which protocol maps to which technique (DNS → all-records query, NTP → monlist, Memcached → UDP exposure) and that IP spoofing makes the response hit the victim
- **SYN flood vs. SYN cookies** — expect scenario questions where a server's connection table fills with half-open entries; SYN cookies are the correct fix
- **Slowloris as a low-bandwidth Layer 7 attack** — questions may describe "partial HTTP headers" or "minimal traffic, maximum disruption" and expect you to identify Slowloris
