## Zero-Day Vulnerabilities

Zero-day vulnerabilities represent the worst-case scenario in vulnerability management: the vendor doesn't know the flaw exists, so no patch exists, no advisory exists, and traditional defenses have nothing to match against. This lesson covers the full lifecycle, the CVE/CVSS systems, disclosure models, and how defenders protect themselves when patching isn't an option.

---

### What a zero-day actually is

A **zero-day vulnerability** is a security flaw in software or hardware that is unknown to the vendor — meaning the vendor has had *zero days* to develop a fix.

- No patch available
- No vendor advisory to act on
- No signature for antivirus or IDS to match
- Attackers who know about it have a significant **asymmetric advantage** — they can exploit freely while defenders have no specific countermeasure

> Think of it like a master key that only the thief knows exists — the locksmith can't issue a fix for a lock defect they don't know about.

---

### Who discovers zero-days — and why it matters

The same flaw can be found by very different parties with very different intentions:

| Discoverer | What they do with it |
|---|---|
| Academic/corporate researchers | Report through coordinated disclosure |
| **Bug bounty hunters** — independent researchers working within vendor-defined scope | Submit via platforms like **HackerOne** or **Bugcrowd** for monetary rewards |
| Nation-state intelligence agencies | Stockpile for offensive operations; do NOT disclose |
| Criminal organizations | Use directly or purchase from **exploit brokers** — intermediaries who buy zero-days and resell them to governments or other buyers |

---

### The zero-day lifecycle

**Discovery → Weaponization → Exploitation in the wild → Defender visibility → Vendor notification → Patch released → Patch deployed**

The most dangerous period is the **window between first exploitation and successful patch deployment** — during this time, no standard defense addresses the specific flaw.

**2023 real examples:**
- **Chrome** (Google, April): memory corruption + sandbox escape
- **Windows** (Microsoft, May): unsigned code bypassed **Secure Boot** — the UEFI firmware feature that ensures only trusted bootloaders run — during the boot process
- **iOS/iPadOS** (Apple, May): three separate flaws actively exploited before patches shipped

### The CVE system

**CVE** — Common Vulnerabilities and Exposures — is a standardized naming and cataloging framework for security vulnerabilities, maintained by **MITRE** at `cve.mitre.org`.

- Format: `CVE-[year]-[sequence number]` — e.g., **CVE-2021-44228** is the Log4Shell vulnerability
- Gives every flaw a single unambiguous ID so vendors, security tools, and organizations all refer to the same thing
- Without CVE IDs, the same flaw could circulate under different names, breaking coordination

The **NVD** — National Vulnerability Database, at `nvd.nist.gov` — enriches CVE entries with CVSS scores, affected-product identifiers, and analysis.

> CVE IDs work like a universal product barcode: every vendor, tool, and database scans the same code and pulls up the same item.

---

### The CVSS scoring system

**CVSS** — Common Vulnerability Scoring System — assigns each vulnerability a numerical severity score from **0.0 to 10.0**.

**Base Score components** (intrinsic, never change):

| Metric | What it measures |
|---|---|
| **Attack Vector** | Local / adjacent network / internet-level access required |
| **Attack Complexity** | Whether special conditions beyond attacker control are needed |
| **Privileges Required** | Authentication needed before exploitation? |
| **User Interaction** | Must a victim take an action? |
| **Scope** | Can exploitation affect components *beyond* the vulnerable one? |
| **Confidentiality / Integrity / Availability Impact** | Degree of harm to each CIA property |

A **10.0** score means: remotely exploitable, no authentication, no user interaction, cross-component impact, complete CIA compromise.

**Score modifiers:**

- **Temporal Score** — adjusts for factors that change over time: exploit code availability, whether a patch exists, and certainty of the vulnerability report
- **Environmental Score** — lets organizations adjust based on asset criticality or compensating controls already in place

**Severity bands:**

| Band | Score range |
|---|---|
| Critical | 9.0 – 10.0 |
| High | 7.0 – 8.9 |
| Medium | 4.0 – 6.9 |
| Low | 0.1 – 3.9 |

> CVSS is like a triage tag in an ER — it doesn't treat the wound, but it tells you who needs the operating room first.

### Disclosure models

**Responsible disclosure** (also called **coordinated disclosure**) — the researcher reports the flaw privately to the vendor and agrees to withhold public details for a set period, typically **90 days** (the standard set by **Google's Project Zero**), giving the vendor time to patch before attackers can exploit published details. After 90 days, details go public regardless.

**Full immediate disclosure** — researcher publishes everything publicly with no vendor notification or waiting period.

| | Responsible disclosure | Full immediate disclosure |
|---|---|---|
| Vendor gets time to patch | ✅ | ❌ |
| Maximizes pressure on vendor | ❌ | ✅ |
| Attackers also get immediate info | ❌ | ✅ |

**Bug bounty programs** pay researchers for responsibly disclosed findings — up to $1M+ for critical flaws in flagship products (Microsoft, Google, Apple). This aligns researcher incentives toward disclosure rather than sale.

**Exploit brokers** like **Zerodium** pay researchers and resell to government agencies — Zerodium has published prices up to **$2.5 million** for a complete no-interaction iOS exploit chain.

> Responsible disclosure is like finding a gas leak and calling the utility company before posting about it — you give them a chance to fix it before anyone gets hurt.

### Nation-state risk: the EternalBlue lesson

The **NSA** developed **EternalBlue** — an exploit targeting a flaw in **Windows SMB** (Server Message Block, the Windows file-sharing protocol) — for offensive intelligence operations. The **Shadow Brokers** hacking group stole and published it in 2017. It was then weaponized in:

- **WannaCry** — a ransomware worm
- **NotPetya** — a destructive wiper attack

Combined damage: tens of billions of dollars. The lesson: stockpiled government zero-days are a risk to everyone if they escape their intended context.

### Defending without a patch

Because patches don't exist for zero-days, defenders rely on layers that work on *behavior*, not *signatures*:

- **Defense-in-depth** — multiple independent security layers so no single flaw enables complete compromise
- **EDR** — Endpoint Detection and Response — detects exploitation behaviors (shellcode execution, process injection, abnormal parent-child process relationships) without needing to know the specific vulnerability. Unlike traditional **antivirus** — which only matches files against a known-bad signature list at execution time — EDR records ongoing activity and can catch novel exploit behavior
- **Application sandboxing** — constrains what resources a compromised process can access, limiting the blast radius
- **Network segmentation** — prevents lateral movement after initial compromise
- **Least privilege** — limits damage a compromised process can cause
- **Threat intelligence** — from **CISA** (Cybersecurity and Infrastructure Security Agency), **ISACs** (Information Sharing and Analysis Centers — sector-specific groups that share threat data), and commercial feeds
- **Virtual patching** — **WAF** (Web Application Firewall) rules or **IPS** (Intrusion Prevention System) signatures block known exploit patterns while the vendor develops an official patch
- **Minimal attack surface** — fewer exposed services = fewer targets

---

### Recap

- A zero-day is unknown to the vendor — no patch, no signature, attacker has full asymmetric advantage during the exposure window
- CVE = unique identifier (`CVE-year-sequence`); CVSS = severity score 0–10 with Critical ≥ 9.0
- Responsible disclosure = private report + 90-day window (Project Zero standard); full disclosure = immediate public release
- Bug bounties incentivize disclosure; exploit brokers incentivize sale (Zerodium up to $2.5M for iOS chains)
- Zero-day defense relies on behavior-based detection (EDR), sandboxing, segmentation, and least privilege — not patching

### Exam flags

- **CVE format and CVSS severity bands** — know the `CVE-year-sequence` format and the Critical/High/Medium/Low cutoffs (9.0, 7.0, 4.0)
- **Responsible vs. full disclosure** — know the 90-day standard, who established it (Google Project Zero), and the tradeoff
- **Zero-day defensive strategies** — expect scenario questions asking which control helps *when no patch exists*; EDR, sandboxing, and least privilege are the key answers
