## Network Infrastructure Concepts

Network infrastructure is the physical and logical skeleton that all security controls are built on. Understanding how data moves, how devices make decisions, and how design choices create or remove attack paths is essential for Security+.

---

### Routers and routing

**Routers** are Layer 3 devices — meaning they operate at the network layer of the OSI model and make forwarding decisions based on IP addresses — that move packets between different networks by consulting a **routing table** (a database mapping destination network prefixes to next-hop addresses or outbound interfaces).

Routing tables are populated two ways:

- **Static routing** — an admin manually enters each route; full control, but no automatic failover
- **Dynamic routing** — routers exchange reachability info automatically via routing protocols

Key routing protocols:

| Protocol | Full Name | Where Used | Notes |
|---|---|---|---|
| **OSPF** | Open Shortest Path First | Enterprise LANs | Calculates lowest-cost path; widely used |
| **RIP** | Routing Information Protocol | Legacy only | Distance-vector; obsolete in modern nets |
| **BGP** | Border Gateway Protocol | Internet (between ISPs/orgs) | Routes between **autonomous systems** — independently managed networks |

**BGP hijacking** is an attack where a malicious autonomous system announces IP prefixes it doesn't legitimately own, redirecting internet traffic through attacker infrastructure. Defenses include:

- **Route filtering** — prefix lists and route maps block unauthorized announcements
- **AS path filtering** — rejects routes with unexpected autonomous system paths
- **RPKI** (Resource Public Key Infrastructure) — cryptographically binds IP prefixes to their authorized autonomous system, so forged announcements can be detected and rejected

> Think of BGP like a GPS routing system for the internet: RPKI is the verified map that prevents a bad actor from planting a fake road sign that redirects all traffic through their territory.

### Switches, hubs, and bridges

**Switches** are Layer 2 devices that forward **Ethernet frames** — the data-link-layer packets used on local networks — within a LAN using a **MAC address table** (also called a **CAM table** — Content Addressable Memory), which maps MAC addresses to specific physical ports. Frames go only to the right port, not every port.

**Managed switches** support security features; **unmanaged switches** do not:

| Feature | Managed | Unmanaged |
|---|---|---|
| VLANs | ✅ | ❌ |
| Port security / 802.1X | ✅ | ❌ |
| DHCP snooping / Dynamic ARP Inspection | ✅ | ❌ |
| SNMP monitoring | ✅ | ❌ |

**Hubs** are Layer 1 devices — they operate at the physical layer and have no awareness of addresses — that simply repeat electrical signals to every connected port. Every device sees every other device's traffic, making passive capture trivial. Obsolete; replaced by switches.

**Bridges** are Layer 2 devices that connect two network segments using MAC addresses. Also legacy technology — their function is built into modern switches.

### Network topologies and security

**Network topology** describes how devices are connected; this matters because topology determines traffic flow and where monitoring or choke points can be placed.

| Topology | Structure | Security Note |
|---|---|---|
| **Star** | All devices → central switch | Modern standard; failure isolated to one device |
| **Bus** | All devices on one cable | Shared medium; passive eavesdropping trivial; any break kills the whole network |
| **Ring** | Devices linked in a loop | Legacy (Token Ring); rarely seen today |
| **Mesh** | Every device ↔ every other device | Maximum redundancy; used in WAN/MPLS |
| **Hybrid** | Mix of the above | Common in real enterprise networks |

**Physical topology** = how devices are actually cabled. **Logical topology** = how traffic actually flows, which can differ. **VLANs** — Virtual Local Area Networks — are the key example: devices share the same physical switches but are isolated into separate broadcast domains at Layer 2. Traffic between VLANs requires a Layer 3 device (router or Layer 3 switch).

> A VLAN is like putting different departments' desks in the same open-plan office but giving each team soundproof glass walls — same physical space, but no one can hear the others without going through the front desk (the router).

### Physical media

| Medium | Bandwidth / Distance | Security Characteristic |
|---|---|---|
| **Cat 5e** (twisted pair copper) | 1 Gbps / 100 m | Susceptible to EMI; can be physically tapped |
| **Cat 6 / 6A** (twisted pair copper) | 10 Gbps / varies | Same tap risk as Cat 5e |
| **Single-mode fiber** | Very long distances (km) | Immune to EMI; very hard to tap; preferred for high-security runs |
| **Multi-mode fiber** | Shorter distances (data centers) | Same tap resistance as single-mode |
| **Wireless (802.11)** | Varies | Inherently broadcast; anyone in range can attempt to receive; requires strong encryption and authentication |

**Fiber optic cable** transmits data as pulses of light through glass or plastic. Its tap resistance and EMI immunity make it preferred in high-security and long-distance environments.

### SDN and the three network planes

**SDN** (Software-Defined Networking) separates the network's **control plane** from its **data plane** — in traditional devices both live in the same box. A centralized software controller holds all control logic and programs forwarding behavior into data plane devices via interfaces like **OpenFlow** (a standardized protocol for a controller to instruct forwarding devices).

Security advantages of SDN:

- Policies defined centrally → applied consistently everywhere
- Suspicious device can be **quarantined in seconds** by updating forwarding rules network-wide
- **Microsegmentation** — granular per-workload traffic control that limits lateral movement after a compromise — becomes practical (rather than relying on broad VLAN boundaries)

The three planes, and what attacks/controls operate there:

| Plane | Function | Attack Example | Control Example |
|---|---|---|---|
| **Data plane** (forwarding plane) | Moves packets — switching, routing, NAT, QoS | ARP spoofing | Dynamic ARP Inspection |
| **Control plane** | Makes forwarding decisions — routing tables, spanning tree, MAC tables | BGP hijacking | RPKI, route filtering |
| **Management plane** | Admin interface — SSH, SNMP, web UI, API | Unauthorized config change | Access controls, MFA on admin interfaces |

> Traditional networking is like every city having its own traffic department making local decisions. SDN is like a central traffic authority that can re-route every intersection in the city simultaneously the moment an incident is detected.

### SD-WAN and overlay networks

**SD-WAN** (Software-Defined WAN) applies SDN principles to wide-area connectivity. Traditional WANs relied on expensive **MPLS** — Multiprotocol Label Switching, a dedicated leased-line service used between offices — circuits. SD-WAN lets organizations mix link types (MPLS, broadband, 4G LTE, satellite) and route traffic intelligently by policy:

- **Application-aware routing** sends latency-sensitive traffic (VoIP, video) over the best available link
- Built-in **encrypted tunnels**, integrated firewall policies, and centralized security management
- Much cheaper and simpler than managing individual VPN configs at each branch

**Overlay networks** are virtual networks built on top of existing physical infrastructure:

- **VXLAN** (Virtual Extensible LAN) — encapsulates Layer 2 Ethernet frames inside **UDP** packets, letting Layer 2 segments span Layer 3 networks. Critical for VM mobility and multi-tenant isolation in data centers and cloud.
- **GRE** (Generic Routing Encapsulation) — simpler tunneling protocol that wraps arbitrary network protocols inside IP packets; commonly used in VPN implementations.

### IPv4, IPv6, and NAT

**IPv4** uses 32-bit addresses in dotted-decimal notation with **CIDR** (Classless Inter-Domain Routing) notation (e.g., `192.168.1.0/24` = 24 network bits, 8 host bits). Private ranges not routable on the public internet:

| Range | CIDR |
|---|---|
| 10.x.x.x | 10.0.0.0/8 |
| 172.16–31.x.x | 172.16.0.0/12 |
| 192.168.x.x | 192.168.0.0/16 |

**NAT** (Network Address Translation) — translates private IP addresses to a public IP at the border router so internal hosts can reach the internet. **PAT** (Port Address Translation) — a form of NAT that allows many internal hosts to share one public IP by tracking individual connections via source port numbers.

> NAT hides your internal addressing like a mail room that replaces each employee's desk number with the building's street address — outsiders see only one address.

⚠️ NAT is **security through obscurity** — it hides internal IPs but is not a true security control and should never be the primary defense.

**IPv6** uses 128-bit addresses in hexadecimal — the vastly larger address space eliminates the need for NAT, meaning every device can have a globally routable address. This changes the security model: internal devices are directly addressable, making perimeter firewall rules even more critical.

---

### Recap

- **Routers** forward between networks (L3/IP); **switches** forward within networks (L2/MAC); **hubs** broadcast everything to everyone — a passive-capture risk
- **BGP hijacking** poisons internet routing; **RPKI** defends against it by cryptographically authorizing prefix announcements
- **VLANs** create logical isolation on shared physical infrastructure; inter-VLAN traffic always requires a Layer 3 device
- **SDN** centralizes control, enabling rapid quarantine and microsegmentation — granular per-workload isolation that limits lateral movement
- **NAT** hides internal addressing but is not a real security control

### Exam flags

- **BGP hijacking + RPKI**: know what BGP hijacking is, why it's dangerous, and that RPKI is the cryptographic defense
- **SDN planes**: be able to match data/control/management plane to its function and to an attack or control (e.g., BGP hijacking → control plane; ARP spoofing → data plane)
- **NAT/PAT security limitation**: NAT provides obscurity, not true security — expect a scenario question testing whether you'd rely on it as a defense
