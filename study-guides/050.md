## Malicious Code

Malicious code covers far more than the classic "virus file" — it includes scripts, macros, memory-only payloads, and even legitimate Windows tools turned against you. This lesson maps the major categories, how attackers use them, and how defenders detect each one.

---

### Shell scripts as malicious code

A **shell script** is a plain-text file of commands interpreted by a shell (Bash, sh) — no compilation needed, just execute.

- Can download additional payloads using **curl** or **wget** — command-line tools for fetching files over HTTP/HTTPS
- Establishes persistence by adding entries to **cron** (Linux's scheduled task system) or **rc files** (scripts that run at system startup)
- Exfiltrates data through **netcat** — a utility for sending raw data over a network connection
- Leaves **no binary signature** — traditional antivirus matches known file hashes, but a text file has no fixed binary pattern to match

**Defenses:** script logging, **file integrity monitoring** — alerting on unexpected changes to system directories — application allowlisting, and **script signing** — requiring a cryptographic signature before a script is allowed to run.

> *Think of a malicious shell script like a sticky note slipped into a manager's inbox: it looks like plain text, not a "weapon," so it sails past the security desk.*

### PowerShell abuse and fileless attacks

**PowerShell** is Microsoft's administrative scripting language with deep access to the OS, the **.NET framework** (Windows's application runtime), and remote management — which makes it a top attacker target.

**Key technique — fileless execution:**

- **`Invoke-Expression` (IEX)** — a PowerShell command that runs a string as code; combined with **`System.Net.WebClient DownloadString`** — a method that fetches text from a URL — it pulls a script from the internet and runs it *entirely in memory*, never writing a file to disk
- No file = no hash = no antivirus match
- **Base64 encoding** — converting a command into a string of letters/numbers — passed via the **`EncodedCommand`** parameter, defeats simple pattern matching
- **WS-Management** — Microsoft's remote management protocol — lets attackers with valid credentials run commands on remote machines

**Defenses:**

| Control | What it does |
|---|---|
| **AMSI** (Anti-Malware Scan Interface) | Windows API that hands script content to antivirus *after* deobfuscation, before execution |
| **Script Block Logging** | Records the actual (deobfuscated) code each PowerShell script block runs — forensic gold |
| **Constrained Language Mode** | Restricts PowerShell to a safe feature subset, enforced via AppLocker or WDAC |

> *Fileless PowerShell is like a hitman who memorizes orders verbally and leaves no written instructions — nothing to find at the scene.*

### WMI persistence and remote execution

**WMI** (Windows Management Instrumentation) is a built-in Windows framework for querying and managing nearly every aspect of the OS.

- **WMI event subscriptions** — code registered to fire on system events (startup, logon, process creation) — survive reboots and are stored in the **WMI repository**, not the registry, so they hide from typical persistence hunts
- Remote WMI execution requires only valid credentials — no extra software installed
- Traffic blends with normal admin activity

> *A WMI subscription is like a land mine buried under the floorboards: it's invisible to anyone just looking around the room, and it fires automatically when someone steps on the trigger.*

### Python offensive tooling

**Python** is a cross-platform interpreted language whose rich library ecosystem makes it practical for attacker tooling.

- **Impacket** — a Python library providing pure-Python implementations of Windows protocols (SMB, MSRPC, Kerberos), enabling Windows attacks from any OS
- **Scapy** — a Python library for building and injecting arbitrary network packets
- Custom Python tools don't match signatures of known frameworks, bypassing signature-based detection

> *Python attack tools are like custom-made skeleton keys: because they're one-off, no locksmith's database has their profile.*

---

### JavaScript, VBScript, and HTA files

**Windows Script Host (WSH)** — a Windows component that executes `.js` and `.vbs` files with access to the filesystem, registry, and network — runs them with the logged-in user's full privileges on double-click.

**HTA files** (`.hta`) — **HTML Applications** executed by **`mshta.exe`** (Microsoft's HTA host process) — run with elevated permissions that bypass browser sandboxing.

**Defense:** disable WSH for users who don't need scripting; email filters should block these attachment types.

> *A malicious `.hta` file is like a document that opens in a room with no guards — the sandbox walls just don't exist.*

---

### Office macros (VBA)

**VBA** (Visual Basic for Applications) is a scripting language embedded in Office documents. When a user opens a macro-enabled document and clicks "Enable Macros," the code runs with full user privileges.

- **`Document_Open`** / **`Workbook_Open`** — VBA event hooks that fire automatically on open, requiring no further user interaction
- Macro typically downloads a second-stage payload using PowerShell IEX

**Defenses:**

- **Protected View** — opens internet-sourced documents in a read-only sandbox; macros don't execute
- **Macro signing** — only macros from a trusted, cryptographically signed publisher are allowed to run
- Microsoft 365 now blocks macros from internet-sourced files by default

### Staged vs. stageless payloads

| Type | Structure | Use case |
|---|---|---|
| **Staged** | Small **loader/dropper** downloads full payload (e.g., **Meterpreter** or **Cobalt Strike Beacon** — common post-exploitation tools) from a C2 server into memory at runtime | Open internet access available |
| **Stageless** | Full payload bundled in one artifact | Restricted outbound access; no second-stage download possible |

**C2** (Command and Control) — the attacker-controlled server the malware calls home to receive instructions and deliver payloads.

---

### Living-off-the-land binaries (LOLBins)

**Living-off-the-land** attacks use legitimate, already-installed Windows binaries to perform malicious actions — avoiding custom tools that might trigger alerts.

| Binary | Abuse |
|---|---|
| **`certutil.exe`** | Download files from URLs; decode Base64 data |
| **`mshta.exe`** | Fetch and run a remote HTA payload |
| **`regsvr32.exe`** | Proxy-execute a DLL from a remote location via COM |
| **`rundll32.exe`** | Execute exported functions from a DLL |
| **`wscript.exe`** / **`cscript.exe`** | Execute VBScript and JScript |

Because these are signed Microsoft binaries, application allowlisting rules typically permit them.

> *LOLBins are like a burglar using the homeowner's own crowbar, found in the garage — no suspicious tools to trace back.*

---

### Defense-in-depth overview

No single control stops all malicious code. Effective defense layers:

1. **AMSI** — runtime script inspection across PowerShell, VBScript, JScript, VBA
2. **Script Block Logging + Module Logging** — capture deobfuscated code for detection and forensics
3. **AppLocker / WDAC** (Windows Defender Application Control) — application allowlisting to block unauthorized executables and scripts
4. **EDR** (Endpoint Detection and Response) — monitors process behavior, memory, and network activity at runtime, catching fileless and LOLBin attacks that leave no file for antivirus to scan
5. **Email gateway filtering** — strip macro-enabled documents and script attachments before delivery

---

### Recap

- **Fileless attacks** load code into memory via PowerShell IEX + DownloadString — no file, no hash, traditional AV is blind
- **WMI event subscriptions** persist across reboots by living in the WMI repository, not the registry
- **LOLBins** (certutil, mshta, regsvr32, etc.) abuse signed Windows binaries to evade allowlists
- **AMSI** inspects script content post-deobfuscation; **Script Block Logging** captures the same for forensics
- **Staged payloads** split delivery into a small loader + in-memory second stage; **stageless** bundles everything for restricted environments

### Exam flags

- **Fileless PowerShell technique** — IEX + DownloadString, Base64 EncodedCommand, why it bypasses AV (no file = no hash)
- **WMI persistence** — event subscriptions survive reboots, stored in WMI repository (not registry Run key)
- **LOLBins** — be able to match certutil, mshta, regsvr32, rundll32 to their specific abuse capability
