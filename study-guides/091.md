## Operating System Security

OS security is the foundation everything else rests on — if an attacker owns the OS, they own every app, file, and network connection running on top of it. This lesson covers the key controls: patching, least privilege, file permissions, disk encryption, application control, credential protection, account management, registry security, and auditing.

---

### Patch management

**Patch management** is the process of keeping OS software updated to eliminate known vulnerabilities — the most impactful single control defenders have, since most successful attacks exploit already-patched flaws.

**Windows patch tools:**

| Tool | What it does |
|---|---|
| **Windows Update** | Delivers patches automatically to individual endpoints |
| **WSUS** (Windows Server Update Services) | Centralized server that downloads patches from Microsoft and distributes them internally on a controlled schedule |
| **MECM/SCCM** (Microsoft Endpoint Configuration Manager) | Enterprise platform unifying OS deployment, app management, compliance, and patching |
| **Windows Autopatch** | Cloud-based SaaS service that automates the full patching workflow without managing WSUS |

**Linux package managers by distro family:**

| Family | Tool(s) |
|---|---|
| Debian/Ubuntu | `apt`, `apt-get` + **unattended-upgrades** for auto security patches |
| Red Hat/CentOS/Fedora | `yum`, `dnf` + **dnf-automatic** for auto patches |
| SUSE | `zypper` |

> Think of WSUS like a local warehouse: instead of every employee ordering from the factory one-by-one (direct Windows Update), the warehouse receives the shipment once and hands out vetted copies internally.

### Least privilege and elevation controls

**Least privilege** is the principle that every user, service, and process gets only the minimum permissions needed to do its job — nothing more.

- Daily work uses a **standard user account**; admin tasks use a separate elevated account
- **UAC** (User Account Control) — a Windows mechanism that prompts for confirmation or credentials before granting administrative elevation, blocking silent privilege escalation by malware
- **sudo** — the Linux command that lets specific users run specific commands with elevated privileges; all executions are logged to `/var/log/auth.log` for an audit trail
- **Service accounts** should run with minimum rights; services running as SYSTEM or root give an attacker full control the moment that service is compromised

> UAC is like a bouncer at the admin door: even if you're already inside the building (logged in), you still have to show ID every time you try to enter the VIP area.

### File system permissions

**NTFS permissions** — the Windows file access control system — assign **Read, Write, Execute, Modify**, or **Full Control** to users/groups; child folders inherit parent permissions by default. Effective permissions = direct assignments + all group memberships combined. **icacls** — the Windows command-line tool for viewing and editing NTFS permissions.

Linux uses the **owner/group/others** model with **read (r), write (w), execute (x)** bits per class:
- **chmod** — changes permission bits; **chown** — changes file ownership
- **Sticky bit** — set on directories so users can't delete files owned by others (e.g., `/tmp`)
- **SUID/SGID** (Set User/Set Group ID) bits — when set on an executable, it runs with the *file owner's* permissions rather than the caller's; dangerous if placed on programs that can be abused for privilege escalation
- **ACLs** (Access Control Lists) — extend basic Linux permissions to allow per-user/per-group rules without the owner-group-others constraint

**Encrypted file systems** protect against physical-access attacks:
- **EFS** (Encrypting File System) — Windows feature that encrypts individual files/folders transparently using the user's certificate; other users can't read the raw data
- Linux **ext4** — supports directory-level transparent encryption for similar protection

> The sticky bit on `/tmp` is like a coat-check room: everyone can hang their coat, but only you can take yours — the attendant won't hand it to someone else.

### Disk encryption

**Disk encryption** protects data at rest when a drive is physically stolen — bypassing OS login becomes useless because the raw disk data is ciphertext.

| Solution | Platform | Key detail |
|---|---|---|
| **BitLocker** | Windows | AES-256 full-volume encryption; uses **TPM** (Trusted Platform Module — a dedicated chip that stores the key and validates pre-boot integrity) for most secure config; recovery key should be stored in Active Directory/Azure AD |
| **BitLocker To Go** | Windows | Extends BitLocker to removable drives (USB, external storage) |
| **FileVault** | macOS | XTS-AES-128 full-disk encryption integrated with Apple hardware security |
| **LUKS** (Linux Unified Key Setup) + **dm-crypt** | Linux | Block-device encryption configured at install time; standard for Linux laptops |

> BitLocker with TPM is like a car that only starts when the original key fob is present — pulling the engine (drive) out and putting it in another car (machine) won't work.

### Application control

**Application whitelisting** blocks all executables except explicitly approved ones — the opposite of blacklisting.

- **WDAC** (Windows Defender Application Control) — kernel-level whitelisting that enforces code integrity policies on executables, scripts, drivers, and DLLs; tamper-resistant because it runs below user-mode
- **AppLocker** — older Group Policy-based tool that restricts execution by file path, hash, or digital publisher; user-mode, so less tamper-resistant than WDAC
- Uninstall unnecessary applications; every installed app is a potential attack surface; keep all remaining apps patched

> WDAC at the kernel is like security screening built into the building's foundation — not a guard desk anyone can bribe on the way in.

### Credential storage security

**Credential theft** is attackers' primary way to move laterally after initial access — so protecting stored credentials is critical.

- Windows stores credentials in **LSASS** (Local Security Authority Subsystem Service — the process managing Windows authentication and credential caching)
- **Mimikatz** — a well-known attack tool that targets LSASS memory to extract password hashes and plaintext credentials, enabling **pass-the-hash** (reusing a stolen hash without knowing the plaintext password) attacks
- **Credential Guard** — uses virtualization-based security to run a hypervisor-protected LSA instance that the main OS can't directly access, preventing hash extraction even with admin access
- **Protected Users** security group — restricts high-privilege accounts from using NTLM authentication and limits Kerberos ticket lifetimes, shrinking the window of exposure if credentials are stolen

> Credential Guard is like keeping the vault combination inside a locked room that even the bank manager's key can't open — admin access to the building no longer means access to the vault.

---

### Account management

- Disable **default and guest accounts** — frequent attacker targets due to weak/default credentials
- **PAWs** (Privileged Access Workstations) — dedicated hardened machines used *only* for admin tasks, isolating privileged sessions from email/web browsing risk
- **Account lockout policy** sets: failed-attempt threshold, lockout duration, and observation window — limits brute force and **password spraying** (trying one common password against many accounts), but too aggressive a threshold lets attackers intentionally lock accounts as a denial-of-service

### Registry security (Windows)

The **Windows registry** is a hierarchical database storing system and application configuration that persists across reboots — a prime target for attacker persistence.

- Restrict write access to sensitive registry keys
- Monitor **autorun keys** (e.g., `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`) — common locations attackers plant persistence mechanisms
- Enable audit policies to log registry access for forensic investigation

---

### Security audit policies

**Audit policies** define what events Windows records — defaults are often too sparse for real security monitoring.

Key categories to audit (both successes and failures):
- Account logon events, account management, object access, privilege use, process tracking, system events, policy changes
- Failures reveal attack attempts; successes create a normal-activity baseline

On Linux, **auditd** — a daemon providing kernel-level auditing of system calls — is configured with **auditctl** (manages rules) and analyzed with **ausearch**/**aureport**; logs go to `/var/log/audit/audit.log`.

> Audit logging is like a bank's security camera: it doesn't stop the robbery, but it tells you exactly who touched what and when.

### Recap

- **WSUS/MECM/Autopatch** are enterprise Windows patch tools; Linux uses distro-specific package managers + auto-update packages
- **UAC** (Windows) and **sudo** (Linux) enforce least privilege at elevation time; LSASS is the credential target; **Credential Guard** isolates it with virtualization
- **NTFS permissions** + **icacls** on Windows; **chmod/chown** + sticky/SUID/SGID bits on Linux; **ACLs** extend both
- **BitLocker + TPM** is the Windows full-disk encryption standard; **LUKS/dm-crypt** is the Linux equivalent
- **WDAC** (kernel-level) > **AppLocker** (user-mode) for tamper resistance in application whitelisting

### Exam flags

- **BitLocker TPM integration** — expect a scenario asking which configuration prevents offline disk attacks or what stores the key
- **SUID/SGID privilege escalation risk** — likely to appear as "which special permission bit creates a privilege escalation risk on Linux executables"
- **Credential Guard vs. LSASS** — a scenario where an admin-level attacker can't extract hashes; the answer is Credential Guard using virtualization-based security
