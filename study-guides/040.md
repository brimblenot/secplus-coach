## An Overview of Malware

Malware is software intentionally designed to harm, disrupt, or compromise systems — and the Security+ exam treats it not as a list of names to memorize but as an integrated system with anatomy, persistence, evasion, and defensive countermeasures you need to reason through.

---

### Malware anatomy: dropper, payload, and C2

Every malware infection has three structural pieces working together.

- **Dropper / loader** — the delivery vehicle (malicious email attachment, infected installer, drive-by download) whose only job is to plant the main payload on the target.
- **Payload** — the actual malicious functionality: ransomware encryption, credential theft, remote access, data exfiltration.
- **C2 (Command and Control, also written C&C)** — the channel attackers use *after* deployment to send commands, pull stolen data, and update malware behavior.

Modern **C2 infrastructure** blends in by using:

| Channel | How it hides |
|---|---|
| HTTP/HTTPS on standard ports | Looks like normal web traffic |
| DNS with encoded subdomains | Covert channel through routine DNS queries |
| Peer-to-peer networks | No central server to take down |
| Legitimate cloud services (Google Docs, Twitter, Pastebin) | Trusted domains rarely blocked |

> Think of C2 like a spy handler: the malware is the field agent, and C2 is the dead-drop system letting the handler issue new orders without meeting in person.

### Persistence mechanisms

**Persistence** means the malware survives a reboot. Common Windows persistence locations:

- **Run / RunOnce registry keys** under `HKEY_LOCAL_MACHINE` or `HKEY_CURRENT_USER` — programs listed here launch automatically at login.
- **Scheduled tasks** — configurable to trigger on nearly any system condition.
- **Windows services** — registered to start automatically with the OS.
- **Startup folder** — executables placed here run at user login.

Advanced persistence abuses:

- **WMI (Windows Management Instrumentation) event subscriptions** — trigger malware when specific system events occur; WMI is a Windows framework for managing and monitoring system resources.
- **COM object hijacking** — **COM (Component Object Model)** is a Windows mechanism where applications load reusable library components; hijacking replaces a legitimate component reference with a malicious one.
- **DLL search order hijacking** — a **DLL (Dynamic Link Library)** is a shared code file Windows applications load at runtime; attackers place a malicious DLL in a folder Windows searches *before* the legitimate DLL's location.

> Think of persistence like leaving a spare key under every doormat in the house — even if you find one, others remain.

---

### Propagation vectors

How malware gets in:

- **Email** — malicious attachments (fake invoices, shipping notices) or links to drive-by download sites.
- **Drive-by downloads** — exploit browser or plugin vulnerabilities to install malware silently when a victim merely *visits* a page; no explicit download required.
- **Removable media** — USB drives carrying malware that exploits autorun functionality.
- **Worms** — exploit network service vulnerabilities to spread *autonomously*, requiring zero user action.
- **Trojans** — disguise themselves as useful software to trick users into voluntarily running them.

### Evasion techniques

**Signature-based detection** — the traditional antivirus approach; matches byte patterns in a file against a database of known malicious signatures.

The problem: attackers build malware that looks different every time.

| Technique | What it does | Why signatures fail |
|---|---|---|
| **Polymorphic malware** | Encrypts its code with a *different key* on each infection, plus may vary the decryption stub | Binary looks different each time; no stable byte pattern |
| **Metamorphic malware** | Completely rewrites its own code on each propagation using semantic-preserving transforms (inserting no-ops, reordering instructions, substituting equivalent sequences) | No consistent bytes at all; requires heuristic/behavioral detection |
| **Packers / crypters** | Compress and obfuscate the binary; malware unpacks itself at runtime | Signature matches nothing until execution |

> Polymorphic malware is like a criminal who wears a different disguise every time — same person, different face. Metamorphic malware is like a shapeshifter who literally *becomes* a different person each time while committing the same crime.

---

### Anti-analysis techniques

Sophisticated malware actively resists examination:

- **Sandbox detection** — checks for VMware/VirtualBox process names, virtual hardware IDs, absent mouse movement/browser history, or unrealistically perfect timing. If sandbox artifacts are found, malware behaves benignly.
- **Time-delay** — malware sleeps longer than the sandbox's analysis window before activating.
- **Anti-debugging** — detects whether a debugger (a tool analysts attach to step through code execution) is attached, then alters behavior to prevent analysis.

### Fileless malware and living off the land

**Fileless malware** operates entirely in system memory using legitimate OS tools, writing no malicious executable to disk — making file-scanning antivirus blind to it. Traditional antivirus scans files on disk and matches signatures; if nothing is ever written to disk, there is nothing to scan.

It abuses **LOLBins (Living off the Land Binaries)** — legitimate, trusted Windows utilities repurposed for malicious action:

| LOLBin | Legitimate purpose | Malicious abuse |
|---|---|---|
| **PowerShell** | Scripting and automation | Download/execute payloads in memory, credential harvesting |
| **WMI / wmic** | System management | Remote command execution |
| **certutil** | Certificate management | Download files, decode base64 payloads |
| **regsvr32** | Register COM components | Execute remote scripts |
| **mshta** | Run HTML applications | Execute remote malicious scripts |
| **PsExec** | Legitimate remote admin utility | Push malware to new machines during lateral movement |

A typical fileless chain: phishing link → browser exploit → PowerShell command → obfuscated in-memory script → additional payload stages, all in RAM. **Cobalt Strike Beacon** — a commercial attack-simulation tool widely abused by criminal groups and nation-states — is the canonical real-world example.

**Detecting fileless malware** requires **EDR (Endpoint Detection and Response)** — a platform that monitors and records *what processes do* (behavioral telemetry) rather than what files exist. Traditional antivirus only matches files against known signatures at execution time and keeps no record of activity, so it cannot detect or investigate in-memory threats.

> Fileless malware is like a burglar who picks your lock with your own house keys, never bringing tools from outside — nothing foreign to find at the scene.

### Malware category quick reference

| Type | Core behavior |
|---|---|
| **Virus** | Attaches to host files; needs user action to activate |
| **Worm** | Self-replicates across networks autonomously |
| **Trojan** | Disguises as legitimate software to induce execution |
| **Ransomware** | Encrypts data; demands payment for recovery |
| **Spyware** | Covertly monitors user activity |
| **Adware** | Displays unwanted advertisements |
| **Rootkit** | Hides itself and other malware from the OS and security tools |
| **Backdoor** | Maintains a persistent unauthorized access channel |
| **Botnet** | Network of compromised machines controlled for coordinated attacks |
| **Keylogger** | Records keystrokes to steal credentials |
| **RAT (Remote Access Trojan)** | Gives attacker full remote control |
| **Logic bomb** | Executes payload only when a specific trigger condition is met |

Real attacks chain these together — a Trojan dropper installs a RAT that establishes C2, which deploys ransomware.

### Defensive controls

| Control | What it addresses |
|---|---|
| AV/anti-malware (signature + behavioral) | Known malware; suspicious execution patterns |
| Email filtering with sandboxing | Detonates attachments/links before delivery |
| Web filtering | Blocks known malicious domains |
| Patch management | Closes vulnerabilities used for initial access/escalation |
| Application allowlisting | Blocks novel malware by permitting only approved executables |
| EDR | Behavioral monitoring, telemetry, automated response — catches fileless threats |
| Network traffic monitoring | Identifies C2 communication from compromised hosts |
| MFA (Multi-Factor Authentication) | Prevents credential theft (via keyloggers) from becoming account compromise |
| Offline backups | Recovery option when ransomware encryption succeeds |
| User awareness training | Reduces successful phishing delivery |

---

### Recap

- Malware has three structural layers: **dropper** (delivery), **payload** (malicious function), and **C2** (attacker communication).
- **Persistence** survives reboots via registry Run keys, scheduled tasks, services, WMI subscriptions, and DLL/COM hijacking.
- **Polymorphic** malware changes its encryption key per infection; **metamorphic** malware rewrites its entire code — both defeat signature detection.
- **Fileless malware** runs entirely in memory via LOLBins, leaving nothing on disk for antivirus to scan; EDR behavioral monitoring is the required countermeasure.
- Real attacks chain multiple malware types together rather than using any single category in isolation.

### Exam flags

- **Polymorphic vs. metamorphic evasion** — know the specific difference: polymorphic re-encrypts with a new key, metamorphic rewrites its entire code body.
- **Fileless malware and why traditional AV fails** — AV scans files on disk; fileless malware stays in memory using trusted LOLBins, requiring EDR behavioral monitoring.
- **C2 channels and blending** — expect questions on how C2 hides (HTTPS, DNS, cloud services, P2P) and why detection is difficult.
