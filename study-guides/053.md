## Password Attacks

Password attacks are one of the most common and practical threat categories on the Security+ exam. This lesson covers every major technique — from online guessing to offline cracking to hash extraction — and the defenses that counter each one.

---

### Online vs. offline attacks

The most fundamental split in password attacks is *where* the guessing happens.

**Online attacks** submit password guesses directly to a live authentication service — a login form, SSH server, or Active Directory endpoint.
- Constrained by network latency, account lockout policies, CAPTCHA, and rate limiting
- Attackers must guess slowly to avoid triggering lockouts

**Offline attacks** operate against a file of stolen **password hashes** — fixed-length outputs produced by running a password through a one-way hashing algorithm (e.g., MD5, SHA-1, NTLM). The attacker already has the hashes and tests candidates locally, with no interaction with the target.
- Tools like **Hashcat** — a GPU-accelerated password cracking tool — can test billions of hashes per second on consumer graphics cards
- Orders of magnitude faster than online approaches; most weak passwords fall within hours

*Think of online attacks like guessing a PIN at an ATM (you get 3 tries before lockout) vs. offline attacks like getting a copy of the PIN database and testing every combination at home with no timer.*

---

### Brute force

A **brute force attack** systematically tries every possible character combination for a given character set and length.

- Time grows **exponentially** with length and character set size
- 6-char lowercase-only: ~300 million combos → cracked offline in under a second
- 8-char full ASCII: ~700 trillion combos → cracked in hours to days
- 12-char random, full ASCII: centuries with current hardware
- **Length is the single most important password security property**
- Most practical when max password length is known or character set is restricted

*Brute force is like trying every locker combination at a gym — tedious but guaranteed if you have enough time.*

---

### Dictionary attacks

A **dictionary attack** uses a pre-built wordlist of real passwords, common words, names, and breach data — hashing each candidate and comparing against the target hashes.

- **rockyou.txt** — a wordlist compiled from a 2009 breach exposing 14 million plaintext passwords; the baseline wordlist for most cracking engagements
- Supplemented with other breach data, web crawls, and target-specific terms (company names, product names, employee names gathered via open-source intelligence)

*It's like consulting a "most common guesses" cheat sheet instead of trying every combination blindly.*

---

### Hybrid attacks

A **hybrid attack** combines a dictionary wordlist with **rule-based transformations** — modifications that model how users tweak simple words to meet complexity requirements.

- Appending numbers (`password1`), prepending symbols (`!password`), capitalizing first letter (`Password`)
- Substituting characters: `a → @`, `i → !`, `o → 0`
- Doubling words or combining two words
- Hashcat's rule engine applies multiple transformations per base word, generating hundreds of variations each
- Highly effective because the rules model the same shortcuts real users take

*Like knowing that most people lock their "Password" with a "1" at the end — so you test every word that way first.*

---

### Password spraying

**Password spraying** guesses one or a few common passwords against *every* account in an organization, then waits before the next round — specifically designed to stay below lockout thresholds.

- Most lockout policies trigger after 5–10 failures on *one* account; spraying stays well below that on every account
- Common spray candidates: `Summer2024!`, `Welcome1`, `Password1`, `[OrgName]1`, default system passwords
- Highly effective against large Active Directory environments where many users share predictable patterns
- **Detection**: look for low-frequency failures *spread across many accounts* — the inverse pattern of classic brute force

*Instead of hammering one door until security shows up, you knock once on every door in the building and move on.*

---

### Credential stuffing

**Credential stuffing** replays verified username/password pairs from previous breaches — it doesn't guess at all.

- Works because users reuse passwords across services; a breach at a shopping site may unlock a corporate email
- Billions of credential pairs from thousands of breaches are publicly available or sold underground
- Tools like **Sentry MBA** and **OpenBullet** — automated stuffing tools that simulate browser behavior to defeat basic bot detection
- **Have I Been Pwned** — a public service where users check if their email appears in known breach datasets
- **Best defense: multi-factor authentication (MFA)** — a replayed password pair alone is not enough for access

*It's like using a copy of someone's house key found on the street — no guessing required.*

---

### Rainbow table attacks

A **rainbow table attack** uses a precomputed lookup table mapping hash values back to the passwords that produced them, enabling near-instant cracking after the table is built.

- Building the table is expensive; using it is nearly instantaneous
- **Only works against unsalted hashes** — a **salt** is a unique random value added to each password before hashing, so two identical passwords produce different hashes, making a single table useless
- Defense: always store hashes with a unique per-user salt
- Modern algorithms **bcrypt**, **scrypt**, and **Argon2** — adaptive password hashing algorithms that automatically include per-user salts and a configurable **work factor** (deliberately slowing each hash computation to make offline cracking expensive)

*A rainbow table is like a pre-built answer key — instant if no one changed the questions, worthless if each question has a unique twist (the salt).*

---

### Hash dumping

**Hash dumping** is extracting stored password hashes from a target system for offline cracking.

| Source | What it contains | Access required |
|---|---|---|
| **SAM database** — Windows Security Accounts Manager, stores local account NTLM hashes | Local account NTLM hashes | Boot to alternate OS, access raw registry hive |
| **NTDS.dit** — the Active Directory database on domain controllers | NTLM hashes + Kerberos keys for *every* domain account | Domain administrator |
| **LSASS process** — Local Security Authority Subsystem Service, caches recently authenticated credentials in memory for single sign-on | NTLM hashes, Kerberos tickets, sometimes plaintext credentials (older configs) | Code execution on system |

**Mimikatz** — a widely used credential-extraction tool whose `sekurlsa` module reads credentials directly from LSASS memory, making hash extraction accessible to any attacker with code execution.

*LSASS is like a sticky note on the monitor with recent passwords — Mimikatz is the tool that reads it.*

**Defenses against hash dumping:**
- **Windows Credential Guard** — isolates LSASS credentials inside a Hyper-V container, preventing Mimikatz from reading them
- **Protected Users security group** in Active Directory — disables NTLM authentication for members, limiting pass-the-hash exposure

---

### Defenses summary

| Control | What it addresses |
|---|---|
| **12+ character minimum length** | Brute force |
| **Password manager** | Reuse, complexity |
| **bcrypt/scrypt/Argon2 with high work factor** | Offline cracking speed |
| **Unique salts per account** | Rainbow tables |
| **MFA** | Stuffing, spraying, all credential attacks |
| **Account lockout** | Online brute force / dictionary |
| **CAPTCHA / rate limiting** | Automated online attacks |
| **SIEM rules for cross-account low-fail patterns** | Spraying detection |
| **Credential Guard** | Mimikatz / LSASS dumping |
| **Breach monitoring services** | Early warning of external compromise |

---

### Recap

- **Online attacks** are slow and constrained by lockouts; **offline attacks** against stolen hashes are billions of guesses/second with no limits
- **Spraying** evades lockout by spreading one guess across many accounts — detected by the inverse pattern (many accounts, few failures each)
- **Credential stuffing** uses real verified pairs from breaches — MFA is the only reliable defense
- **Rainbow tables** are defeated by per-user salts; modern algorithms (bcrypt, scrypt, Argon2) include salts and slow computation automatically
- **LSASS / NTDS.dit** are the primary Windows hash sources; Mimikatz extracts from memory; Credential Guard blocks it

---

### Exam flags

- **Spraying vs. brute force** — know that spraying is specifically designed to stay below lockout thresholds and is detected by the cross-account low-frequency pattern, not the single-account high-frequency pattern
- **Salting and adaptive hashing** — know that salts defeat rainbow tables, and that bcrypt/scrypt/Argon2's work factor makes offline cracking expensive even with the hash in hand
- **Credential stuffing** — know it doesn't guess at all (replays verified breach pairs) and that MFA is the primary defense
