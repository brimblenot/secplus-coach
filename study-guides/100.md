## Scripting and Automation

Security teams are chronically understaffed relative to the volume of events and systems they must manage. Scripting and automation let teams scale operations, reduce human error in repetitive tasks, and free analysts for judgment-intensive work that machines cannot replace.

---

### Scripting languages and what they're good for

**Bash/shell scripting** is the native automation language for Linux and macOS. It handles file manipulation, process management, log parsing, and general system administration. **Cron jobs** — scheduled tasks defined in a time-based table on Unix systems — let shell scripts run automatically at set intervals (log rotation, backups, periodic security checks) without human initiation.

**PowerShell** is Microsoft's scripting language for Windows administration. It provides native access to:
- **Active Directory** — the Windows directory service for managing users, groups, and policies
- **Windows Registry** — the hierarchical database storing Windows configuration settings
- **WinRM** (Windows Remote Management) — the protocol for running commands on remote Windows machines
- **Windows Event Logs** — the built-in audit trail for system and security events

Because PowerShell ships on every Windows machine and can run code entirely in memory (no files written to disk), attackers love it for post-exploitation. Windows counters this with **AMSI** (Anti-Malware Scan Interface) — a runtime hook that lets security products scan PowerShell code as it executes, even after obfuscation.

Security teams should enable all three PowerShell logging modes:

| Logging mode | What it records |
|---|---|
| **Script Block Logging** | Actual code in each script block, including deobfuscated content |
| **Module Logging** | Pipeline execution details |
| **Transcription Logging** | Full text transcript of every session — all input and output |

Think of these logs as a court reporter sitting in the room every time PowerShell runs — nothing said goes unrecorded.

**Python** is the most versatile security language. Key libraries:

| Library | What it does |
|---|---|
| **Scapy** | Crafts, sends, receives, and dissects raw network packets |
| **Requests** | Automates HTTP interaction with web APIs and applications |
| **Paramiko** | Implements SSH for remote system access and management |
| **Impacket** | Implements Windows protocols (SMB, NTLM, Kerberos) for testing |
| **Volatility** | Memory forensics framework for analyzing RAM captures |

**Ruby** is less common in general security work but is the native language of **Metasploit** — the widely used penetration testing and exploit development platform — making Ruby knowledge useful for writing Metasploit modules.

### Automation use cases across the security lifecycle

- **User provisioning/deprovisioning** — HR system changes automatically create or disable accounts in Active Directory; departing employees lose access immediately, not after someone files a ticket.
- **Vulnerability scanning orchestration** — scans run on schedule, findings are parsed by severity, and tickets are automatically created in the IT ticketing system for anything above the risk threshold.
- **Patch management** — identifies unpatched systems, deploys patches to target groups, verifies success, and generates compliance reports.
- **Log aggregation and parsing** — collects logs from diverse sources, normalizes formats to a common schema, enriches events with asset and threat-intel context, then forwards to a **SIEM** (Security Information and Event Management system — a platform that aggregates and correlates security events for alerting).
- **Incident response** — handled by **SOAR** platforms (see below).

### SOAR: automated incident response at machine speed

**SOAR** (Security Orchestration, Automation and Response) is a platform category that integrates the full security tool stack and executes automated response workflows called **playbooks**. When a SIEM raises a malware alert, a SOAR playbook can — within seconds — query the **EDR** (Endpoint Detection and Response) platform for the process tree, block the malicious hash and IP across all endpoints, isolate the infected machine, collect forensic artifacts, open an incident ticket, and page the on-call analyst.

The key metric SOAR improves is **MTTR** (Mean Time to Respond) — the average time from alert generation to incident containment.

Major SOAR platforms: Splunk SOAR (formerly Phantom), Microsoft Sentinel (via Azure Logic Apps), Palo Alto Cortex XSOAR, IBM Security SOAR.

Think of a SOAR playbook as a fire-suppression system: the moment a sensor detects smoke, sprinklers activate, alarms sound, and the fire department is called — no human needs to decide each step.

### Infrastructure as Code (IaC) and configuration management

**IaC** (Infrastructure as Code) applies scripting principles to provisioning infrastructure itself. **Terraform** (HashiCorp's IaC tool) defines cloud or on-premises resources in declarative config files that can be version-controlled and applied consistently. Equivalent cloud-native tools: AWS CloudFormation, Azure Resource Manager, Google Cloud Deployment Manager.

**Ansible**, **Puppet**, and **Chef** are **configuration management** tools — software that enforces a defined server configuration, detects **configuration drift** (when a system's actual state diverges from its intended state), and remediates it automatically.

Security benefits of IaC:
- Security groups and **ACLs** (Access Control Lists — rules that permit or deny network traffic) are baked into Terraform templates and applied automatically at provisioning.
- Ansible playbooks can apply **CIS Benchmark** hardening — the Center for Internet Security's prescriptive configuration standards — to every new server.
- IaC templates can be scanned before deployment with tools like **Checkov**, **tfsec**, and **cfn-nag** — static analysis tools that detect misconfigurations in IaC code — catching problems in development, where fixes are cheap.

### Automation risks and secrets management

Automation runs with elevated service-account privileges — a misconfigured or compromised automation system can cause serious damage at machine speed. Key controls:

- **Least privilege** — automation accounts get only the access the task requires, nothing more.
- **Idempotent design** — an **idempotent** script produces the same end state whether run once or ten times, preventing partial-execution inconsistencies.
- Input validation, error handling, and testing in non-production before production deployment.
- Avoid **technical debt** — using automation to mask underlying infrastructure problems rather than fixing root causes creates fragile, accumulating risk.

**Secrets management** addresses a specific risk: scripts that need credentials to call APIs or authenticate to systems. Hardcoding credentials in plaintext inside a script — especially one stored in version control — is a frequent source of credential exposure. The correct approach is a **secrets vault**: solutions like **HashiCorp Vault**, **AWS Secrets Manager**, or **Azure Key Vault** store credentials outside the script; the script retrieves them at runtime using its own service identity. This allows credential rotation without touching the script.

Think of hardcoded credentials like writing the safe combination on a sticky note taped to the safe — anyone who sees the note owns the safe.

### REST API integration

**REST APIs** (interfaces that let software systems exchange data over HTTP using standard web conventions) allow security tools that would otherwise operate in isolation to share data and trigger actions in each other. Most modern security products expose REST APIs for querying threat intelligence, submitting file hashes for reputation lookup, pushing blocking rules, pulling scan data, and triggering responses. This enables custom integrations beyond what vendor connectors provide.

---

### Recap

- Bash handles Linux/macOS automation; PowerShell handles Windows — but PowerShell's power makes it an attacker favorite, countered by AMSI and three logging modes.
- Python dominates security tool development via libraries like Scapy, Impacket, and Volatility; Ruby matters specifically for Metasploit.
- SOAR platforms execute playbooks to automate incident response end-to-end, with MTTR as the key metric.
- IaC embeds security controls at provisioning time; pre-deployment scanning (Checkov, tfsec, cfn-nag) catches misconfigurations before they reach production.
- Hardcoded credentials in scripts are a major risk — use secrets vaulting solutions instead.

### Exam flags

- **PowerShell logging modes** — know what Script Block, Module, and Transcription Logging each record, and why AMSI matters.
- **SOAR vs. manual IR** — be able to describe what a SOAR playbook automates and that MTTR is the metric it targets.
- **Secrets management** — know why hardcoded credentials in scripts are dangerous and that vault solutions (HashiCorp Vault, AWS Secrets Manager, Azure Key Vault) are the correct alternative.
