## Hardening Techniques

System hardening is the process of locking down a system so attackers have as little to work with as possible. This lesson covers every layer — OS, applications, network devices, wireless, and mobile — along with the standards used to measure how well you've done.

---

### The guiding principle: minimal footprint

**Minimal footprint** means a system should have only what it needs to do its job — nothing more. Every extra service, open port, default account, or unused feature is a door an attacker can try.

- Remove what isn't needed
- Configure only what's required
- Run only the services the system's role demands

> Think of it like packing for a camping trip: every item you don't bring is one less thing that can break, get lost, or slow you down.

---

### OS hardening

**OS hardening** is the process of securing the operating system itself through patching, account controls, and local firewall rules.

**Patching**
- An unpatched OS is the most common exploitation vector
- Apply security updates promptly — public exploits often exist for known vulnerabilities

**Account management**
- **Default accounts** (e.g., Windows Guest) — pre-built accounts that ship with the OS — should be disabled
- Rename or replace default admin accounts so the name doesn't reveal privilege level
- Passwords: minimum 12 characters with complexity requirements
- **Account lockout policy** — a setting that locks an account after a small number of failed login attempts, blocking online brute-force attacks
- Apply **least privilege** — grant only the rights a user needs; revoke elevated rights immediately after use
- Separate admin accounts from daily-use accounts: browse the web and read email as a regular user, not as admin

**Host-based firewall**
A **host-based firewall** controls traffic to and from a single machine, enforcing its rules no matter which network the machine is on. This is different from a **perimeter firewall** — a device that sits at the edge of a network and only filters traffic crossing that boundary; a perimeter firewall offers no protection once a laptop leaves the office and connects to a coffee-shop Wi-Fi.

- **Windows Defender Firewall**, **iptables** / **nftables** (Linux) provide host-based firewall functionality
- Default rule: deny all inbound; allow only required ports
- Outbound rules can block malware from calling home to **command-and-control (C2)** infrastructure — attacker-controlled servers that send instructions to compromised machines

> A host-based firewall is like a bouncer who travels with you everywhere — the club's door staff (perimeter firewall) can't help you once you've left the building.

### Endpoint Detection and Response

**EDR** — Endpoint Detection and Response — is a security platform that continuously monitors endpoint behavior to detect and respond to threats. Traditional **antivirus** only compares file hashes against a database of known-bad signatures at execution time and keeps no record of activity, so it cannot catch novel threats or look back at what already happened.

EDR goes further by:
- Watching **process execution trees** — the parent/child relationships between running programs
- Detecting **process injection** — when malicious code is inserted into the memory space of a legitimate process
- Tracking network connections per process
- Applying machine learning to spot attack patterns without needing a matching signature
- **Automatically quarantining** systems, terminating malicious processes, and rolling back to a known-good state

> Think of antivirus as a "most-wanted" poster — it only catches faces it already knows. EDR is a detective who watches everyone's behavior and flags anything suspicious, even from a stranger.

### Data encryption

**Full disk encryption (FDE)** encrypts an entire storage volume — OS, files, everything — so a stolen drive is unreadable without the decryption key.

| Tool | Platform |
|------|----------|
| **BitLocker** | Windows |
| **FileVault** | macOS |
| **LUKS** — Linux Unified Key Setup | Linux |

- Keys protected by PIN, password, or **TPM** — a dedicated security chip on the motherboard that stores encryption keys
- **EFS** — Windows Encrypting File System — encrypts individual files/folders without encrypting the whole volume
- **TLS** — Transport Layer Security — encrypts data in transit between systems

---

### Host-based IDS and IPS

A **host-based IDS** — Intrusion Detection System — monitors OS-level activity (system calls, file changes, registry edits, network connections) and generates alerts when attack patterns are detected. A **host-based IPS** — Intrusion Prevention System — takes automated blocking action, such as terminating a process trying to modify a protected registry key. This functionality is often built into the EDR platform.

### Application hardening

**Application hardening** secures the software running on a system.

- Keep applications updated — outdated versions often have published exploits
- Remove or disable unused features, modules, and extensions
- Disable **debug mode** and diagnostic endpoints in production — these often expose sensitive internals
- Return **generic error messages** to users; log detailed errors locally (prevents attackers from mapping the app)
- Enforce TLS for all network communication; disable older protocol versions

**Web server–specific hardening**

| Setting | Why it matters |
|--------|----------------|
| Disable **directory listing** | Stops browsers from seeing the server's file structure when no index file exists |
| Suppress **server version banners** | Hides exact software version from attackers in HTTP response headers |
| Disable unneeded **HTTP methods** (TRACE, PUT, DELETE) | Reduces attack surface; most apps only need GET and POST |
| **HSTS** — HTTP Strict Transport Security | Tells browsers to only connect via HTTPS for this domain |
| **CSP** — Content Security Policy | Restricts what resources a page may load and from where |
| **X-Frame-Options** | Prevents the page from loading inside an iframe, blocking **clickjacking** — an attack where a hidden frame tricks users into clicking something they can't see |
| **X-Content-Type-Options** | Stops browsers from **MIME-sniffing** — guessing a file's type instead of trusting the declared content type — which can enable script injection |

### Network device hardening

**Network device hardening** secures routers, switches, firewalls, wireless access points, and other infrastructure.

**First priority: change all default passwords.** Vendor-default credentials are publicly documented and are among the first things attackers try.

| Hardening action | Detail |
|-----------------|--------|
| Replace **Telnet** with **SSH** | **Telnet** sends everything — including passwords — in cleartext; **SSH** — Secure Shell — encrypts the session |
| Replace HTTP management with **HTTPS** | Encrypts admin web interface traffic |
| Use **SNMPv3** | **SNMP** — Simple Network Management Protocol — v1 and v2 use only a "community string" (essentially a shared password in cleartext) for authentication; **SNMPv3** adds real authentication and encryption |
| Disable unneeded services | Disable **CDP** — Cisco Discovery Protocol, which advertises device info to neighbors — **Finger** protocol, and **DTP** — Dynamic Trunking Protocol, which negotiates trunk links between switches — on access ports |
| **ACLs** on management interfaces | **ACL** — Access Control List — restricts management access to specific trusted IP addresses |
| **802.1X port authentication** | Requires devices to authenticate with valid credentials before connecting to a switch port |
| **BPDU Guard** | **BPDU** — Bridge Protocol Data Unit — messages are used by **STP** — Spanning Tree Protocol — to prevent network loops; BPDU Guard blocks unauthorized switches from joining the STP topology on access ports |
| **DHCP Snooping** | Validates DHCP traffic to block **rogue DHCP servers** — unauthorized servers that hand out false IP configuration, redirecting traffic |
| **Dynamic ARP Inspection (DAI)** | Validates **ARP** — Address Resolution Protocol — packets to prevent **ARP poisoning**, where an attacker sends fake ARP replies to redirect traffic through their machine; DAI depends on DHCP Snooping to work |

### Wireless hardening

**Wireless hardening** means selecting the strongest available security protocol and eliminating known weaknesses.

| Protocol | Status |
|---------|--------|
| **WPA3** | Current standard; uses **SAE** — Simultaneous Authentication of Equals — handshake that resists offline dictionary attacks |
| **WPA2** | Acceptable with a passphrase of 20+ characters |
| **WPA** | Insufficient — do not use |
| **WEP** — Wired Equivalent Privacy | Completely broken — never use |

- **WPS** — Wi-Fi Protected Setup — should be disabled; its PIN-based method can be brute-forced in hours
- Change default **SSID** names — the network name that access points broadcast — so they don't reveal the hardware vendor or model
- Change default admin credentials on the access point immediately
- **WPA2/WPA3-Enterprise** uses **802.1X** with a **RADIUS server** — a centralized authentication server — for per-user credentials; revoking one user doesn't affect everyone else
- **EAP-TLS** — a wireless authentication method that requires certificates on both the client and the access point — is the most secure option and defeats **evil twin attacks** — rogue access points that impersonate a legitimate one — because the fake AP cannot present a valid certificate

### Mobile device hardening

**Mobile device hardening** applies security controls to smartphones and tablets.

- Enforce PIN or biometric authentication
- Enable full device encryption (default on modern iOS and Android)
- Enroll in **MDM** — Mobile Device Management — a platform that enforces security policies and enables remote wipe
- Disable **developer mode** and **USB debugging** — settings that grant privileged low-level access to the device
- Use **VPN** on untrusted networks; MDM profiles can enforce all of the above and lock users out of changing them

### Hardening standards

**CIS Benchmarks** — free, consensus-developed configuration guides published by the **Center for Internet Security** — provide specific, testable settings for particular OS versions, applications, and cloud platforms.

| Level | Posture |
|-------|---------|
| **Level 1** | Balanced — strong security with minimal usability/performance impact |
| **Level 2** | High security — for the most sensitive environments; some settings may affect compatibility |

**STIGs** — Security Technical Implementation Guides — are security configuration standards developed by **DISA** — the Defense Information Systems Agency — for use across U.S. Department of Defense systems, with mandatory compliance requirements in that context.

### Recap

- **Minimal footprint**: disable, remove, and close everything not explicitly required
- **Host-based firewall** travels with the device and protects it on any network; a perimeter firewall does not
- **EDR** uses behavioral analysis and memory inspection to catch threats antivirus misses because antivirus only matches known file signatures
- **WEP is broken, WPS is brute-forceable** — use WPA3 (or WPA2-Enterprise) and disable WPS
- **Default credentials must be changed** on every device and application before production use

### Exam flags

- **EDR vs. antivirus**: know that antivirus relies on signature matching and EDR adds behavioral monitoring, process inspection, and automated response
- **Wireless protocol ranking**: WPA3 > WPA2 (20+ char passphrase) > WPA (insufficient) > WEP (broken); WPS disabled
- **Web security headers**: be able to match HSTS, CSP, X-Frame-Options, and X-Content-Type-Options to their specific defensive purpose
