## On-path attacks

On-path attacks are a foundational attack category in which an adversary secretly intercepts traffic between two parties — both of whom think they're talking directly to each other. Understanding the mechanics here unlocks several other attack types on the exam.

---

### What an on-path attack is

An **on-path attack** (historically called a **man-in-the-middle attack**) is an attack where the adversary secretly positions themselves between two communicating parties, reading and potentially modifying every message in real time, while each party believes it has a direct connection to the other.

- Attacker **relays** messages to maintain the illusion of a normal session
- Attacker can **modify data in transit** — change dollar amounts, inject commands, alter content
- Invisibility to the victims is what makes it dangerous and what enables the subtypes below

> Think of it like a postal worker who opens every letter, reads it, optionally rewrites it, reseals it, and delivers it — neither sender nor recipient knows the letter was ever touched.

---

### ARP spoofing (local network on-path)

**ARP** — Address Resolution Protocol — is the mechanism a device uses to discover which MAC address (hardware address) corresponds to a given IP address on the local network. A device broadcasts "who has IP X?" and the owner replies with its MAC, which gets cached.

**ARP spoofing** (also called **ARP poisoning**) is an attack that sends forged ARP replies to poison a victim's ARP cache — replacing a trusted host's real MAC address with the attacker's MAC — so that traffic intended for that host is physically delivered to the attacker instead.

- ARP has **no authentication** — any device can send an unsolicited **gratuitous ARP** reply and other devices will accept it
- Attacker poisons **both directions**: victim → attacker → gateway, and gateway → attacker → victim
- Tools: **arpspoof**, **Ettercap**, **Bettercap**

**Defenses:**

| Defense | How it works |
|---|---|
| **Dynamic ARP Inspection (DAI)** | Managed switch validates ARP replies against a DHCP snooping binding table; drops mismatches |
| **DHCP snooping** | Builds the trusted IP-to-MAC table that DAI checks against |
| Static ARP entries | Manually lock critical hosts (gateway) so cache can't be poisoned |
| VLAN segmentation / port security | Limits the broadcast domain an attacker can poison |

> Like a building directory that anyone can update with a fake room number — DAI is the security guard who cross-checks every update against the official lease records before posting it.

### SSL stripping (HTTPS downgrade)

**SSL stripping** (also called an **HTTPS downgrade attack**) is an on-path technique where the attacker intercepts the victim's initial plain HTTP request, establishes an HTTPS session with the real server themselves, and returns only an HTTP response to the victim — so the victim communicates with the attacker in cleartext while the attacker holds the encrypted session with the server.

- Victim sees **no padlock**, no `https://` — but assumes the site is real
- Attacker reads every password, session token, and form submission in cleartext
- Only works if the victim's browser makes an initial HTTP request (i.e., user didn't type `https://`)

**Defenses:**

| Defense | What it does |
|---|---|
| **HSTS** (HTTP Strict Transport Security) | Server header that tells the browser: always use HTTPS for this domain, for `max-age` seconds |
| **HSTS preloading** | Domain is hardcoded into browsers before first visit — eliminates the initial HTTP request entirely |

> SSL stripping is like a translator who intercepts your letter written in a foreign language, reads the cleartext translation, then passes along the original encrypted version to the recipient. HSTS preloading is like refusing to ever send the letter by regular mail in the first place.

### BGP hijacking (internet-scale on-path)

**BGP** — Border Gateway Protocol — is the routing protocol that determines how traffic moves between large networks (called **autonomous systems** — independently operated networks, like ISPs) across the internet. Routers running BGP announce which IP address ranges they can reach.

**BGP hijacking** is an attack where an adversary controlling a BGP router announces a false or more-specific route for a target IP range, causing other networks to route internet traffic through the attacker's infrastructure.

- Traditional BGP has **no cryptographic verification** of route announcements — it runs on trust between operators
- Can redirect traffic **globally within minutes**
- Used for: cryptocurrency theft, mass credential harvesting, surveillance

**Defense — RPKI** (**Resource Public Key Infrastructure**): a system that provides cryptographic proof of which autonomous system has the right to announce a given IP prefix, so routers can reject illegitimate route announcements.

> Think of BGP hijacking as announcing at an airport departures board that all flights to New York now leave from your gate — everyone lines up at the wrong gate before anyone notices.

### Session hijacking

**Session hijacking** is an attack where the adversary steals a valid, already-authenticated **session token** — typically stored in a browser cookie — and presents it to the server to impersonate the victim without needing their password.

- After login, the server issues a session token; every subsequent request includes it to prove "I'm still the authenticated user"
- Token capture methods: **XSS** (cross-site scripting — malicious script in a page that steals cookie contents), **packet sniffing** on unencrypted connections, **sidejacking** (capturing cookies on open Wi-Fi, popularized by the **Firesheep** Firefox extension)

**Defenses:**

| Defense | What it prevents |
|---|---|
| HTTPS everywhere | Stops packet sniffing / sidejacking |
| `HttpOnly` cookie flag | Blocks JavaScript (XSS) from reading the cookie |
| `Secure` cookie flag | Cookie only sent over HTTPS, never HTTP |
| Short session lifetimes | Limits replay window if token is stolen |
| Token regeneration after login/role change | Invalidates tokens captured before privilege escalation |

> A session token is like a wristband at a concert — if someone copies your wristband, they can get back in without showing ID. The `HttpOnly` flag is laminating the wristband so it can't be photocopied by the venue's own screens.

### TLS inspection (authorized on-path)

**TLS inspection** (also called **SSL inspection** or **HTTPS interception**) is an intentional on-path technique deployed by enterprise security appliances: a corporate firewall or proxy terminates the client's TLS connection, decrypts the traffic for **DLP** (data loss prevention — scanning outbound data to stop leaks) or malware scanning, re-encrypts it, and forwards it.

- Client receives a certificate signed by the **organization's internal CA** (certificate authority — the trusted entity that issues and signs digital certificates), not the real website's certificate
- Legitimate when users are informed and the org's CA certificate is installed on corporate devices
- Creates an **authorized** man-in-the-middle for all encrypted web traffic

> Like a mailroom that legally opens, scans for prohibited items, reseals, and forwards every package — employees know it happens as a condition of using company mail.

### Downgrade attacks

A **downgrade attack** forces two communicating parties to negotiate a weaker, older cryptographic protocol than they would prefer — one the attacker can then break.

Three historically significant examples:

| Attack | Full name | What it exploited |
|---|---|---|
| **POODLE** | Padding Oracle On Downgraded Legacy Encryption | Forced fallback to SSLv3, then exploited its CBC padding weakness |
| **BEAST** | Browser Exploit Against SSL and TLS | Exploited CBC mode weakness in TLS 1.0 via chosen-plaintext attack |
| **DROWN** | Decrypting RSA with Obsolete and Weakened eNcryption | Servers supporting both SSLv2 and modern TLS had TLS traffic decrypted via SSLv2's weak key exchange |

- **CBC mode** — Cipher Block Chaining, a block cipher mode with padding that, in older implementations, leaks information through error responses (**padding oracle**)
- **Defense for all three**: disable obsolete protocol versions entirely

| Protocol | Status |
|---|---|
| SSLv2, SSLv3 | Disabled — do not use |
| TLS 1.0, TLS 1.1 | Disabled — do not use |
| TLS 1.2 | Minimum acceptable |
| TLS 1.3 | Preferred — handshake design prevents downgrade via authenticated negotiation |

> A downgrade attack is like a spy who jams a secure radio channel so both parties fall back to unencrypted walkie-talkies — then listens freely. TLS 1.3's authenticated negotiation is like a radio that refuses to switch to an insecure channel no matter what.

---

### ICMP redirect attacks

**ICMP** — Internet Control Message Protocol — is a network-layer protocol used for diagnostics and control messages (like "host unreachable" or "use a better route").

An **ICMP redirect attack** sends a crafted ICMP Redirect message to a victim, instructing it to update its routing table to use the attacker as the next hop for a specific destination.

- Most modern operating systems **ignore ICMP redirects by default**
- Still a risk on misconfigured or legacy systems

---

### Comprehensive defenses summary

| Defense | Threat it addresses |
|---|---|
| TLS 1.3 with mutual authentication | General on-path interception |
| Certificate pinning | Fraudulent certificates in mobile apps |
| VPN tunnels | Encrypts all traffic regardless of application |
| DAI + DHCP snooping | ARP poisoning |
| HSTS + HSTS preloading | SSL stripping |
| RPKI | BGP hijacking |
| DNSSEC | DNS-based redirection |
| `HttpOnly` + `Secure` cookie flags, short lifetimes | Session hijacking |
| Disable TLS 1.0/1.1 and SSLv3 | Downgrade attacks |

---

### Recap

- An on-path attack secretly inserts the attacker between two parties who believe they're communicating directly; the attacker can read and modify all traffic
- **ARP spoofing** poisons ARP caches to redirect local LAN traffic; **DAI + DHCP snooping** on managed switches is the primary defense
- **SSL stripping** downgrades HTTPS to HTTP so the attacker reads cleartext; **HSTS preloading** eliminates the initial HTTP request that makes the attack possible
- **BGP hijacking** redirects internet-scale traffic via false route announcements; **RPKI** provides cryptographic route verification
- **Session hijacking** steals authenticated cookies; `HttpOnly`, `Secure` flags, HTTPS, and short lifetimes limit exposure; downgrade attacks (POODLE, BEAST, DROWN) are defeated by disabling TLS 1.0/1.1 and below

---

### Exam flags

- **ARP spoofing mechanics and DAI as the defense** — know the role of DHCP snooping in building the binding table DAI validates against
- **SSL stripping vs. HSTS vs. HSTS preloading** — know why preloading is stronger (prevents the first HTTP request, not just subsequent ones)
- **POODLE / BEAST / DROWN** — be able to match each name to what it exploited and that disabling old TLS/SSL versions is the fix
