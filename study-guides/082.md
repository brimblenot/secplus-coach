## Vulnerability Scanning

Vulnerability scanning is how organizations systematically find their own weaknesses before attackers do. This lesson covers what scanning is, how different scan types work, how findings are scored, and how to prioritize what to fix first.

---

### Scanning vs. penetration testing

**Vulnerability scanning** is the automated process of testing systems, networks, and applications to identify known weaknesses, misconfigurations, and missing patches — and *reporting* them without exploiting them.

**Penetration testing** goes further: it actually *exploits* those vulnerabilities to demonstrate real-world impact.

- Scanning = find and report
- Pen testing = find, exploit, and prove

> Think of scanning as a building inspector who flags every code violation on a clipboard — versus a pen tester who actually kicks the door in to prove the lock is broken.

---

### Why organizations scan

Scanning serves two overlapping purposes: **compliance** and **proactive risk management**.

Key compliance mandates:

| Framework | Scanning Requirement |
|---|---|
| **PCI DSS** — payment card security standard | Quarterly external scans by an **ASV** (Approved Scanning Vendor); internal scans after significant changes |
| **HIPAA** — healthcare data privacy law | Regular technical and non-technical security evaluations |
| **SOC 2** — service org security audit framework | Vulnerability management assessed as part of security criteria |
| **FedRAMP** — federal cloud authorization program | Continuous monitoring including scanning for cloud systems used by federal agencies |

---

### Types of vulnerability scans

**Network vulnerability scanning** connects to target IP addresses over the network and checks for exposed services, missing patches, default credentials, and known-vulnerable software versions.

**Web application scanning** interacts with web interfaces and analyzes application behavior to find vulnerabilities in the **OWASP Top 10** — a ranked list of the most critical web app risks, including SQL injection, cross-site scripting, and broken authentication.

**Configuration compliance scanning** compares a system's actual settings against a security baseline such as a **CIS Benchmark** (Center for Internet Security hardening standard) or **DISA STIG** (Defense Information Systems Agency security configuration guide), and reports every deviation.

**Database scanning** checks database instances for default/weak credentials, unpatched versions, and excessive privilege grants.

**CSPM** — **Cloud Security Posture Management** — continuously scans cloud environments for misconfigurations like publicly accessible storage buckets or disabled logging.

---

### Authenticated vs. unauthenticated scanning

This is one of the most tested distinctions in vulnerability scanning.

**Unauthenticated scanning** (non-credentialed) simulates an external attacker: the scanner connects to services without logging in and observes only what's externally visible — open ports, service banners, network-level exposures.

- Cannot see installed software, patch status, registry settings, or local config
- Produces significantly more **false positives** — the scanner must *guess* versions from banners rather than read them directly

**Authenticated scanning** (credentialed) gives the scanner login credentials so it can read the actual software inventory, patch status, registry settings, and service configuration directly from the system.

- Far more accurate and comprehensive
- Preferred for internal scanning

> Unauthenticated scanning is like a doctor guessing your age from an X-ray; authenticated scanning is like reading your birth certificate directly.

---

### Agent-based vs. agentless scanning

**Agent-based scanning** installs a lightweight software **agent** — a small background program — on each target system. The agent runs continuously and reports findings to a central console.

- Always-current data; doesn't wait for a scheduled scan
- Works even when a laptop is off-network (home Wi-Fi, hotel)
- Tradeoff: requires installing and maintaining software on every system

**Agentless scanning** connects remotely over the network using credentials — no software installed on the target.

- Works well for servers and network devices where agent installation is impractical
- Requires the scanner to reach the target over the network when the scan runs

### Scan frequency

- **Continuous** (agent-based) — preferred for all endpoints
- **Monthly** authenticated scans — internal assets minimum
- **Quarterly** external scans — internet-facing systems (required by PCI DSS)
- **Immediately** after major infrastructure changes or a critical public vulnerability disclosure

---

### Reading scan results: false positives and false negatives

Each finding includes a **CVSS score** (severity number), a **CVE identifier** — a unique ID cross-referencing the **National Vulnerability Database** (**NVD**) entry — plus a description, affected systems, and remediation guidance.

**False positive** — scanner reports a vulnerability that doesn't actually exist (e.g., version banner looks vulnerable but a patch was applied without updating the version string). More common with unauthenticated scans; requires human validation.

**False negative** — a real vulnerability exists but the scanner misses it (e.g., zero-day not yet in the plugin database, or a custom app vulnerability). Also more likely with unauthenticated scans.

---

### CVSS scoring

**CVSS** — **Common Vulnerability Scoring System** — gives each vulnerability a standardized numerical severity score from 0.0 to 10.0.

Key base score metrics:

| Metric | What it measures | Values |
|---|---|---|
| **Attack Vector** | How the attacker reaches the target | Network / Adjacent / Local / Physical |
| **Attack Complexity** | Conditions needed for exploitation | Low / High |
| **Privileges Required** | Access level attacker needs | None / Low / High |
| **User Interaction** | Does a victim need to do something? | None / Required |
| **Scope** | Can exploitation spread beyond the vulnerable component? | Unchanged / Changed |
| **CIA Impact** | Effect on Confidentiality, Integrity, Availability | None / Low / High |

Severity ranges and remediation timelines:

| Score | Rating | Typical Patch Window |
|---|---|---|
| 9.0–10.0 | **Critical** | 24–48 hours (internet-exposed) |
| 7.0–8.9 | **High** | 7–14 days |
| 4.0–6.9 | **Medium** | ~30 days |
| 0.1–3.9 | **Low** | Quarterly patch cycle |

> A CVSS score is like a restaurant health inspection score — it gives a standardized severity rating, but you still need to know if the inspector visited a food truck or a hospital cafeteria to judge the real risk.

---

### Vulnerability prioritization

**CVSS score alone doesn't equal real-world risk.** Effective prioritization combines four factors:

1. **CVSS severity** — how bad is it in general?
2. **Exploitability** — does a working exploit exist in the wild? Is it used by ransomware groups?
3. **Asset criticality** — what data does this system hold? What business processes depend on it?
4. **Exposure** — is the system internet-facing or isolated internally?

Two prioritization tools:

- **CISA KEV** — **CISA Known Exploited Vulnerabilities** catalog: lists CVEs confirmed as actively exploited in real attacks → treat as highest priority
- **EPSS** — **Exploit Prediction Scoring System**: uses machine learning to predict the probability a CVE will be exploited in the next 30 days → forward-looking complement to CVSS

> Prioritizing by CVSS alone is like triaging ER patients purely by how loud they're screaming — EPSS and KEV tell you which ones are actually about to crash.

---

### Recap

- Vulnerability scanning *identifies and reports* weaknesses; penetration testing *exploits* them — never confuse the two
- Authenticated scans are dramatically more accurate than unauthenticated scans because they read software/patch data directly instead of guessing from banners
- Agent-based scanning covers off-network endpoints continuously; agentless scanning requires network reachability
- CVSS scores 9.0–10.0 = Critical → patch internet-exposed systems within 24–48 hours
- Prioritize using CVSS + CISA KEV (confirmed exploited) + EPSS (predicted exploitability) + asset criticality, not CVSS alone

### Exam flags

- **Authenticated vs. unauthenticated scanning** — expect scenario questions asking which produces more false positives (unauthenticated) and which is preferred for internal scans (authenticated)
- **CVSS metric definitions** — Attack Vector, Scope, and the four severity bands (Critical/High/Medium/Low with their score ranges) are highly testable
- **PCI DSS scanning requirements** — quarterly external scans by an ASV and scanning after significant changes are classic compliance scenario answers
