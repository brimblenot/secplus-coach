## Security Monitoring

Security monitoring is the continuous observation of systems, networks, and user activity to catch threats before they cause lasting damage. This lesson covers the platforms, data sources, and detection techniques that make up a real-world monitoring program — and the concepts CompTIA expects you to know cold.

---

### Why monitoring speed matters

The average breach goes undetected for **nine months** (IBM Security, 2022). In that window, attackers escalate privileges, move laterally, and entrench themselves. Continuous monitoring compresses detection from months to minutes.

> Think of it like a motion-sensor alarm vs. checking your security footage once a year — one catches the burglar in the act, the other finds the damage long after.

---

### SIEM — the central platform

A **SIEM** — Security Information and Event Management system — is the core platform that collects, normalizes, correlates, and alerts on log data from across the entire environment.

- Pulls logs from firewalls, IDS/IPS, servers, endpoints, cloud services, databases, and applications
- **Log aggregation** — the process of collecting logs from distributed sources into one central repository; sources either *push* (via **syslog** — a standard protocol for forwarding log messages — or API) or the SIEM *pulls* (via API queries, network shares, or database queries)
- **Log normalization** — extracting common fields (timestamp, source IP, destination IP, user, action, result) from inconsistent formats and mapping them to a single schema so sources can be compared

> Think of a SIEM like a universal translator that takes logs written in a hundred different languages and converts them all to one so a single analyst can read them together.

---

### Correlation rules and alerting

A **correlation rule** defines a multi-source pattern that, taken together, signals suspicious activity. A single failed login is noise; 100 failed logins from one IP against 10 accounts in 5 minutes followed by a success is a **credential stuffing** (automated use of stolen username/password pairs) or **password spraying** (trying one common password across many accounts) attack.

Example rules:
- VPN login from a geography inconsistent with the user's normal location
- Privilege escalation shortly after an authentication failure sequence
- Large outbound transfer following a connection from a known-malicious IP
- Process creation of **Mimikatz** — a credential-dumping attack tool — or PowerShell with encoded commands

**Real-time alerting** fires when a rule matches or a threshold is crossed. **Alert fatigue** — the phenomenon where analysts begin ignoring alerts because too many fire for legitimate activity — is countered by **alert tuning**: suppressing known-good patterns and raising thresholds based on behavioral baselines.

---

### SOAR — automated response

**SOAR** — Security Orchestration, Automation and Response — extends the SIEM by executing automated response **playbooks** (predefined step-by-step response workflows) when specific alerts fire.

Example phishing playbook (runs in seconds, no human needed):
1. Extract sender, URLs, attachments
2. Query threat intelligence for reputation
3. Block sender and URLs in email/web filters
4. Scan all inboxes for matching indicators
5. Open a case management ticket

SOAR reduces **mean time to respond** — average elapsed time from detection to containment — from hours to minutes for common incidents, freeing analysts for complex cases.

### Log sources and what each reveals

| Source | What it shows |
|---|---|
| **Firewall logs** | Permitted/denied connections; denied traffic reveals scanning and blocked attacks |
| **IDS/IPS alerts** — Intrusion Detection/Prevention System | Attack signatures, protocol anomalies, behavioral indicators |
| **DNS logs** — Domain Name System logs | C2 beaconing, DNS tunneling (unusual TXT/NULL queries), **DGA** — Domain Generation Algorithm — patterns seen as high NXDOMAIN responses |
| **Web proxy logs** | URLs, bytes transferred, user identity; C2 over HTTP/HTTPS, large downloads, cloud-storage uploads |

**Windows Event Log IDs** worth memorizing:

| Event ID | Meaning |
|---|---|
| 4624 | Successful logon (includes logon type, source IP) |
| 4625 | Failed logon — sequences indicate brute force |
| 4672 | Special privileges assigned — admin account authenticated |
| 4688 | Process creation with command line — catches Mimikatz, **LOLBAS** (Living Off the Land Binaries — abusing built-in Windows tools for malicious purposes) |
| 4648 | Explicit credential use — detects **pass-the-hash** (using a stolen password hash directly without cracking it) |

### Network monitoring

**NetFlow/IPFIX** — protocols that capture traffic *metadata* (IPs, ports, bytes, duration) without storing payload content — identify C2 beaconing, lateral movement, data exfiltration, and port scanning cheaply.

**Full packet capture** stores complete traffic content for retrospective forensic analysis, but is storage-intensive and typically deployed only at key **chokepoints** — network boundary points where all traffic must pass.

**NDR** — Network Detection and Response — platforms (e.g., Darktrace, ExtraHop, Vectra AI) apply machine learning to establish traffic baselines and detect anomalies that signature-based tools miss.

---

### UEBA — behavioral analytics

**UEBA** — User and Entity Behavior Analytics — builds a behavioral baseline for each user and system, then alerts on significant deviations.

- **Impossible travel**: account logs in from New York, then London 30 minutes later — physically impossible, signals compromise
- Unusual data access: a finance account reading engineering source code at 3 AM
- Unusual privilege use: a standard user account suddenly running admin tools

UEBA is especially valuable for **insider threats** — attackers with valid credentials who never trigger signature-based detection.

---

### High-priority threat patterns to monitor

| Threat | Key indicators |
|---|---|
| **Lateral movement** | WMI connections, **PsExec** (remote execution tool) usage, workstation-to-workstation SMB sessions, unexpected RDP |
| **Ransomware** | Mass file renames/extension changes, deletion of **Volume Shadow Copies** via `vssadmin` or `wmic` |
| **Data exfiltration** | Large outbound transfers, long DNS subdomains (tunneling), connections to unapproved cloud storage |
| **C2 beaconing** | Regular periodic connections with consistent byte size and interval — automated, not human |

### SNMP — device health monitoring

**SNMP** — Simple Network Management Protocol — lets a **Network Management Station** (NMS) poll **agents** on routers, switches, and servers for metrics stored in the **MIB** — Management Information Base, a structured database of device operational data organized by **OIDs** — Object Identifiers, unique numeric addresses for each metric.

- **SNMP trap** — an unsolicited alert the agent sends to the NMS the moment a condition is met (e.g., CPU > 95%), rather than waiting for the next polling cycle
- **SNMPv3** is the only acceptable version for production — earlier versions transmit **community strings** (shared passwords used to authenticate SNMP queries) in plaintext

> SNMP is like a building's sensor system: normally you check dashboards on a schedule, but a fire alarm (trap) calls you immediately without waiting.

---

### Recap

- **SIEM** aggregates and normalizes logs; **correlation rules** turn multi-source patterns into actionable alerts
- **SOAR** automates playbook responses, cutting mean time to respond from hours to minutes
- **Windows Event IDs 4624/4625/4672/4688/4648** are the key process and logon events for Windows attack detection
- **UEBA** detects insider threats and credential abuse through behavioral baselines; **impossible travel** is a classic example
- **SNMPv3** is required for secure device monitoring; earlier versions expose community strings in cleartext

### Exam flags

- Scenario asking which Event ID detects a specific attacker technique (process creation → 4688, pass-the-hash → 4648, brute force → 4624/4625 sequence)
- Scenario distinguishing SIEM (aggregation/correlation/alerting) from SOAR (automated playbook response)
- Question on why SNMPv1/v2 is insecure — community strings sent in cleartext
