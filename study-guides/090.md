## Web Filtering

Web filtering is the technical and policy framework that controls which websites and web content users can access from organizational networks and devices. It matters because it simultaneously enforces policy, blocks malware delivery, and stops communication with attacker infrastructure — all from a single control layer.

---

### URL filtering: the foundation

**URL filtering** is a technique that permits or blocks web requests by matching the requested URL or domain against a vendor-maintained database of categorized websites.

- The database groups millions of sites into categories: gambling, adult content, social media, malware distribution, phishing, **C2** (command-and-control — servers attackers use to send instructions to compromised machines), newly registered domains, and more.
- Admins set **category-level policies** (block gambling, allow productivity tools, monitor social media) rather than managing millions of individual entries.
- **Custom lists** override category decisions for specific sites.
- **Reputation scoring** assigns each domain a trustworthiness score based on behavior, hosting infrastructure, registration age, and threat intelligence — domains below a set threshold are blocked regardless of their category.

> Think of reputation scoring like a credit score for websites: even if a site claims to be a news outlet, a low score means it gets blocked at the door.

---

### DNS filtering: block before connection

**DNS filtering** blocks malicious domains at the **DNS resolution layer** — the step where a domain name is translated into an IP address — before any network connection is ever made.

- Returns either **NXDOMAIN** (domain doesn't exist) or a redirect to a block page.
- Simpler to deploy than proxy-based filtering — no traffic redirection required.
- Blocks malicious domains from *any* protocol (HTTP, HTTPS, custom malware protocols), not just web browsing.
- A **DNS sinkhole** returns a *false* IP for a malicious domain, directing the connection to a controlled internal server where it fails harmlessly and gets logged for investigation.

| Service | Type | Key trait |
|---|---|---|
| **Cisco Umbrella** | Cloud | Threat intelligence-enriched domain reputation |
| **Cloudflare Gateway** | Cloud | Integrated with Zero Trust platform |
| **Quad9** | Public DNS | Auto-blocks malicious domains for any user |
| **Pi-hole** | Open-source | Home/small network ad and tracker blocker |

> DNS filtering is like blocking a wrong address from ever being handed out — the delivery truck never leaves the depot.

---

### Proxy-based filtering: inspect every request

A **forward proxy** is a server positioned between users and the internet that intercepts every web request, applies security policies, and forwards or blocks the traffic.

- **Explicit proxy** — each browser/app is configured to send traffic to the proxy. Easy to set up via **Group Policy** (Windows domain-wide configuration tool) or **MDM** (Mobile Device Management — software that manages settings on employee devices). Easy to bypass by changing browser settings.
- **Transparent proxy** — redirects traffic at the network/firewall level with no client configuration needed and no user awareness. Harder to bypass because it requires no client cooperation.

> An explicit proxy is a toll booth you have to drive up to; a transparent proxy is a weight sensor built into the road — you pass through it whether you know it's there or not.

---

### SSL/TLS inspection: seeing inside encrypted traffic

**SSL/TLS inspection** (also called HTTPS inspection or SSL interception) decrypts, inspects, and re-encrypts HTTPS traffic at the proxy to enable security analysis of content that would otherwise be hidden.

- Without SSL inspection, the proxy sees only the *destination domain*, not the URL, request body, or response — the payload is fully encrypted.
- Works by performing a **man-in-the-middle** on the HTTPS session: the proxy presents a dynamically generated certificate to the browser signed by its own **CA** (Certificate Authority — an entity trusted to issue certificates), establishes a separate TLS session to the real server, and inspects decrypted traffic in between.
- The proxy's CA certificate must be installed in every client device's **trusted certificate store** — done via Group Policy (Windows) or MDM profiles (mobile).
- **Bypass rules** are common for banking, healthcare, and government sites to protect sensitive personal data.
- Users must be notified via the **AUP** that inspection is in place.

> SSL inspection is like a secure mail room that opens your letter, scans it for contraband, reseals it in an identical envelope, and sends it on — the recipient never knows the difference.

### Acceptable Use Policy

The **AUP** (Acceptable Use Policy) is the foundational policy document defining what web usage is permitted and prohibited. Web filtering technically *enforces* what the AUP defines in writing.

| Treatment | Typical categories |
|---|---|
| **Blocked** | Adult content, gambling, hacking tools, malware/phishing sites, P2P file sharing |
| **Allowed** | Business apps, reference, news, educational content |
| **Monitored** | Social media (logged, reported, not blocked) |

- **Time-based policies** apply different rules during working hours vs. after hours.
- **Role-based policies** give IT security staff access to hacking tool and malware analysis sites that are blocked for standard users.

---

### Safe search enforcement

**Safe search enforcement** forces search engines to apply their strictest content filters for all network users, even if a user tries to disable safe search manually.

- DNS-based method: DNS lookups for `google.com` are redirected to `forcesafesearch.google.com`; `bing.com` lookups go to `strict.bing.com`.
- These endpoints activate the search engine's maximum content filtering settings network-wide.

---

### Download controls

**Download controls** restrict which file types users can download from the internet, reducing malware delivery risk.

- Common blocked executables for standard users: `.exe`, `.msi`, `.bat`, `.ps1` (PowerShell script), `.scr`.
- Files that pass type checks can be scanned by antivirus at the proxy.
- Suspicious files may be submitted to a **cloud sandbox** — an isolated environment that executes the file and reports behavioral indicators of malicious activity before delivery or blocking.

---

### Agent-based filtering: off-network devices

**Agent-based web filtering** installs a lightweight client on each endpoint device that enforces URL filtering and security policies locally, regardless of which network the device is on.

- Solves the problem of remote/home workers whose traffic never touches the corporate proxy or firewall.
- The agent routes filtered traffic through a **cloud-based security service** via a lightweight tunnel — no full corporate VPN required.
- Must receive continuous updates (URL categories, threat intelligence) via a management platform.

> The agent is like a security guard who travels with the employee — the guard's rules apply whether you're in the office, a coffee shop, or home.

---

### CASB: controlling cloud app access

A **CASB** (Cloud Access Security Broker) is a specialized control that extends web filtering to cloud application usage, addressing the problem of **shadow IT** — employees using unauthorized cloud services that bypass organizational security and data governance.

- **Discovery mode**: analyzes network traffic logs to inventory all cloud services in use, showing data volumes, risk posture, and compliance certifications for each.
- For *permitted* services: enforces **DLP** (Data Loss Prevention — policies that detect and block uploads of sensitive data like intellectual property or regulated customer info) directly on cloud traffic.
- Sits inline in the traffic path or analyzes logs — both modes are valid.

> Think of a CASB as an auditor who reviews every cloud app employees have signed up for and flags the ones that handle your data without your knowledge.

---

### Bypass attempts and countermeasures

Users may attempt to circumvent web filtering using personal VPN services that route traffic outside the corporate proxy.

- Firewalls can block common **VPN** ports and destinations — but sophisticated VPN services may disguise traffic as normal HTTPS.
- On mobile devices, users may switch to cellular data to bypass Wi-Fi-based filtering entirely.
- **MDM-enforced always-on VPN** configurations — which apply to all data interfaces and prevent device use when VPN is inactive — provide the most comprehensive filtering coverage for managed mobile devices.

---

### Recap

- **URL filtering** uses a category + reputation database; **DNS filtering** blocks at resolution before any connection; **proxy-based filtering** inspects every request in transit.
- **SSL/TLS inspection** requires deploying the proxy CA certificate to all clients; without it, encrypted payload content is invisible.
- The **AUP** is the policy source; web filtering is its technical enforcement — blocking, allowing, and monitoring map directly to AUP categories.
- **Agent-based filtering** maintains policy enforcement for off-network devices via a cloud security tunnel.
- A **CASB** discovers shadow IT and enforces DLP on permitted cloud services.

### Exam flags

- **SSL/TLS inspection mechanism** — how the proxy performs MITM, the role of the proxy CA, and why the CA cert must be distributed to clients.
- **DNS filtering vs. proxy-based filtering** — when each applies, and that DNS filtering blocks *all protocols*, not just web traffic.
- **CASB and shadow IT** — what a CASB discovers, how it enforces DLP, and what problem it solves.
