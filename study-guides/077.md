## Hardening Targets (Domain 4)

Hardening means deliberately configuring systems to be more secure than their factory defaults — because defaults optimize for ease, not security. This lesson covers how that process differs across eight distinct target types you'll see on the exam.

---

### Mobile device hardening

**Mobile Device Management (MDM)** — software that lets an organization push and enforce security policies on employee smartphones and tablets — is the foundation of everything else here. Without MDM enrollment, IT has no way to verify or control device security.

Key policies delivered through MDM:

- **Full-device encryption** — both iOS and Android support it natively, but MDM must enforce it
- **Screen lock with PIN or biometric + auto-lock timeout** — protects lost/stolen devices
- **Remote wipe** — IT erases corporate data when a device is reported missing
- **ADB (Android Debug Bridge) / developer mode** — must be disabled; these bypass production security controls and allow unauthorized code execution
- **Sideloading** — installing apps from outside the official app store (iOS supervised mode blocks this entirely; MDM disables "unknown sources" on Android)
- **Geofencing** — restricts device features (e.g., disables camera) based on geographic location
- **Per-app VPN** — MDM pushes a configuration that routes only corporate apps through an encrypted tunnel on untrusted networks
- **Bluetooth / NFC** — disable when not in use; both are short-range wireless attack surfaces

> Think of MDM like a remote control for a rental car fleet — you can lock doors, check locations, and cut the engine from headquarters, even though drivers are scattered everywhere.

### Workstation hardening

The biggest single win: **remove local administrator rights** from standard user accounts. Most malware succeeds by running in the context of an admin-privileged user — strip that privilege and malware cannot install software, modify system files, or disable security tools. Use a separate admin account only when elevation is genuinely needed.

Other key controls:

- **EDR (Endpoint Detection and Response)** — security software that monitors workstation behavior in real time and logs activity for forensic investigation. Unlike traditional antivirus — which only matches files against known signatures at execution time and keeps no behavior history — EDR can detect novel threats and let analysts look back at exactly what happened.
- **Host-based firewall** — set to default-deny; only explicitly required connections are permitted
- **BitLocker** (Windows) / **FileVault** (macOS) — full-disk encryption protecting data on lost or stolen laptops
- **USB port lockdown** — removable storage is a common malware introduction and data exfiltration vector
- **WDAC (Windows Defender Application Control)** / **AppLocker** — **application allowlisting** tools that permit only pre-approved executables to run, blocking unauthorized software regardless of delivery method
- **PowerShell Constrained Language Mode** — limits what PowerShell scripts can do, reducing script-based attack effectiveness
- **Secure Boot** — a **UEFI** (firmware interface that initializes hardware before the OS loads) feature that verifies the OS bootloader is signed and trusted, preventing **bootkit** malware from loading before the OS

> Removing admin rights is like taking the master key off the janitor's ring — they can still clean, but they can't open the vault.

### Switch hardening

**Switches** are the Layer 2 devices that connect devices within a local network. Their defaults create several exploitable conditions.

| Control | What it prevents |
|---|---|
| Change native VLAN away from **VLAN 1** | **VLAN hopping** — exploiting default VLAN to jump between network segments |
| Disable unused ports + assign to parking VLAN | Unauthorized plug-in access |
| **Port security** — limit MACs per port | Damage from unauthorized device connections |
| **DHCP snooping** — trust table of legit DHCP servers | Rogue DHCP servers handing out false IP config |
| **Dynamic ARP Inspection (DAI)** — validates ARP using snooping table | **ARP poisoning** — attacker maps their MAC to a legitimate IP to intercept traffic |
| **BPDU Guard** on access ports | Attacker connecting a rogue switch to hijack Spanning Tree root and control Layer 2 topology |
| Disable **CDP (Cisco Discovery Protocol)** on user-facing ports | Reconnaissance — CDP leaks platform version and capabilities |
| Disable **DTP (Dynamic Trunking Protocol)** on access ports | VLAN hopping via negotiated trunk links |
| **SNMPv3** with auth + encryption | Replaces older SNMP that sent **community strings** (shared passwords) in cleartext |
| Disable **Telnet**; use **SSH** | Telnet sends all management traffic including passwords in cleartext |

> A switch's defaults are like a hotel where every door defaults to unlocked — hardening means locking each one that doesn't need to be open.

### Router hardening

**Routers** make Layer 3 (IP-level) forwarding decisions and often sit at network boundaries — making them high-value targets.

- **IP directed broadcasts** — disabled; prevents **smurf amplification attacks** where one packet triggers broadcast responses from all hosts on a subnet
- **ICMP redirects** — disabled; attackers use them to manipulate a host's routing decisions and redirect traffic through an attacker-controlled path
- **Proxy ARP** — disabled unless required; causes the router to answer ARP requests for devices on other subnets, enabling man-in-the-middle attacks
- **Ingress/egress ACLs (Access Control Lists)** — filter rules that block traffic with spoofed source IP addresses from entering or leaving the network
- **Routing protocol authentication** — dynamic routing protocols like **OSPF** must use MD5 or SHA authentication so routers verify update sources and prevent **route injection** (attacker inserts false routes to redirect traffic)
- Restrict management access to specific trusted source IPs (ideally a dedicated management network)
- Configure a **login banner** giving legal notice that unauthorized access is prohibited

> Hardening a router is like securing the border crossing — you check credentials on every lane, block forged plates, and shut down unused checkpoints entirely.

### Cloud infrastructure hardening

Cloud environments have all the attack surface of traditional infrastructure plus the risk of misconfiguration being instantly internet-exposed. **CIS Benchmarks** — detailed hardening guides published by the Center for Internet Security — exist for AWS, Azure, and GCP and are the starting reference.

| Control | Detail |
|---|---|
| **CloudTrail** (AWS) / **Azure Monitor** | Audit logs of all API calls and config changes — must be enabled |
| **AWS GuardDuty** / **Microsoft Defender for Cloud** | Threat detection services that analyze logs for indicators of compromise |
| Security groups / **NSGs (Network Security Groups)** | Firewall rules for cloud resources; never allow port 22 (SSH) or 3389 (RDP) from **0.0.0.0/0** (the entire internet) |
| **MFA (Multi-Factor Authentication)** | Required for all accounts, especially root/global admin |
| **S3 Block Public Access** | Prevents AWS storage buckets from being accidentally exposed publicly |
| **VPC Flow Logs** | Capture network traffic metadata for monitoring and forensics |
| **IAM roles with temporary credentials** | Preferred over long-lived access keys, which should be rotated regularly |
| **AWS Config / Azure Policy** | Continuous automated compliance checking against security standards |

> Exposing SSH to 0.0.0.0/0 in a cloud security group is like leaving the front door of your data center propped open on the internet — anyone can walk up and try the handle.

### Server hardening

- Servers run under **minimally privileged service accounts** — not high-privilege system accounts — unless the application specifically requires it
- Remove unnecessary **server roles and features** (e.g., a web server doesn't need the print spooler)
- Disable services not required for the server's function
- **NTP (Network Time Protocol)** — the protocol that synchronizes clocks across systems; accurate time is critical for **Kerberos** authentication (which fails if clocks are too far apart), log correlation, and forensic timelines
- **Windows Defender Credential Guard** — isolates **NTLM hashes** (Windows credential tokens) and **Kerberos tickets** inside a virtualization-based security container, preventing tools like **Mimikatz** (a credential-extraction tool) from pulling them out of memory
- Linux mount options: **noexec** prevents binaries from executing off a mounted filesystem; **nosuid** prevents **setuid programs** (programs configured to run with elevated privileges) from doing so when launched from that filesystem

> Credential Guard is like keeping the master password list inside a locked safe within the server room — even if attackers get into the server room, they still can't crack open the safe.

### ICS/SCADA hardening

**ICS (Industrial Control Systems)** and **SCADA (Supervisory Control and Data Acquisition)** systems — software and hardware that monitor and control physical industrial processes like power grids, water treatment, and manufacturing — prioritize availability above all. They often run proprietary or legacy operating systems that cannot be patched without halting production, so **compensating controls** (alternative safeguards used when primary controls can't be applied) are essential.

- **OT DMZ (Operational Technology DMZ)** — a network segment that separates ICS networks from corporate IT networks, limiting damage if IT is compromised. (**DMZ** — demilitarized zone — a network buffer zone that limits direct access between two trust domains)
- **Unidirectional security gateways / data diodes** — hardware that enforces one-way data flow from OT to IT, making it physically impossible for an attacker on the IT network to send commands back into OT systems
- Application allowlisting configured for control-system-specific applications
- USB port lockdown — primary malware introduction vector
- **Dragos / Claroty** — specialized OT monitoring platforms that analyze OT protocols and detect anomalous device behavior without requiring agents on fragile embedded systems

> A data diode is like a one-way mirror in an interrogation room — the OT side can be observed from the IT side, but nothing from IT can reach through and touch the controls.

---

### IoT hardening

**IoT (Internet of Things)** devices — smart cameras, sensors, building automation systems, and network-connected physical controls — ship with notoriously weak defaults and often have no mechanism for updates.

- **Change default credentials immediately** — IoT devices frequently ship with identical factory usernames and passwords, and attackers scan for them at scale
- Isolate IoT devices on a **dedicated VLAN** with no path to corporate systems
- Disable unused services and interfaces
- Keep firmware updated whenever the vendor releases patches
- Where possible, place IoT devices behind a firewall that restricts their outbound communication to only required destinations

> IoT defaults are like every lock in a neighborhood using the same key that came in the box — until you rekey them, anyone with the original key can walk right in.

---

### Recap

- **MDM enrollment** is the prerequisite for enforcing all other mobile policies; without it, the org has no visibility or control
- Removing **local admin rights** is the single highest-impact workstation hardening measure because most malware depends on that privilege to execute fully
- Switch attacks — VLAN hopping, ARP poisoning, rogue DHCP, rogue root bridge — each have a specific named control (change native VLAN, DAI, DHCP snooping, BPDU Guard)
- ICS/SCADA cannot always be patched; compensating controls (OT DMZ, data diodes, allowlisting) are the primary defenses
- Cloud misconfiguration #1: opening SSH (22) or RDP (3389) to **0.0.
