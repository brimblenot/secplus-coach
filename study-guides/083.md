## Threat Intelligence (ID: 083, Domain 4)

Threat intelligence turns raw data into actionable knowledge about attackers — who they are, how they operate, and how to stop them. This lesson covers the sources, sharing mechanisms, formats, indicators, frameworks, and hunting techniques that make up the threat intelligence lifecycle.

---

### Raw data vs. threat intelligence

**Threat intelligence** is processed, analyzed information about threats and threat actors that enables informed security decisions — not just a list of facts, but context that tells you *what to do*.

- A list of IP addresses = raw data
- Knowing those IPs are C2 servers run by a ransomware group targeting hospitals, including their preferred entry vectors = **intelligence**
- Used by: analysts (SIEM triage), architects (control investment), vuln teams (patching priority), incident responders (attacker behavior)

> Think of it like the difference between a police scanner log and a detective's case file — same raw events, but the case file tells you who did it and how.

---

### OSINT sources

**OSINT** — Open Source Intelligence — is threat intelligence gathered from publicly available sources with no special access required.

| Source type | Examples |
|---|---|
| Threat feeds | Malicious IP/domain/hash lists from honeypots, sinkholes, malware analysis |
| Security blogs/research | Krebs on Security, SANS ISC, CrowdStrike, Unit 42, Mandiant |
| Government advisories | **CISA** (Cybersecurity and Infrastructure Security Agency) alerts, **FBI Flash** reports, NSA advisories |
| Social/dark web | Twitter researcher communities, Pastebin paste sites, dark web forums |
| Code repositories | GitHub PoC exploit code post-disclosure |
| Malware sandboxes | **VirusTotal**, **any.run** — behavioral indicators from submitted samples |
| Domain/IP investigation | **WHOIS** and passive DNS — domain registration history and infrastructure mapping |

> OSINT is like an investigative journalist's toolkit — everything is public, but knowing where to look and how to connect the dots is the skill.

### Threat intelligence sharing organizations

**ISACs** — Information Sharing and Analysis Centers — are sector-specific nonprofits where peer organizations share threat intelligence under agreed confidentiality terms and receive curated, sector-relevant intelligence in return.

| ISAC | Sector |
|---|---|
| **FS-ISAC** | Financial services / banking |
| **H-ISAC** | Healthcare |
| **MS-ISAC** | State, local, tribal, territorial governments (CISA-sponsored) |
| **E-ISAC** | Electric power |

**ISAOs** — Information Sharing and Analysis Organizations — were created by executive order as a flexible alternative: any group of organizations can form a sharing community regardless of industry sector.

> An ISAC is like a neighborhood watch program for a specific street — healthcare organizations only. An ISAO is a watch program anyone on any street can start.

### Standard formats: STIX and TAXII

**STIX** — Structured Threat Information eXpression — is a standardized language for describing threat intelligence objects: IoCs, malware, threat actor profiles, attack patterns, campaigns, and relationships between them.

- A STIX bundle can link a threat actor → campaign → malware → specific file hashes and domains → mapped MITRE ATT&CK techniques

**TAXII** — Trusted Automated eXchange of Intelligence Information — is the transport protocol that moves STIX data between organizations, using a **REST API** (a web-based request/response interface) model with servers hosting intelligence collections that clients subscribe to.

- Together: automated, machine-readable sharing that plugs directly into security tools

> STIX is the language; TAXII is the postal service. You write the threat report in STIX, then TAXII delivers it automatically to every subscriber.

### Indicators of Compromise (IoCs)

**IoCs** — Indicators of Compromise — are observable artifacts that signal a system may be compromised or an attack is underway. They are used to block or detect known-bad activity.

| IoC type | Where it's applied |
|---|---|
| IP addresses | Firewall / proxy blocklists |
| Domain names | DNS filtering |
| URLs | Web proxy blocking |
| File hashes (MD5, SHA-256) | Endpoint security, file analysis |
| Email subject lines / sender addresses | Email security gateways |
| **YARA rules** | Pattern-matching expressions that identify malware by byte sequences, strings, or structural traits — detect malware *families* even when individual hashes change due to packing or obfuscation |

> An IP blocklist is like a bouncer with a no-fly list — effective until the attacker gets a new ID. A YARA rule is like recognizing someone by how they walk, not their face.

---

### TTPs vs. IoCs

**TTPs** — Tactics, Techniques, and Procedures — describe *how* threat actors behave: initial access methods, post-exploitation tools, lateral movement, exfiltration patterns.

- IoCs (IPs, domains) are **easily changed** — a blocked C2 domain just gets replaced with a new one
- TTPs require attackers to **develop new capabilities** to change — making TTP-based detection far more durable
- TTP-based defense focuses on *behaviors*, not artifacts

> IoCs are like changing your phone number to dodge calls. TTPs are like your speech patterns, your handwriting, your habits — much harder to change.

---

### MITRE ATT&CK framework

The **MITRE ATT&CK framework** — ATT&CK stands for Adversarial Tactics, Techniques, and Common Knowledge — is a publicly available matrix of adversary TTPs organized by the attacker's objective at each stage.

**Tactics** (the "why" / objective at each stage):

| Tactic | What the attacker is doing |
|---|---|
| Initial Access | Getting first foothold (phishing, exploiting public apps, supply chain) |
| Execution | Running attacker code (PowerShell, WMI, scheduled tasks) |
| Persistence | Surviving reboots (registry run keys, backdoor accounts) |
| Privilege Escalation | Gaining higher access (vuln exploits, token impersonation, sudo abuse) |
| Defense Evasion | Avoiding detection (disabling tools, timestomping, process injection, obfuscation) |
| Credential Access | Stealing credentials (keylogging, LSASS dump, Kerberoasting, phishing) |
| Discovery | Learning the environment (network scanning, account enumeration) |
| Lateral Movement | Moving system to system (pass-the-hash, RDP, SMB) |
| Collection | Gathering target data (screen capture, network shares) |
| Command & Control | Communicating with implants (web protocols, DNS tunneling, cloud services) |
| Exfiltration | Moving data out (compressed/encrypted, cloud storage) |
| Impact | Achieving objectives (ransomware, data destruction, service disruption) |

> ATT&CK is like a playbook scouted from watching hundreds of real attackers — defenders study it the same way a defensive coordinator studies an opposing team's tendencies.

### Threat hunting

**Threat hunting** is the proactive practice of searching an organization's environment for threats that have already evaded automated detection — it is human-led, hypothesis-driven investigation, not waiting for an alert.

Two approaches:
- **Hypothesis-based**: Start from threat intelligence ("this actor uses Base64-encoded PowerShell for lateral movement") → search SIEM logs, **EDR** (Endpoint Detection and Response — security software that records detailed endpoint activity and behavior) telemetry, and network traffic for that specific behavior
- **Baseline anomaly**: Establish what "normal" looks like, then hunt for deviations — a user accessing systems they never have, a process making new network connections, a service communicating externally on an unusual port

> Hypothesis-based hunting is like a detective working a tip. Baseline anomaly hunting is like a bank noticing an account that suddenly wires money to three countries it's never touched.

### Vulnerability intelligence

**Vulnerability intelligence** connects threat intelligence to patching by identifying which CVEs — **CVEs** are Common Vulnerabilities and Exposures, the standard numbered identifiers for known software flaws — are actively exploited in real attacks, not just theoretically dangerous.

- **CISA Known Exploited Vulnerabilities catalog**: a maintained list of CVEs confirmed actively exploited in the wild — organizations should treat these as highest-priority patches
- Threat feeds can flag when a new vulnerability appears in exploit frameworks or is attributed to a ransomware group, enabling patching *before* widespread exploitation begins

> The KEV catalog is like the CDC's list of diseases with confirmed community spread — theoretical risk is one thing, but confirmed active cases change your response priority entirely.

---

### Recap

- **Threat intelligence = data + context + analysis**; raw IoCs become actionable only when you know the who, why, and how
- **ISACs** are sector-specific sharing communities; **ISAOs** are the flexible, any-sector alternative
- **STIX** describes intelligence in a standard format; **TAXII** transports it between organizations automatically
- **TTPs are more durable than IoCs** for defense — attackers can swap IPs and domains in minutes, but changing how they operate takes real effort
- **MITRE ATT&CK** maps adversary behavior across 12 tactics from Initial Access through Impact

---

### Exam flags

- **STIX vs. TAXII distinction** — expect a question that tests whether you know STIX is the *format/language* and TAXII is the *transport mechanism*, not interchangeable
- **TTPs vs. IoCs durability** — high likelihood of a scenario question asking which type of indicator is harder for an attacker to change and therefore provides more long-term defensive value
- **ISAC vs. ISAO** — know that ISACs are sector-specific and ISAOs are the flexible executive-order alternative open to any group of organizations
