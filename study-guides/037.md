## Misconfiguration Vulnerabilities

Misconfigurations aren't bugs in code — they're errors in how software is *set up and maintained*. They're among the most common breach causes, and many are trivially easy to exploit with free scanning tools. This lesson covers every misconfiguration category the Security+ exam tests.

---

### Default credentials

**Default credentials** are the factory-set usernames and passwords (e.g., `admin/admin`, `root/root`, blank passwords) that manufacturers ship on routers, cameras, printers, IoT devices, and embedded systems for initial setup convenience.

- **Shodan** and **Censys** — search engines that index internet-connected devices — let attackers filter for specific device types and test known defaults at scale
- The **Mirai botnet** (2016) used 60+ default credential pairs to compromise millions of IoT devices, then launched record-breaking **DDoS** — **Distributed Denial-of-Service** — attacks, including taking down major DNS infrastructure
- Defenses: force credential change during setup wizard, scan your own network for defaults, use **network segmentation** — isolating device groups so a compromised IoT device can't reach sensitive internal systems

> *Think of default credentials like a master key that every hotel guest gets — useful on day one, catastrophic if nobody ever changes the lock.*

---

### Open permissions

**Open permissions** — also called excessive permissions — occur when users, applications, or groups are granted more access than their job requires, violating the **principle of least privilege** (access only to what is needed, nothing more).

- World-readable file shares, the Windows **Everyone group** with write access, overly permissive **ACLs** (Access Control Lists — rules defining who can read/write/execute a resource), and public cloud storage buckets are common examples
- Database accounts for applications should have **SELECT** (read-only query) access on specific tables only — never admin or **DDL** (Data Definition Language — commands that create or alter database structure) rights
- Defense: periodic **access reviews** to find and revoke permissions that accumulated beyond original need

> *Like a new employee who gets the master keycard "temporarily" — then nobody revokes it when the project ends.*

---

### Unsecured APIs

An **API** (Application Programming Interface — a set of endpoints that let software talk to software) is unsecured when it lacks proper authentication or access controls.

- **No authentication**: anonymous callers can invoke any endpoint freely
- **Broken access control** (also called **insecure direct object reference**): a predictable ID in a URL (e.g., `/customer/1042`) can be changed to `/customer/1043` to access another user's data
- **Over-fetching**: the API returns full objects when only a few fields are needed, exposing sensitive data the app never displays
- **Verbose error messages**: stack traces, SQL queries, internal IPs, and file paths in error responses hand attackers free reconnaissance

> *An unsecured API is like a bank drive-through with no teller — anyone who pulls up can ask for any account balance.*

### Unnecessary open ports and services

Every open, reachable port is an attack surface. Some ports are especially dangerous when internet-facing:

| Port | Service | Risk |
|------|---------|------|
| 3306 | **MySQL** — a popular relational database | Should only accept internal app-server connections |
| 5432 | **PostgreSQL** — another relational database | Same — never internet-facing |
| 6379 | **Redis** — an in-memory data store | Shipped with *no auth* by default; any internet instance was open |
| 9200 | **Elasticsearch** — a search/analytics platform | Same no-auth-by-default history |
| 3389 | **RDP** — Remote Desktop Protocol, Windows remote GUI access | Repeatedly exploited in breaches |
| 22 | **SSH** — Secure Shell, encrypted remote command-line access | Safer than Telnet but still probe-targeted |
| 5900 | **VNC** — Virtual Network Computing, remote desktop | Exploited when internet-exposed |
| 23 | **Telnet** — remote command-line access that transmits *everything*, including passwords, in **cleartext** (unencrypted, readable by anyone intercepting the traffic) | Replace with SSH |

**Unnecessary services** are equally dangerous even when ports aren't externally reachable:

- **Windows Print Spooler** — a background service managing print jobs — running on **domain controllers** (servers that authenticate all users in a Windows network) enabled the **PrintNightmare** vulnerability family, allowing **privilege escalation** (gaining higher permissions than authorized) across enterprise networks
- **SMBv1** — Server Message Block version 1, an ancient file-sharing protocol — was exploited by **EternalBlue**, the exploit behind both **WannaCry** and **NotPetya** ransomware attacks, yet stayed enabled by default long after Microsoft shipped a secure replacement
- **FTP** — File Transfer Protocol, cleartext file transfer — should be replaced by **SFTP** (SSH File Transfer Protocol — encrypted file transfer)
- **SNMPv1/v2** — Simple Network Management Protocol versions 1 and 2, used to monitor and manage network devices — transmit **community strings** (passwords used by SNMP to authenticate queries) in cleartext; replace with **SNMPv3**, which adds real authentication and encryption

> *Running unnecessary services is like leaving a dozen unlocked side doors on a building just because you only use the front entrance.*

Defense: regular **port scanning** of your own perimeter catches unexpected open ports before attackers do. Minimizing running services is called **attack surface reduction**.

### Misconfigured firewalls

A **firewall** controls which network traffic is allowed or blocked. Misconfigurations include:

- **Overly permissive rules**: allowing any source to any destination on any port defeats the firewall's purpose
- **Stale temporary rules**: rules added during troubleshooting that are never removed become permanent exposures
- **No default-deny posture**: a firewall that allows anything not *explicitly blocked* is hard to reason about — correct posture is deny-all, allow-by-exception
- **Missing egress filtering**: without outbound traffic controls, malware on a compromised internal host can freely phone home to a **C2** (Command-and-Control — the attacker's server that issues instructions to compromised machines) and exfiltrate data undetected

> *A firewall with no default-deny is like a nightclub bouncer who lets everyone in unless they're on a "banned" list — you can't possibly ban everyone dangerous in advance.*

### Debug mode in production

**Debug mode** is an application framework setting designed for development that generates verbose error output — full stack traces, database query text, local variable values, file paths, and sometimes source code — exposed directly in HTTP responses when an error occurs.

- Framework developers intend this *only* for development environments where developers need it
- In production, every unhandled exception hands an attacker free reconnaissance
- Defense: always disable debug mode before deploying to production

> *Running debug mode in production is like doing a bank robbery rehearsal with the vault open and real customers watching.*

---

### Missing security headers

**HTTP security headers** are fields in a web server's response that instruct browsers to enforce protective behaviors. Missing them leaves browsers open to several attack classes:

| Header | What it does |
|--------|-------------|
| **HTTP Strict Transport Security (HSTS)** | Forces the browser to use HTTPS for all future visits, blocking protocol downgrade attacks |
| **Content Security Policy (CSP)** | Restricts which scripts and resources the browser will load, blocking **XSS** (Cross-Site Scripting — injecting malicious scripts into a page) |
| **X-Frame-Options** | Prevents the page from being loaded inside a frame on another domain, blocking **clickjacking** (overlaying an invisible frame on a legitimate page to hijack clicks) |
| **X-Content-Type-Options** | Stops **MIME sniffing** (browser guessing a file's type from content rather than declared type), preventing uploaded files from being executed as scripts |
| **Referrer-Policy** | Controls what URL information is sent in outbound requests, preventing leakage of internal URLs and session tokens |

### SSL/TLS misconfigurations

**SSL** (Secure Sockets Layer — the now-deprecated predecessor to TLS) and **TLS** (Transport Layer Security — the current standard protocol for encrypting network communications) protect data in transit, but only when configured correctly.

- Supporting **SSL 3.0**, **TLS 1.0**, or **TLS 1.1** exposes connections to known attacks against those deprecated versions
- Weak **cipher suites** — the specific algorithms used inside a TLS session to encrypt data — like **RC4**, **DES**, or export-grade ciphers provide inadequate confidentiality
- **Self-signed certificates** — TLS certificates not issued by a trusted **CA** (Certificate Authority — a third party that verifies server identity and vouches for certificates) — prevent browsers from verifying server identity and train users to click through warnings, making them ignore genuine attacks
- Not redirecting **HTTP** (unencrypted web traffic) to **HTTPS** (HTTP protected by TLS) means the user's first request travels unencrypted and can be intercepted before the redirect

> *Leaving TLS 1.0 enabled is like putting a deadbolt on your door but leaving the old broken lock in place — attackers will just pick the weaker one.*

### Configuration baselines and defenses

A **security configuration baseline** is a documented, tested set of approved settings for a given technology — the known-good starting point.

- **CIS Benchmarks** — Center for Internet Security Benchmarks, detailed configuration guides published by a non-profit security organization — and **DISA STIGs** — Defense Information Systems Agency Security Technical Implementation Guides, similar guidance used by the U.S. military — are the two major sources
- Automated **configuration scanning tools** compare live systems against baselines and report deviations continuously
- **Infrastructure as code** — defining infrastructure in version-controlled configuration files rather than manual steps — combined with security scanning in **CI/CD pipelines** (Continuous Integration/Continuous Delivery — automated build, test, and deploy workflows) catches misconfigurations before deployment
- **Change management** processes requiring security review of configuration changes prevent accidental exposures from reaching production

---

### Recap

- Misconfigurations are deployment/setup errors, not code bugs — scanning tools make them easy to find and exploit
- Default credentials, open permissions, and unnecessary open ports/services all violate the same core principle: minimize access and attack surface
- Debug mode, verbose API errors, and missing security headers all hand attackers free reconnaissance
- Deprecated protocols (SSL, TLS 1.0/1.1, SMBv1, SNMPv1/v2, Telnet, FTP) should be disabled and replaced with secure equivalents
- CIS Benchmarks and DISA STIGs provide the configuration baselines; automated scanning verifies compliance

### Exam flags

- **Scenario: a tool is described that finds internet-connected devices still using factory passwords** → Shodan or Censys; the control is mandatory credential change + network segmentation
- **Scenario: an application framework exposes stack traces and SQL queries on errors** → debug mode left enabled in production; disable before deployment
- **Scenario: a firewall allows all outbound traffic** → missing egress filtering; enables C2 callbacks and data exfiltration
