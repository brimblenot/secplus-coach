Identity and Access Management, commonly abbreviated IAM, encompasses the policies, processes, and technologies that manage digital identities and control access to organizational resources. IAM has become foundational to modern security architecture, particularly as cloud computing and remote work have expanded the perimeter beyond the traditional enterprise network boundary. When users access resources from any device, from any location, the question of who is allowed to do what can only be answered by a robust identity framework. IAM is not a single product but a discipline spanning provisioning, authentication, authorization, federation, governance, and lifecycle management.

The identity lifecycle describes the complete journey of a digital identity from creation through retirement. The joiner process, also called provisioning, occurs when a new user joins the organization or when an existing user changes roles. The goal is to create the user account with the appropriate attributes and grant access to the resources required for the new role, nothing more and nothing less. In mature organizations, provisioning is triggered automatically by the HR system when a new hire is recorded or a role change is made, and the access granted is determined by the user's role, department, and job title rather than by manual requests. The mover process handles modifications during the user's tenure, updating access when the user's role changes. The critical security discipline here is ensuring that access from the previous role is removed while access for the new role is granted, a process sometimes called access modification or the mover workflow. Failing to remove old access during role changes leads to accumulation of excess privileges over time, a phenomenon called privilege creep. The leaver process handles deprovisioning when the user leaves the organization. This is arguably the most security-critical phase of the lifecycle: accounts belonging to former employees must be disabled on the last day of employment, and ideally accounts should be pre-staged for disablement so they can be turned off immediately when the user's access ends. Orphaned accounts, belonging to users who have departed but whose accounts remain active, represent a significant security risk as they may be accessed by the former employee or by attackers who compromise the credentials.

Just-in-Time provisioning, or JIT provisioning, extends the lifecycle principle to access grants themselves. Rather than permanently provisioning access to sensitive resources, JIT provisioning creates temporary access on demand and revokes it automatically when the task requiring the access is complete. A technician who needs administrative access to a production server for a specific maintenance task receives elevated credentials that expire after a defined time window, eliminating the standing privileged access that would otherwise exist and represent an ongoing compromise risk. JIT provisioning is enabled by automated systems that integrate with HR event triggers and can be implemented using SCIM, the System for Cross-domain Identity Management, a standard protocol for automating account lifecycle management between identity providers and applications.

User identity governance encompasses the controls that ensure access remains appropriate over time. Access recertification campaigns, also called access reviews or certification campaigns, are periodic processes in which managers review and certify that their subordinates' current access is appropriate for their job function. Any access that is not actively certified during the review is revoked. Recertification campaigns are required by compliance frameworks including Sarbanes-Oxley for financial systems. Separation of duties enforcement through IAM systems ensures that users cannot hold combinations of permissions that would allow them to commit fraud without a second person's involvement — for example, a user who can enter payments should not also have the ability to approve payments. Toxic combination detection identifies and alerts on these dangerous permission combinations automatically.

Privileged Identity Management, or PIM, and Privileged Access Management, or PAM, provide specialized controls for administrative accounts because these accounts carry dramatically elevated risk. The core principles of PAM are just-in-time privileged access, session recording, and password vaulting. Just-in-time privileged access means that users do not have standing administrative access; instead they request elevation for a specific task, an approval workflow grants temporary access, and the access is automatically revoked when the time window expires. Session recording captures a full video and keystroke record of all privileged sessions, creating an audit trail that supports forensic investigation and deters insider abuse. Password vaulting stores the actual credentials for privileged accounts in an encrypted vault system; users never see the actual password. Instead, the PAM solution checks out credentials on behalf of the user for the duration of the session and automatically rotates the password after use, ensuring that even the administrator who just used the account cannot reuse the credentials. Leading PAM vendors include CyberArk, BeyondTrust, and Delinea.

Single Sign-On, or SSO, allows a user to authenticate once and then access multiple applications without re-authenticating for each one. The user presents credentials to a central identity provider, receives an authentication token, and presents that token to each application they subsequently access. SSO dramatically improves the user experience by eliminating the need to manage separate credentials for each application and reduces the help desk burden from password reset requests. From a security perspective, SSO centralizes access revocation: disabling a user's SSO account immediately revokes access to all connected applications simultaneously. However, SSO also centralizes risk: an attacker who compromises an SSO credential gains access to all applications connected to that SSO. This makes multi-factor authentication on the SSO identity provider absolutely critical.

Federation extends the SSO concept across organizational boundaries, allowing users to authenticate with their home organization's identity provider and receive access to resources in partner organizations or cloud services without creating separate accounts in each location. SAML 2.0, the Security Assertion Markup Language, is the dominant standard for enterprise federation. In the SAML model, the Identity Provider, or IdP, is the authoritative source for the user's identity and performs authentication. The Service Provider, or SP, is the application or service the user is trying to access, and it trusts the IdP to authenticate users. When a user attempts to access the SP without an active session, they are redirected to the IdP, where they authenticate. The IdP then generates a digitally signed SAML assertion containing claims about the user's identity and attributes and sends it back to the SP. The SP validates the signature using the IdP's public certificate and grants access based on the claims in the assertion. SAML 2.0 is widely used for enterprise SSO to SaaS applications.

OAuth 2.0 is an authorization framework rather than an authentication protocol. Its purpose is to allow a user to grant a third-party application limited access to resources in another service without sharing their credentials. The familiar "Login with Google" or "Connect with Facebook" buttons use OAuth 2.0 to allow third-party applications to access a subset of the user's data in the identity provider's service without receiving the user's password. OAuth 2.0 handles authorization, answering the question of what the third party is allowed to do, but does not itself provide authentication, the verification of who the user is. OpenID Connect, or OIDC, adds an authentication layer on top of OAuth 2.0. OIDC introduces the concept of the ID token, a cryptographically signed JSON Web Token that contains claims about the authenticated user's identity. This combination of OAuth 2.0 for authorization and OIDC for authentication is the foundation of most modern federated identity systems, particularly in cloud and mobile contexts where SAML's XML-based approach is less suitable.

SCIM, the System for Cross-domain Identity Management, is an HTTP-based protocol that standardizes the API interface for user and group provisioning and deprovisioning. SCIM allows an identity provider such as Azure Active Directory or Okta to automatically create, update, and delete user accounts in connected applications when changes occur in the authoritative identity store, eliminating the manual provisioning processes that lead to delays and errors.

Directory services provide the storage and query infrastructure for identity data. Active Directory is Microsoft's LDAP-based directory service used in Windows domain environments, storing users, groups, computers, and Group Policy Objects and serving as the authentication authority for Kerberos-based domain authentication. Azure Active Directory, now called Microsoft Entra ID, is Microsoft's cloud identity platform, providing identity services for Microsoft 365, Azure, and thousands of integrated SaaS applications. Azure AD Conditional Access policies allow organizations to define risk-based access policies that require additional authentication factors when access is attempted from untrusted locations, from unfamiliar devices, or for high-risk operations. Azure AD Privileged Identity Management provides JIT elevation for Azure AD administrative roles.

Access reviews and recertification automation uses tools that compare current access grants to role-based expectations, identify anomalies such as access that exceeds what the user's role would suggest, and generate manager review workflows that present access for certification. Automated access review platforms dramatically reduce the manual effort required for compliance-driven recertification campaigns while improving the accuracy and thoroughness of the review process. Onboarding and offboarding automation that integrates the HR information system with the IAM platform ensures that account provisioning and deprovisioning are triggered reliably and promptly by HR events rather than depending on manual IT ticket submission, which introduces delays that represent access gaps during transitions.
