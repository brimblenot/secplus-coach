Multifactor Authentication, or MFA, is one of the most effective controls available for preventing unauthorized account access. The premise is straightforward: a single authentication factor, such as a password, can be stolen, guessed, or leaked without the account owner's knowledge. Requiring proof from multiple independent sources makes it dramatically harder for an attacker to gain access even when one factor is compromised. Understanding MFA requires understanding the categories of authentication factors, the specific implementations available, their relative security properties, and the attacks that can defeat each type.

Authentication factors are divided into categories based on the fundamental nature of what they represent. Something you know is a knowledge factor — information that only the legitimate user should possess. Passwords are the most common example, along with PINs and security question answers. Knowledge factors are the most widely used and the weakest: passwords can be guessed through brute force or password spraying, stolen through phishing or keylogging, leaked through data breaches, or obtained through social engineering. Something you have is a possession factor — a physical device that the legitimate user should physically possess. Examples include hardware security tokens, smart cards, mobile phones with authenticator applications, and USB security keys. Possession factors are significantly harder to attack remotely than knowledge factors because stealing a physical device requires physical access or physical proximity. Something you are is an inherence factor — a biometric characteristic of the user. Fingerprint patterns, facial geometry, iris patterns, retinal blood vessel patterns, and voice characteristics are all inherence factors. Biometrics cannot be forgotten, cannot be shared intentionally, and in the case of physical biometrics cannot be remotely stolen in the traditional sense. However, biometric data cannot be changed if compromised, and privacy implications must be considered when storing biometric templates. Somewhere you are is a location factor — geographic information about where the user is accessing from. GPS coordinates from a mobile device, network location derived from IP address geolocation, or cell tower triangulation can all serve as location factors. Location is most commonly used as a supplementary signal or risk indicator rather than a primary authentication factor. Something you do is a behavioral factor — characteristics of how a user performs actions, such as typing cadence, mouse movement patterns, or gait analysis from a mobile device's accelerometer. Behavioral factors enable continuous authentication, passively verifying the user's identity throughout a session rather than only at login.

True multifactor authentication requires combining two or more factors from different categories. Two passwords are two instances of the same category and do not constitute MFA. A password combined with a hardware token satisfies MFA because it combines something you know with something you have. This distinction is important for exam questions that present combinations of authentication mechanisms and ask whether they constitute MFA.

Time-based One-Time Passwords, or TOTP, defined in RFC 6238, generate temporary numeric codes based on a shared secret and the current time. The authenticator application and the server both know the shared secret and apply an HMAC-SHA1 algorithm to the combination of that secret and the current Unix time rounded to 30-second intervals, producing the same 6 or 8-digit code. The code changes every 30 seconds and is only valid for a brief window. Google Authenticator, Microsoft Authenticator, and Authy all implement TOTP. TOTP is significantly more secure than a password alone but has one important vulnerability: real-time phishing attacks can relay TOTP codes. An attacker who tricks a user into entering credentials on a phishing site can relay both the password and the TOTP code to the legitimate site within the 30-second validity window, defeating TOTP protection without the user ever knowing. HOTP, defined in RFC 4226, is a counter-based variant where the code does not expire on a time basis but is invalidated once used, as the counter increments with each use. TOTP is more commonly deployed than HOTP because time-based codes do not require counter synchronization between client and server.

Hardware tokens are dedicated physical devices that generate one-time passwords or participate in cryptographic challenge-response protocols. RSA SecurID is the most historically prominent hardware token, generating time-based codes synchronized with the RSA authentication server. FIDO hardware security keys, such as YubiKey and Google Titan Key, support multiple authentication protocols and represent the most phishing-resistant form of hardware token authentication. Hardware tokens are the most secure OTP option available but carry higher cost and require physical distribution to users.

SMS one-time passwords send a numeric code to the user's registered mobile phone number via text message. SMS OTP is widely supported and familiar to users but is the weakest form of MFA available. SS7 vulnerabilities, which affect the global telephone signaling infrastructure, can allow sophisticated attackers to intercept SMS messages without needing physical access to the phone. SIM swapping attacks, where an attacker convinces a mobile carrier to transfer the victim's phone number to an attacker-controlled SIM card by social engineering the carrier's customer service, redirect all SMS messages to the attacker. Phone number porting attacks are a variant of SIM swapping that use the legitimate number porting process. NIST Special Publication 800-63B now deprecated SMS OTP as an acceptable second factor for government authentication systems due to these vulnerabilities.

Push notification authentication, used by platforms like Duo Security and Microsoft Authenticator, sends a push notification to an enrolled mobile application when a login attempt occurs. The user reviews the request and approves or denies it by tapping a button. Push authentication is convenient and more secure than SMS because it is tied to a specific enrolled device with a cryptographic binding rather than a phone number. However, push authentication is vulnerable to MFA fatigue attacks, also called MFA bombing: an attacker who has obtained the victim's password bombards the victim with push notifications, hoping the victim will eventually approve one out of frustration or confusion. The defense against MFA fatigue is number matching, where the login screen shows a number and the push notification requires the user to type that same number before approving, ensuring the user is actively engaged with a specific legitimate authentication request.

Biometric authentication systems implement the something-you-are factor. Fingerprint scanners, widely deployed on mobile devices as Touch ID and similar systems, use capacitive or optical sensors to capture the fingerprint image and store a mathematical representation rather than the actual image. Facial recognition systems such as Face ID use infrared depth-mapping cameras to create a three-dimensional map of the face, providing liveness detection that defeats attempts to authenticate using a photograph. Face ID achieves approximately 1-in-1,000,000 false accept rate, meaning the probability of a random person unlocking the device is one in a million. Retinal scanning maps the pattern of blood vessels in the retina and is highly accurate but requires expensive specialized hardware and close proximity to the scanner. Iris scanning captures the unique random pattern of the iris and is used in high-security environments including border control. Voice recognition analyzes vocal characteristics but is susceptible to recordings of the user's voice and increasingly to deepfake voice attacks that generate synthetic audio indistinguishable from the legitimate user's voice.

FIDO2 and its web component WebAuthn represent the most significant advancement in authentication security in recent years and deserve particular attention. FIDO2 combines the Client-to-Authenticator Protocol version 2, called CTAP2, with the WebAuthn browser API to create a phishing-resistant authentication standard. The fundamental security property of FIDO2 is origin binding: the authenticator creates a unique key pair for each specific origin, which is a website's scheme, hostname, and port. The private key is stored securely on the authenticator device and the public key is registered with the website. When authenticating, the authenticator produces a cryptographic signature that is mathematically bound to the origin the browser reports. Because the origin is part of the signed data, a phishing site at amaz0n.com cannot receive a FIDO2 response intended for amazon.com even if the user is fooled by the visual similarity of the page. This origin binding defeats all phishing attacks, making FIDO2 the only common MFA mechanism that is truly phishing-resistant. Physical security keys such as YubiKey implement FIDO2 as external authenticators. Passkeys are FIDO2-based discoverable credentials stored on the user's device rather than on an external key, using the device's biometric sensor or PIN as the user verification mechanism and optionally synchronizing across the user's devices via platform cloud storage such as Apple iCloud Keychain, Google Password Manager, or Microsoft Windows Hello. Passkeys replace both the password and the second factor with a single phishing-resistant gesture.

Smart card authentication, used extensively in US government through the PIV, or Personal Identity Verification, standard and in the military through the Common Access Card, or CAC, stores an X.509 certificate and the corresponding private key in a secure chip on the physical card. Authentication requires both the physical card and a PIN to unlock the private key, implementing two-factor authentication combining something you have with something you know. The authentication itself uses certificate-based mutual TLS, where the card presents the certificate and performs a cryptographic signature operation that proves possession of the private key without exposing it.

Adaptive MFA uses risk signals to determine when to require additional authentication factors. When a user logs in from a known device, at a typical time, from their usual location, the risk is low and single-factor authentication may be sufficient. When a user attempts to log in from an unrecognized device, from an unusual location, at an unusual time, or immediately after a login from a geographically distant location, the risk signals indicate elevated risk and the system requires step-up authentication. Impossible travel detection, which flags logins from geographically impossible locations within a short time window, is a specific example of risk-based adaptive authentication.
