Web filtering is the technology and policy framework that controls which websites, web content, and web-based applications users can access from organizational networks and devices. Web filtering serves multiple security and compliance purposes: enforcing the organization's Acceptable Use Policy by restricting access to non-work-related content, protecting users from malware and phishing sites, preventing communication with known-malicious command-and-control infrastructure, and meeting regulatory requirements for content control in certain industries.

URL filtering is the foundational web filtering technique that permits or blocks access based on the URL or domain being requested, matched against a categorized database maintained by the filtering vendor. URL filtering databases categorize millions of websites into functional categories: gambling, adult content, social media, streaming video, news, productivity applications, malware distribution, phishing, command-and-control, newly registered domains, and dozens of others. Administrators configure category-level policies — blocking gambling and adult content across the organization, allowing news and productivity applications, monitoring social media usage without blocking it, and blocking all sites in the malware, phishing, and command-and-control categories — rather than maintaining individual allow and block lists for millions of individual sites. Custom lists supplement the category database for site-specific overrides where the category assignment does not match organizational policy. Reputation scoring provides an additional filtering layer beyond category — the URL filtering engine assigns each domain a trustworthiness score based on automated analysis of the site's behavior, hosting infrastructure, registration age, and observed threat intelligence associations, and administrators can block domains below a specified reputation threshold regardless of category assignment.

DNS filtering blocks access to known-malicious domains at the DNS resolution layer — before any network connection to the target site is established. When a user's device or an application attempts to resolve a blocked domain, the DNS filtering service returns either an NXDOMAIN response indicating the domain does not exist or a redirect to an internal notification page explaining that the site is blocked. DNS filtering is simpler to deploy than proxy-based filtering because it operates at the DNS infrastructure level without requiring redirection of HTTP or HTTPS traffic. Cisco Umbrella provides cloud-delivered DNS filtering with a threat intelligence-enriched domain reputation database. Cloudflare Gateway provides DNS filtering integrated with a broader Zero Trust network access platform. Quad9 is a public DNS service that automatically blocks known-malicious domains for any user who configures it as their resolver, using threat intelligence from a consortium of security companies. Pi-hole is an open-source DNS-based ad and tracker blocker commonly deployed on home and small network infrastructure. A significant advantage of DNS filtering is that it blocks malicious domain lookups from any protocol, not just web traffic — malware attempting to resolve its command-and-control domain will be blocked regardless of whether it uses HTTP, HTTPS, or a custom protocol. A DNS sinkhole is a related technique where a DNS server returns a false address for known-malicious domains, directing any connection attempts to a controlled internal server where the connection fails harmlessly and the connection attempt is logged for investigation.

Proxy-based web filtering intercepts web requests by positioning a proxy server between users and the internet. In a forward proxy configuration, all user web traffic passes through the proxy, which applies security policies including URL filtering, malware scanning, DLP inspection, and content analysis to every request before forwarding it to the destination and to every response before delivering it to the user. An explicit proxy requires each user's browser or application to be configured to send requests to the proxy address — this is easy to implement through Group Policy or MDM configuration but also easy for users to bypass by changing their browser configuration. A transparent proxy intercepts traffic at the network level, typically through firewall policy that redirects HTTP and HTTPS traffic to the proxy, without requiring any configuration on client devices and without users being aware that a proxy is processing their traffic. Transparent proxy deployment is harder to bypass because it operates at the network layer rather than requiring client cooperation. The forward proxy is the most common deployment model for enterprise web security because it combines both approaches — transparent interception for HTTP and configured browser proxy for HTTPS — to provide comprehensive coverage.

SSL/TLS inspection, also called HTTPS inspection or SSL interception, is the practice of decrypting, inspecting, and re-encrypting HTTPS traffic at the proxy to enable security analysis of encrypted web content. Without SSL inspection, the proxy can see the destination domain of an HTTPS connection but not the specific URL, request content, or response content — the payload is encrypted end-to-end between the browser and the server. SSL inspection works by performing a man-in-the-middle on the HTTPS connection: the proxy presents a dynamically generated certificate to the browser signed by a proxy Certificate Authority, establishes its own separate TLS connection to the destination server, decrypts traffic received from both sides, and applies security policies including URL filtering, malware scanning, and DLP to the decrypted content before re-encrypting it for transmission. For SSL inspection to work without triggering security warnings, the proxy's Certificate Authority certificate must be installed in the trusted certificate store of all client devices, which is accomplished through Group Policy in Windows domain environments or through MDM configuration profiles on mobile devices. SSL inspection raises privacy considerations for sensitive personal communications — many organizations configure SSL inspection bypass rules for specific categories such as banking, healthcare, and government sites to avoid intercepting sensitive personal information. Users must be informed through a clear acceptable use policy that SSL inspection is in place.

The Acceptable Use Policy, abbreviated AUP, is the foundational policy document that defines what web usage is permitted and prohibited for organizational users. The AUP is the source of truth that web filtering policy implements technically. AUP categories that are typically blocked include adult content, gambling, hacking tools, known malware and phishing sites, and peer-to-peer file sharing. Categories that are typically allowed include business applications, reference sites, news, and educational content. Some categories are handled with monitoring rather than blocking — social media access may be logged and reported to managers without being blocked for professional use cases. Time-based policies allow different rules during working hours versus after hours or during lunch breaks. Role-based policies grant different access to different user groups — IT security staff may need access to hacking tool sites and malware analysis resources that are blocked for standard users.

Safe search enforcement prevents adult content from appearing in search engine results even when search engines themselves are not blocked. DNS-based safe search enforcement works by redirecting DNS lookups for major search engines to their safe search enforcement endpoints: lookups for google.com are redirected to forcesafesearch.google.com, and lookups for bing.com are redirected to strict.bing.com. These safe search enforcement addresses activate the search engine's strictest content filtering settings for all searches from the network, preventing users from disabling safe search in their search settings.

Download controls restrict the types of files users can download from the internet. Blocking executable file types including .exe, .msi, .bat, .ps1, and .scr files from internet sources for standard users prevents the most common malware delivery mechanism — drive-by download and email attachment execution. Files that pass the download type check can be subjected to malware scanning using antivirus and sandbox analysis at the proxy. Suspicious files can be submitted to a cloud sandbox service that executes the file in an isolated environment and reports behavioral indicators of malicious activity before delivering the file to the user or blocking it.

Agent-based web filtering extends content filtering to devices that are not connected to the corporate network. When employees work from home or from public networks, their traffic does not pass through the corporate firewall or on-premises proxy. Agent-based filtering installs a lightweight client on each device that applies URL filtering and security policies locally, regardless of what network the device is connected to. The agent typically routes filtered traffic through a cloud-based security service using a lightweight tunnel, maintaining consistent policy enforcement without requiring VPN connectivity to the corporate network. Agent-based filtering must be continuously updated with the latest URL categories and threat intelligence, requiring a management platform that pushes updates to all agents regularly.

Cloud Access Security Broker, abbreviated CASB, is a specialized security control that extends web filtering capabilities to cloud application access. CASB addresses the challenge of shadow IT — the use of unauthorized cloud applications by employees that bypasses both the organization's security controls and its data governance policies. A CASB discovers all cloud services in use by analyzing network traffic logs or by sitting inline in the traffic path, assessing each service's security posture and compliance certifications, and enforcing policies about which services are permitted. For permitted cloud services, the CASB enforces Data Loss Prevention policies that detect and block uploads of sensitive data such as intellectual property or regulated customer information. For discovery mode, the CASB analyzes traffic logs to identify all cloud services in use and presents the organization with a shadow IT inventory showing which unauthorized services employees are using, what data volumes are flowing to each, and what risk these services represent based on their security posture.

Web filtering bypass attempts and countermeasures are an ongoing challenge. Users may attempt to bypass proxy-based filtering by configuring their browser to use a personal VPN service that routes traffic outside the corporate proxy. Firewalls can block common VPN ports and destinations, but determined users may find VPN services that mimic standard HTTPS traffic. SSL inspection can detect some VPN traffic by examining TLS parameters, but sophisticated VPN services may evade detection. On mobile devices, users may disable MDM VPN profiles or use cellular data instead of Wi-Fi to bypass network-based filtering. MDM-enforced always-on VPN configurations that apply to all data interfaces and restrict device use when the VPN is not active provide the most comprehensive filtering coverage for managed mobile devices.

Web security gateway appliances and cloud services provide the underlying technology for enterprise web filtering deployments. Traditional on-premises web security gateway appliances from vendors including Symantec Web Security Service and Forcepoint Web Security provide comprehensive proxy-based filtering for fixed office locations. Cloud-delivered web security services such as Zscaler Internet Access, Cisco Umbrella, and Netskope route user traffic through cloud infrastructure where filtering and inspection are applied at globally distributed points of presence. Cloud-delivered services are better suited to distributed workforces where users are rarely all in one physical location, providing consistent policy enforcement regardless of where users are working and eliminating the need for backhaul of remote user traffic to a central on-premises proxy.

Reporting and monitoring from web filtering systems provides security intelligence and compliance evidence. User activity logs record which users visited which sites, when, and how much data was transferred, providing the audit trail needed to investigate potential policy violations or security incidents. Blocked request logs show which users attempted to access blocked categories, which may indicate users testing the filtering policy, attempts to access malware or phishing sites — indicating that the user received a malicious link and the filtering saved them from compromise — or policy violations requiring HR involvement. Executive reports summarize web usage trends, top blocked categories, and top users by data volume. Compliance reports demonstrate to auditors that web filtering is in place and functioning according to policy requirements.
