The operating system is the most foundational layer of any computing environment, and its security posture determines the security ceiling for every application and process running on top of it. If an attacker compromises the operating system, they gain influence over everything it hosts — all applications, all data, all network communications. This foundational importance means OS security must be addressed systematically, covering patch management, privilege control, file system protections, disk encryption, application restrictions, credential protections, account governance, registry security, audit policies, and OS hardening for both Windows and Linux platforms.

Patch management at the operating system level is arguably the highest-impact security control available to defenders. The vast majority of successful attacks exploit known vulnerabilities for which patches already exist. On Windows systems, Windows Update provides automated patch delivery for individual endpoints. Windows Server Update Services, commonly abbreviated WSUS, extends this to enterprise environments by providing a centralized server that downloads updates from Microsoft and distributes them internally, allowing administrators to approve, test, and deploy patches on a controlled schedule rather than having every device reach out individually to the internet. Microsoft Endpoint Configuration Manager, also called MECM or its older name SCCM, extends patch management further by integrating OS deployment, application management, compliance reporting, and patch deployment in a unified platform suited to large organizations. Windows Autopatch is a newer cloud-based service that automates the entire patching workflow as a software-as-a-service offering, removing the administrative burden of managing WSUS while maintaining enterprise controls. On Linux systems, package managers handle software and OS updates. Debian-based distributions use apt and apt-get, while Red Hat family systems use yum or its modern successor dnf. SUSE-based systems use zypper. The critical security practice on Linux is ensuring that automatic security updates are configured and enabled, either through the unattended-upgrades package on Debian systems or dnf-automatic on Red Hat systems, so that security patches are applied promptly without requiring manual administrator intervention on every system.

Least privilege is the principle that every user, service, and process should operate with only the minimum permissions required to perform their intended function. At the operating system level, this means daily work should be conducted with standard user accounts rather than administrative or root accounts. A separate elevated account should be used only when administration is required, and it should never be used for browsing the web, reading email, or other routine tasks. On Windows, User Account Control, or UAC, serves as the enforcement mechanism for least privilege by prompting for confirmation or credentials when an action requiring administrative elevation is requested. This prompt interrupts the automatic elevation that would otherwise allow malware running in a user context to silently acquire administrative access. On Linux, the sudo command provides granular privilege elevation, allowing specific users to run specific commands with elevated privileges. All sudo executions are logged in the authentication log at /var/log/auth.log, creating an audit trail of privileged actions. Service accounts should be created with the minimum rights necessary for the service to function, and services should not run as the SYSTEM account or root unless absolutely required. Running services with overly permissive accounts means that if a service is compromised, the attacker inherits those excessive privileges immediately.

File system security controls determine what users and processes can access which files and with what level of access. On Windows, NTFS permissions provide granular control through a set of standard permissions: Read, Write, Execute, Modify, and Full Control. Permissions are assigned to users and groups and can be inherited from parent folders to simplify administration. The effective permissions for any given user account are the combination of all permissions directly assigned to that user plus all permissions assigned to any group that user belongs to. The icacls command-line tool allows viewing and modifying NTFS permissions programmatically. On Linux, file permissions use the traditional owner, group, and others model, with read, write, and execute bits for each class. The chmod command modifies permissions and the chown command changes ownership. Special permission bits add additional functionality: the sticky bit on directories prevents users from deleting files owned by others, which is why /tmp is sticky. The SUID and SGID bits, when set on executables, cause them to run with the permissions of the file owner rather than the executing user, which creates significant security risks if applied to programs that can be abused for privilege escalation. Access Control Lists extend beyond the basic permission model to allow more granular per-user and per-group permissions on specific files without using the basic owner-group-others structure. Encrypted file systems add a layer of protection against physical access attacks. On Windows, the Encrypting File System, or EFS, transparently encrypts individual files and folders using the user's certificate, so the files appear normal to the owning user but are unreadable if accessed by other means. Linux ext4 supports filesystem-level encryption for individual directories, providing similar transparent encryption at the directory level.

Disk encryption protects data at rest against the physical theft scenario where an attacker removes a drive from a system and reads it directly, bypassing OS-level access controls entirely. BitLocker is the Windows full-disk encryption solution, using AES-256 to encrypt entire volumes. BitLocker's most secure configuration uses a Trusted Platform Module chip in the computer to store the encryption key and perform pre-boot authentication, preventing the OS from booting on unauthorized hardware. A recovery key is generated at setup and should be stored in Active Directory or Azure Active Directory so that administrators can recover access if the TPM fails or the system motherboard changes. BitLocker To Go extends encryption to removable drives, ensuring data on USB drives and external storage is protected even if the drive is lost. On macOS, FileVault provides full-disk encryption using XTS-AES-128 and integrates with the Apple platform's hardware security features. On Linux, the standard full-disk encryption solution is LUKS, the Linux Unified Key Setup, working in conjunction with dm-crypt to provide transparent block-device encryption. Most Linux distributions support configuring LUKS encryption during installation, and it becomes the standard approach for securing laptops and sensitive systems.

Application security at the OS level begins with controlling which applications are permitted to execute. Application whitelisting restricts execution to explicitly approved programs, blocking everything else by default. Windows Defender Application Control, or WDAC, is Microsoft's kernel-level application whitelisting technology, enforcing code integrity policies that prevent unauthorized executables, scripts, drivers, and DLLs from loading. Because WDAC operates at the kernel level, it is more tamper-resistant than user-mode solutions. AppLocker is an older, Group Policy-based application control mechanism that defines rules based on file path, hash value, or digital publisher, restricting which users can run which applications. Reducing the attack surface means removing unnecessary applications entirely, since every installed application is a potential vulnerability. Keeping all installed applications patched is equally critical, as vulnerabilities in third-party applications are a major attack vector.

Credential storage security is a critical OS concern because credential theft is the primary lateral movement technique attackers use after initial compromise. Windows stores credentials in the Windows Credential Manager and Local Security Authority Subsystem Service, which is a process called LSASS. The Mimikatz tool and similar attack software target LSASS to extract password hashes and plaintext credentials from memory, enabling pass-the-hash and pass-the-ticket attacks. Credential Guard, introduced in Windows 10, uses virtualization-based security, running a hypervisor-protected instance of the Local Security Authority that stores credentials in an isolated VM-like environment that the main OS cannot directly access. This prevents hash extraction even when an attacker has administrative access to the system. The Protected Users security group provides additional protections for high-privilege accounts, restricting the use of NTLM authentication and limiting Kerberos ticket lifetimes and caching behavior, reducing the exposure window if a protected account is compromised.

Account management encompasses disabling default and guest accounts, which attackers frequently target because they often have default or weak credentials. Naming conventions for accounts should be established and enforced, with privileged accounts clearly identifiable and subject to additional controls. Privileged Access Workstations, or PAWs, are dedicated hardened systems used exclusively for administrative tasks, ensuring that privileged sessions are conducted from systems protected against common attacks rather than from general-purpose workstations that handle email and web browsing. Account lockout policy defines the threshold of failed authentication attempts that triggers a lockout, the duration of the lockout before automatic reset, and the observation window within which failed attempts are counted. These controls limit brute force and password spraying attacks but must be balanced against operational impact, since overly aggressive lockout thresholds can be used by attackers to deny service by intentionally locking accounts.

Registry security is a Windows-specific concern because the registry is a critical configuration store that persists across reboots and is a common target for attacker persistence mechanisms. Restricting which accounts can modify important registry keys prevents unauthorized changes. Monitoring registry paths commonly used for persistence, such as HKLM\Software\Microsoft\Windows\CurrentVersion\Run and related autorun keys, allows detection of attacker-installed persistence mechanisms. Auditing registry access through Windows audit policies provides log data for forensic investigation.

Security audit policies define what events Windows logs and must be configured deliberately, since the default audit configuration is often insufficient for security monitoring. The key audit categories include account logon events, account management, object access, privilege use, process tracking, system events, and policy changes. Each category can audit success events, failure events, or both. Logging both successes and failures provides maximum visibility: failures reveal attack attempts while successes create an audit trail of normal activity. On Linux, the auditd daemon provides kernel-level auditing, recording system calls matching configured rules. The auditctl command manages rules, and ausearch and aureport analyze the resulting audit log at /var/log/audit/audit.log. Auditd can audit file access, network operations, privilege escalation, and virtually any system call, providing granular visibility into OS-level activity.

OS hardening for Windows involves a systematic set of configuration changes that reduce the attack surface and enforce secure defaults. Enabling Windows Defender with real-time protection provides signature and behavior-based malware detection integrated into the OS. Configuring Windows Defender Firewall with appropriate rules for inbound and outbound traffic blocks unauthorized network access. Disabling SMBv1 using Remove-WindowsFeature FS-SMB1 eliminates a protocol version with numerous serious vulnerabilities including those exploited by EternalBlue and WannaCry. Disabling LAN Manager and NTLMv1 authentication and enforcing a minimum of NTLMv2, with a preference for Kerberos authentication wherever possible, eliminates weak authentication protocols that are vulnerable to downgrade and relay attacks. Disabling autorun and autoplay prevents malware from automatically executing when removable media is inserted. Enabling Data Execution Prevention, or DEP, for all programs prevents code from executing from data-only memory regions, blocking a common class of exploitation technique. Address Space Layout Randomization, or ASLR, randomizes the memory addresses where system components are loaded, making it difficult for attackers to predict where code and data will be located in memory. The Enhanced Mitigation Experience Toolkit, EMET, provided additional exploit mitigation controls in older Windows versions, and its successor Windows Defender Exploit Guard integrates similar protections including Attack Surface Reduction rules, Controlled Folder Access, and network protection into modern Windows.

Linux hardening follows a parallel philosophy of reducing attack surface and enforcing secure defaults. Disabling unnecessary services using the systemctl disable command reduces the number of running processes that could be targeted. Configuring the host firewall using iptables, nftables, or firewalld to restrict inbound and outbound traffic limits network exposure. Secure Shell daemon configuration is critical: setting PermitRootLogin no prevents direct root login via SSH, forcing administrators to log in with a personal account and then elevate. Enabling SSH public key authentication and setting PasswordAuthentication no in sshd_config eliminates password-based SSH access entirely, removing the risk of password brute force and credential stuffing attacks against SSH. Configuring fail2ban to automatically block IP addresses with excessive failed authentication attempts provides automated protection against brute force. SELinux, the Security-Enhanced Linux mandatory access control framework, is the standard on Red Hat family distributions including RHEL, CentOS, and Fedora, providing kernel-level enforcement of access policies that confine processes to only the resources they are legitimately permitted to access. AppArmor serves the same mandatory access control purpose on Debian and Ubuntu systems, using profile files to define per-application access rules. Both SELinux and AppArmor implement mandatory access control that operates independently of discretionary user-level permissions, providing a second enforcement layer that limits the damage an attacker can do even after compromising a running process.
