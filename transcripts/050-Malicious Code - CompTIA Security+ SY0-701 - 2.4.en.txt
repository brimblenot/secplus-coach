Malicious code, sometimes called malcode, encompasses any code intentionally written or repurposed to cause harm, gain unauthorized access, exfiltrate data, or disrupt system operation. The category extends well beyond traditional malware files saved to disk. It includes scripts, macros, interpreted code, and legitimate system components used in unauthorized ways. Understanding the breadth of malicious code is essential because modern attackers have shifted heavily toward techniques that avoid writing files to disk at all, making traditional file-based detection insufficient.

Shell scripts are among the simplest and most common forms of malicious code in Linux and Unix environments. Bash and sh scripts can execute destructive commands, download additional payloads over HTTP or HTTPS using curl or wget, establish persistent backdoors by adding entries to cron or rc files, and exfiltrate data through network utilities such as netcat. Because shell scripts are interpreted text files, they leave no binary signature for traditional antivirus to recognize. Defenders detect malicious shell scripts through script logging, file integrity monitoring on system directories, and application allowlisting that prevents execution of unauthorized scripts. Script signing, requiring that executed scripts carry a verified cryptographic signature, adds another layer of control.

PowerShell has become one of the most powerful and consequently most abused tools in the Windows environment. Microsoft built PowerShell as an administrative scripting language with deep integration into the operating system, the .NET framework, and remote management infrastructure. These same capabilities make it extraordinarily attractive to attackers. The most significant PowerShell abuse technique is downloading and executing code entirely in memory without writing anything to disk, often called a fileless attack. The command Invoke-Expression combined with a downloaded string, abbreviated as IEX with System.Net.WebClient DownloadString, retrieves a script from a remote server and executes it immediately in the PowerShell process without creating any file on the local filesystem. Because no file is written, there is no hash to match against an antivirus signature database. Attackers further obfuscate their PowerShell payloads using Base64 encoding of the entire command, passed using the EncodedCommand parameter, or by applying additional layers of string concatenation and character substitution that defeat simple pattern matching. PowerShell's remoting capabilities, built on WS-Management, allow attackers who have compromised credentials to execute commands on remote systems across the network. AMSI, the Anti-Malware Scan Interface, is a Windows API that hooks into the PowerShell, VBScript, JScript, and Office VBA execution pipelines, providing antimalware engines with the content of scripts after deobfuscation and before execution. AMSI bypasses, a class of techniques that disable or subvert this hook, are a constant arms race between attackers and defenders. PowerShell Constrained Language Mode restricts the language features available in a PowerShell session to a safe subset, and enforcing it through AppLocker or Windows Defender Application Control significantly limits what attackers can accomplish even if they can run PowerShell. Script Block Logging records the content of PowerShell script blocks as they are executed, capturing deobfuscated code that AMSI would also see, providing forensic evidence even when fileless techniques are used.

Windows Management Instrumentation, or WMI, is a management framework built into Windows that provides access to nearly every aspect of system configuration, state, and operation. Administrators use WMI for remote queries, configuration changes, and task automation. Attackers have found it equally useful for persistence, lateral movement, remote execution, and reconnaissance. WMI event subscriptions allow code to be registered as a response to system events such as startup, logon, or process creation. These subscriptions survive reboots and even reimage operations in some configurations because they are stored in the WMI repository rather than in conventional persistence locations like the registry Run key. Attackers can use WMI subscriptions to maintain persistent access that is invisible to users and difficult to detect without specific WMI monitoring. Remote WMI execution using valid credentials allows an attacker to run commands on remote systems without installing any agent or additional software. Because WMI is a legitimate Windows component, traffic it generates blends with normal administrative activity and may not trigger network detection tools.

Python has become a dominant language in the security research and offensive tooling communities. Its cross-platform nature, extensive standard library, and rich ecosystem of third-party packages make it practical for building everything from network scanners to full post-exploitation frameworks. The Impacket library provides pure-Python implementations of Windows network protocols including SMB, MSRPC, and Kerberos, enabling sophisticated attacks against Windows environments from any platform where Python runs. Scapy allows arbitrary packet construction and injection for custom network attacks. Python scripts are commonly used to implement exploitation modules, post-exploitation tasks, custom C2 clients, and data exfiltration tools. Python's readability and brevity also make it easy to generate one-time custom tools that do not match signatures of known frameworks.

JavaScript and VBScript are frequently used in malicious contexts delivered through phishing, malvertising, or web exploitation. The Windows Script Host executes JavaScript and VBScript files with the extensions .js and .vbs respectively, providing access to the local filesystem, registry, network, and COM automation interfaces. An attacker who delivers a malicious .js or .vbs file through a phishing email or a drive-by download can execute code with the privileges of the logged-in user simply by double-clicking the file. HTML Application files with the .hta extension execute within the mshta.exe host process using Internet Explorer's rendering engine with elevated permissions that bypass browser sandboxing, making them a popular delivery mechanism for malicious payloads. Defenders can disable Windows Script Host entirely for users who do not require scripting functionality, and email filtering should block execution of these file types when received as attachments.

Macro code embedded in Microsoft Office documents using Visual Basic for Applications, or VBA, has been one of the most prolific malware delivery mechanisms for years. When a user opens a document that contains macros and enables them, the macro code executes with the user's full privileges. The Document_Open event in Word or the Workbook_Open event in Excel provides automatic execution without any user interaction beyond enabling macros. Attackers deliver macro-enabled documents through phishing campaigns, relying on social engineering to convince the user to enable macros when prompted. The payload within the macro typically downloads and executes a second-stage payload, often using the same PowerShell download-and-execute technique described above. Microsoft has progressively tightened macro security defaults in recent years, blocking macros from internet-sourced documents by default in Microsoft 365 and requiring additional user steps to enable them. Protected View opens documents from the internet in a sandboxed read-only mode that does not execute macros. Macro signing requires that only macros signed by a trusted publisher can execute, blocking unsigned attacker macros entirely.

Staged payloads are a common delivery architecture in modern malware. The initial stage, called the loader or dropper, is a small file that performs minimal suspicious activity and is less likely to trigger security controls. Once executed, the loader connects to a command and control server and downloads the larger, more functional second-stage payload, such as a Meterpreter shell or a Cobalt Strike Beacon, directly into memory. Stageless payloads bundle the entire payload into a single artifact for use in environments where outbound internet access is restricted and a second-stage download would fail.

Living-off-the-land attacks use tools already present on the target system to perform malicious activities, avoiding the need to download custom tools that might be detected. Certutil.exe is a certificate utility that can download files from URLs and decode Base64-encoded data, providing an attacker with a download capability using a signed Microsoft binary. Mshta.exe executes HTA files and can be pointed at a remote URL to download and run an HTA payload directly from an attacker server. Regsvr32.exe can proxy-execute DLL files from remote locations using the COM registration mechanism. Rundll32.exe executes exported functions from DLLs, another mechanism for running code without writing a standalone executable. Wscript.exe and cscript.exe execute VBScript and JScript files. Because all of these are legitimate signed Windows binaries, they are typically not blocked by application allowlisting rules and may not trigger antivirus alerts.

A comprehensive defense against malicious code requires multiple overlapping controls. AMSI provides runtime inspection of interpreted code across multiple scripting environments. PowerShell Constrained Language Mode and script signing requirements limit what attackers can accomplish even if they reach a PowerShell prompt. Script Block Logging and Module Logging capture deobfuscated script content for forensic and detection purposes. Windows Defender Application Control and AppLocker enforce allowlists of approved applications and scripts, blocking execution of unauthorized code including custom attacker tools and unsigned scripts. Disabling Windows Script Host for users who do not need it eliminates a common delivery mechanism. Email security gateways that strip or quarantine macro-enabled document attachments and Office Protected View reduce exposure to macro-based attacks. EDR platforms monitor process behavior, memory, and network activity at runtime, detecting malicious patterns even when no file is written to disk.
