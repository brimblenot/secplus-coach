Encryption is the process of transforming readable plaintext into an unintelligible ciphertext using a mathematical algorithm and a key, in such a way that only someone with the correct key can reverse the process and recover the original data. Understanding the wide variety of encryption algorithms, their key lengths, their modes of operation, and the contexts in which each is appropriate is essential for the CompTIA Security Plus exam and for real-world security practice.

Symmetric encryption algorithms use the same key for both encryption and decryption. The oldest widely deployed symmetric standard is DES, the Data Encryption Standard. DES uses a 56-bit key length, which was considered adequate in the 1970s when it was standardized, but is completely insufficient today. A 56-bit key provides only about 72 quadrillion possible key values, and modern hardware can exhaust that entire keyspace through brute force in a matter of hours. DES is considered cryptographically broken and must never be used in any new system.

Triple DES, abbreviated as 3DES, was created as a stopgap measure to extend the life of DES by applying the DES algorithm three times to each block of data. In the most common configuration, called two-key 3DES, three separate 56-bit DES keys are used in an encrypt-decrypt-encrypt sequence, yielding an effective security level of approximately 112 bits. In the three-key configuration the effective security approaches 168 bits, but certain cryptographic attacks reduce this in practice. While 3DES is far stronger than single DES, it is also dramatically slower because it runs the cipher three times. 3DES is now deprecated by NIST and must not be used in new implementations, though it persists in some legacy systems.

The Advanced Encryption Standard, or AES, replaced DES as the federal standard in 2001 and is today the gold standard for symmetric encryption. AES supports three key lengths: 128 bits, 192 bits, and 256 bits. AES-128 is considered secure against all known attacks, including classical brute force, and is extremely fast in both hardware and software implementations. AES-256 provides an additional security margin and is the preferred choice for sensitive government and high-security applications. AES is used in TLS for session encryption, in BitLocker and FileVault for full disk encryption, in WPA3 for wireless security, and in countless other protocols and applications.

The security level provided by any symmetric algorithm depends not just on the key length but also on the mode of operation, which determines how the algorithm processes data that is longer than a single fixed-size block. AES itself operates on 128-bit blocks, so for messages longer than 128 bits, a mode of operation must be specified.

Electronic Code Book mode, ECB, is the simplest but most insecure mode. In ECB mode, each 128-bit block of plaintext is encrypted independently using the same key. This means that identical plaintext blocks always produce identical ciphertext blocks, which reveals patterns in the data. The classic illustration of this flaw is the ECB penguin: an image of a penguin encrypted with AES in ECB mode still clearly shows the outline of the penguin because the uniform color regions in the image produce repeating ciphertext patterns. ECB mode must never be used in any real application.

Cipher Block Chaining mode, CBC, addresses ECB's weakness by XORing each block of plaintext with the ciphertext output of the previous block before encrypting. This means that identical plaintext blocks will produce different ciphertext blocks depending on all the data that came before them. CBC requires an initialization vector, or IV, for the first block, which must be random and unpredictable to prevent certain attacks. The sequential nature of CBC means that encryption cannot be parallelized, because each block depends on the previous one, though decryption can be partially parallelized.

Counter mode, CTR, transforms the block cipher into a stream cipher by encrypting successive values of a counter and XORing the resulting keystream with the plaintext. Because the counter values for different blocks are independent of one another, CTR mode allows both encryption and decryption to be fully parallelized, making it very fast on modern multi-core processors. CTR mode also eliminates the need for padding because it produces exactly as many keystream bytes as needed.

Galois Counter Mode, GCM, extends CTR mode by adding a Galois field multiplication step that computes an authentication tag over the ciphertext and any associated data. This makes GCM an Authenticated Encryption with Associated Data scheme, abbreviated AEAD. An AEAD cipher provides both confidentiality and data integrity in a single pass. If any bit of the ciphertext is altered after encryption, the authentication tag verification will fail and the data will be rejected. GCM is used in TLS 1.3, SSH, and IPsec. It is the preferred mode for virtually all new applications requiring both encryption and integrity.

Stream ciphers encrypt data one bit or byte at a time rather than processing fixed-size blocks. RC4 was once widely deployed in WEP for wireless encryption and in early versions of TLS. However, multiple cryptographic attacks against RC4 have been discovered over the years, and RC4 is now completely broken and explicitly forbidden by RFC 7465. No modern system should use RC4.

Asymmetric encryption algorithms use mathematically related key pairs. RSA is the most widely deployed asymmetric algorithm. Its security is based on the computational difficulty of factoring the product of two very large prime numbers. RSA key lengths of 2048 bits are currently considered the minimum acceptable, and 3072 or 4096 bits are recommended for long-term security. RSA can be used for both key exchange and digital signatures but is too slow for bulk data encryption. RSA key exchange, in which the client encrypts a session key with the server's RSA public key, was used in older TLS versions but has been removed from TLS 1.3 because it does not provide Perfect Forward Secrecy.

Elliptic Curve Cryptography, ECC, provides equivalent security to RSA but with much smaller key sizes. A 256-bit ECC key provides roughly the same security level as a 3072-bit RSA key. Smaller keys mean faster computation and less memory usage, which makes ECC particularly valuable for constrained devices such as smartphones, IoT sensors, and embedded systems. ECC is used in ECDH for key agreement and in ECDSA for digital signatures. Modern TLS 1.3 uses ECDHE, the elliptic curve Diffie-Hellman ephemeral variant, for key exchange, combining ECC's efficiency with Perfect Forward Secrecy.

The Diffie-Hellman key agreement protocol is not an encryption algorithm but rather a method by which two parties can independently derive the same shared secret without ever transmitting that secret over the network. Each party generates a public and private value, exchanges the public values, and each computes the shared secret from their own private value and the other party's public value. The mathematical hardness of the discrete logarithm problem makes it infeasible for an eavesdropper to derive the shared secret from the exchanged public values alone.

The Digital Signature Algorithm, DSA, is a federal standard specifically designed for creating digital signatures and is not used for encryption. DSA is based on the discrete logarithm problem and has been largely superseded by ECDSA in modern systems.

Perfect Forward Secrecy, PFS, is a property of a key exchange protocol in which compromise of the long-term private key does not allow an adversary to decrypt past recorded sessions. PFS is achieved by using ephemeral key pairs: a fresh temporary key pair is generated for each session, the shared session key is derived, and the ephemeral private key is then discarded. Because the session key was never stored and cannot be rederived without the discarded ephemeral private key, an attacker who later obtains the server's long-term private key still cannot decrypt previously recorded sessions. Diffie-Hellman with ephemeral keys, DHE, and elliptic curve Diffie-Hellman with ephemeral keys, ECDHE, both provide PFS and are mandatory in TLS 1.3.

Hardware encryption devices provide security guarantees that software implementations cannot match. The Trusted Platform Module, or TPM, is a specialized chip embedded on a computer's motherboard. The TPM stores cryptographic keys in persistent protected storage, generates random numbers, and provides measured boot integrity verification. It enables full disk encryption solutions like BitLocker by securely storing encryption keys in hardware where they cannot be extracted by software attacks. TPM 2.0 is required for Windows 11 and supports a broader range of cryptographic algorithms than the older TPM 1.2 standard.

The Hardware Security Module, or HSM, is a dedicated, certified hardware device designed for high-performance cryptographic operations at scale. HSMs are validated to FIPS 140-2 or FIPS 140-3 standards, with higher security levels providing greater physical tamper resistance and tamper-response capabilities. HSMs store private keys in hardware where they cannot be exported, perform cryptographic operations internally so keys never leave the device, and can handle many concurrent cryptographic operations efficiently. PKI deployments use HSMs to protect CA private keys, and payment systems use HSMs to protect card processing keys.

The Secure Enclave is an isolated processor region physically separate from the main CPU, designed to protect the most sensitive security operations on a device. Apple's Secure Enclave Processor stores biometric templates for Touch ID and Face ID and the device's encryption keys, ensuring these never reach the main application processor or operating system. Intel Software Guard Extensions, SGX, provides encrypted memory regions called enclaves for confidential computing workloads where even the operating system or hypervisor should not be able to read the data.

Full disk encryption protects all data on a storage device by encrypting the entire volume. BitLocker on Windows uses the TPM for pre-boot authentication and can require a PIN or USB key for additional security. FileVault on macOS uses the Secure Enclave or user password. LUKS combined with dm-crypt provides full disk encryption on Linux. Self-encrypting drives implement AES encryption in the drive firmware according to the Opal standard, making encryption completely transparent to the operating system and enabling instant cryptographic erasure by simply discarding the encryption key.

At the file or folder level, Windows Encrypting File System, EFS, allows individual files to be encrypted within the NTFS file system, and tools like PGP and GPG enable encryption of individual files and email messages. Database encryption protects stored data using Transparent Data Encryption, TDE, which automatically encrypts and decrypts data as it is written to and read from disk without requiring application changes.

Transport layer encryption protects data in motion. TLS provides encryption at the application layer for web traffic, email, and other protocols, while IPsec provides encryption at the network layer, protecting all traffic between two endpoints regardless of application. Application layer encryption, such as end-to-end encrypted messaging, protects data from the application itself all the way to the recipient, such that even the service provider cannot read the content.

Looking toward the future, quantum computing poses a serious threat to current asymmetric cryptography. Shor's algorithm, running on a sufficiently large quantum computer, can efficiently factor large integers and compute discrete logarithms, which would break RSA and ECC entirely. Grover's algorithm provides a quadratic speedup for searching, which effectively halves the security strength of symmetric keys, meaning AES-128 would provide only 64-bit security against a quantum attacker while AES-256 would still provide 128-bit security.

In response, NIST has standardized a set of post-quantum cryptographic algorithms. CRYSTALS-Kyber is a key encapsulation mechanism based on the hardness of lattice problems, intended to replace RSA and ECDH for key exchange. CRYSTALS-Dilithium and FALCON are digital signature algorithms also based on lattice problems. SPHINCS-plus is a hash-based signature scheme that relies only on the security of the underlying hash function for its security guarantees. Organizations are encouraged to develop cryptographic agility, designing systems so that cryptographic algorithms can be swapped out as standards evolve without requiring complete rebuilds of dependent applications and infrastructure.
