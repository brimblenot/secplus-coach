Authentication, Authorization, and Accounting form a three-part security framework commonly referred to as AAA, pronounced "triple A." This framework describes the three distinct functions that any complete access control system must perform: verifying who a user is, determining what that user is permitted to do, and tracking what the user actually did. Understanding each component individually, how they relate to one another, and the protocols used to implement them in enterprise environments is essential for the Security+ exam and for real-world security practice.

Before authentication can occur, a user must perform identification, which means claiming an identity to the system. When you type a username into a login screen, you are identifying yourself. Identification is a declaration, not proof. Authentication is the step that proves the claim is valid. When you also supply the correct password, PIN, smart card, fingerprint, or other credential, you are authenticating. The distinction matters because systems must separately handle the claimed identity and the verification of that identity.

Authentication is based on factors that fall into five categories. Something you know includes passwords, passphrases, PINs, and security question answers. These are the most common but also the weakest factor because they can be guessed, stolen, or socially engineered. Something you have includes physical tokens such as hardware keys, smart cards with embedded chips, one-time password (OTP) generators, and authenticator apps on smartphones that generate time-based one-time passwords (TOTP). Something you are encompasses biometric identifiers: fingerprint scans, retinal or iris patterns, facial recognition, hand geometry, and vein pattern recognition. Somewhere you are is a location-based factor, such as geolocation derived from IP address or GPS, used to verify that the authentication attempt originates from an expected location. Something you do refers to behavioral biometrics such as keystroke dynamics (the rhythm and timing of typing), mouse movement patterns, or handwriting recognition.

Multi-factor authentication, abbreviated MFA, requires a user to present credentials from at least two different factor categories. A password combined with a one-time code sent to the user's phone is MFA because it combines something you know with something you have. MFA dramatically increases security because an attacker who steals a password still cannot authenticate without the second factor. Two-step verification, where two credentials from the same category are used (such as two passwords), is not true MFA.

Once authentication succeeds and the system knows who the user is, the next function is authorization, which determines what that user is permitted to access and do. Authorization is governed by the principle of least privilege, which states that every user, process, and system should be granted only the minimum access rights necessary to perform their legitimate function. The related need-to-know principle states that access to specific information should only be granted if there is a clear business justification.

Access Control Lists, or ACLs, are a common authorization mechanism in which each resource has a list of subjects and their permitted operations. For example, a file might have an ACL stating that Alice can read and write, Bob can only read, and the network administrator can read, write, and delete. Role-based access control, or RBAC, improves scalability by assigning permissions to roles rather than to individual users. A user's authorization is determined by which roles they hold. Adding a user to the "shipping department" role automatically grants all permissions associated with that role, eliminating the need to manually configure individual permissions for each user across each resource.

Accounting, also called auditing, is the third AAA component. Once a user is authenticated and authorized, the system must record what they do. Accounting tracks when users logged in, what resources they accessed, what actions they performed, how much data they transferred, when they logged out, and from what location or device they connected. This creates an audit trail that supports incident response, forensic investigation, compliance reporting, and legal proceedings. Accounting data is typically collected through system logging (syslog), aggregated and analyzed by a SIEM (Security Information and Event Management) system, and retained for a period defined by the organization's log retention policy and applicable regulations.

AAA protocols are standardized systems that implement the AAA framework across network devices and services. The three most important are RADIUS, TACACS+, and DIAMETER.

RADIUS stands for Remote Authentication Dial-In User Service. Despite its name, RADIUS is used today for far more than dial-up connections. It is the most widely deployed AAA protocol for network access, including VPN authentication, wireless 802.1X authentication, and network device access. RADIUS uses UDP (User Datagram Protocol) for transport, with port 1812 used for authentication and authorization, and port 1813 used for accounting. A key characteristic of RADIUS is that it encrypts only the password field within the access-request packet; all other fields are transmitted in plaintext. This is a known security limitation. RADIUS uses a client-server architecture in which network devices such as VPN concentrators, wireless controllers, and network switches act as RADIUS clients that forward authentication requests to a central RADIUS server.

TACACS+ stands for Terminal Access Controller Access-Control System Plus. Despite sharing a name with older TACACS protocol variants, TACACS+ is a completely different, Cisco-proprietary protocol. TACACS+ uses TCP (Transmission Control Protocol) on port 49, making it more reliable than UDP-based RADIUS. The most significant difference from RADIUS is that TACACS+ encrypts the entire body of every packet exchanged between the client and server, not just the password. This provides greater security for the entire AAA conversation. TACACS+ also cleanly separates the three AAA functions into distinct processes, making it more flexible for scenarios where you want to use one server for authentication and a different server for authorization. TACACS+ is most commonly used for device administration, such as authenticating administrators logging into Cisco routers, switches, and firewalls.

DIAMETER is the successor to RADIUS, designed to address RADIUS's limitations. The name is a play on words: RADIUS refers to half a diameter, implying that DIAMETER is twice as capable. DIAMETER uses TCP or SCTP (Stream Control Transmission Protocol) rather than UDP, providing reliable delivery. It supports a much richer set of features, including support for mobile networking, roaming between service providers, and applications like 4G LTE and 5G mobile authentication. DIAMETER is commonly used by telecommunications carriers but is less common in enterprise IT environments, where RADIUS and TACACS+ remain dominant.

Directory services are the database back-end from which AAA systems retrieve user credentials and attributes. LDAP, which stands for Lightweight Directory Access Protocol, is the standard protocol for querying and modifying directory services such as Microsoft Active Directory and OpenLDAP. LDAP uses TCP port 389 for unencrypted queries. LDAPS (LDAP over SSL/TLS) uses TCP port 636 and encrypts the entire LDAP session for security. Active Directory stores user accounts, passwords, group memberships, computer accounts, and organizational unit (OU) structures. When a user logs into a Windows domain computer, the LDAP and Kerberos protocols work together to authenticate the user against Active Directory.

Kerberos is the authentication protocol used within Microsoft Active Directory environments and many Unix and Linux environments. Kerberos operates on TCP and UDP port 88. It uses a ticket-based system in which a trusted third party called the Key Distribution Center (KDC) issues tickets that users present to services rather than repeatedly sending passwords over the network. When a user logs in, they authenticate to the KDC and receive a Ticket Granting Ticket (TGT). When they want to access a specific service, they present their TGT to the KDC's Ticket Granting Service (TGS) and receive a service ticket for that specific resource. The service ticket is then presented to the target service to authenticate access. This approach means the user's password is only verified once at login, and all subsequent access uses cryptographically secure tickets that expire after a defined period.

Single Sign-On, or SSO, is an authentication pattern in which a user authenticates once and then gains access to multiple systems and applications without re-authenticating for each one. Kerberos in an Active Directory domain is one form of SSO. SSO reduces the burden on users, who only have to remember one set of credentials, and reduces the risk from credential fatigue, which occurs when users create weak passwords because they have too many to remember.

Federation extends SSO across organizational boundaries. When two separate organizations establish a trust relationship, users from one organization (the identity provider) can access resources in the other organization (the service provider) without needing separate credentials in the second organization. SAML (Security Assertion Markup Language) is an XML-based standard for exchanging authentication and authorization data between identity providers and service providers, widely used for enterprise web application SSO. OAuth (Open Authorization) is a framework for delegated authorization that allows a user to grant a third-party application limited access to their account on another service without sharing their credentials. OpenID Connect (OIDC) is an identity layer built on top of OAuth 2.0 that adds authentication functionality, enabling SSO across web applications. These three protocols, SAML, OAuth, and OIDC, form the foundation of modern federated identity and cloud application access management.
