Data does not exist in a single static condition. At any given moment, information within an organization is in one of three distinct states, and each state presents its own threat landscape and requires its own protective measures. The three states of data are data at rest, data in transit, and data in use. Security professionals must understand all three states because attackers choose their attack vector based on where data is most vulnerable, and the Target Corporation breach of 2013, in which 110 million credit card numbers were stolen from point-of-sale terminal memory, demonstrated that protecting data in only two of the three states provides incomplete security. A comprehensive data protection strategy requires appropriate controls applied to each state simultaneously.

Data at rest refers to any data that is stored on a physical or virtual storage medium and is not actively being transmitted or processed. Hard drives, solid-state drives, USB flash drives, magnetic tape, optical media, network-attached storage arrays, cloud storage buckets, mobile device storage, and database servers all hold data at rest. The defining characteristic is that the data is persistently stored and not currently moving between systems or loaded into processor memory. The security of data at rest depends primarily on two controls: encryption and access control.

Encryption of data at rest renders the stored data unreadable to any party that does not possess the decryption key, meaning that physical theft or unauthorized access to the storage medium does not result in a meaningful breach. The standard for sensitive data at rest is AES-256, the Advanced Encryption Standard with a 256-bit key, which is computationally infeasible to brute-force with current and foreseeable technology. Encryption can be applied at different granularities. Full disk encryption, such as BitLocker on Windows or FileVault on macOS, encrypts every sector of the storage device, protecting all data including the operating system, swap space, and temporary files. Database encryption can be implemented at the column level, encrypting specific sensitive fields such as Social Security numbers and credit card numbers within database tables while leaving non-sensitive fields unencrypted for performance efficiency. File-level and folder-level encryption allows selective encryption of specific files without encrypting the entire volume. Operating systems provide native capabilities for all these approaches, and dedicated hardware devices called self-encrypting drives perform encryption automatically in the drive firmware without software overhead.

Access controls for data at rest work alongside encryption. File system permissions define which users and processes can read, modify, or delete stored files. Database access controls restrict which application accounts and database users can query specific tables or columns. Role-based access control assigns permissions based on job function, ensuring that a payroll clerk can access salary records but not healthcare records, even though both datasets may reside on the same server. Operating systems allow both individual account permissions and group-level permissions, providing flexibility in managing access at scale.

Physical security protects data at rest against the threat of media theft. Server rooms and data centers require physical access controls, including badge readers, biometric authentication, man traps, and video surveillance. Backup media, which contains copies of all the sensitive data on primary systems, is equally valuable to an attacker and must receive equivalent physical protection. Backup tapes transported off-site for disaster recovery purposes are particularly vulnerable during transit, because they leave the physical security perimeter of the organization. Encrypting backup media before transport means that even if tapes are stolen from a vehicle or courier, the data they contain is unreadable.

Cloud storage introduces a specific threat to data at rest: misconfiguration. Amazon S3 buckets, Azure Blob Storage containers, and Google Cloud Storage buckets that are inadvertently configured for public access have exposed vast quantities of sensitive data in high-profile breach incidents. Cloud data at rest protection requires that organizations verify storage bucket permissions, enable default encryption for all objects stored in cloud services, use customer-managed encryption keys where possible, and implement continuous compliance monitoring to detect configuration drift.

Data in transit, also called data in motion, refers to data actively traveling across any network, whether an internal local area network, a wide area network, a wireless network, the public internet, or a dedicated circuit. Any time a user loads a web page, submits a form, sends an email, transfers a file, synchronizes a cloud backup, or queries a remote database, data is in transit. The fundamental threat to data in transit is network interception. An attacker with access to any network segment between sender and receiver can use packet capture tools to read unencrypted traffic. This threat is particularly acute on wireless networks, public Wi-Fi, and any network segment where the attacker has physical or logical access.

Encryption of data in transit makes intercepted traffic useless to the attacker because they capture ciphertext rather than plaintext. Transport Layer Security, specifically TLS version 1.2 or 1.3, is the universal standard for encrypting web and API traffic. HTTPS is simply HTTP traffic carried over a TLS-encrypted connection. TLS 1.3 is preferred over TLS 1.2 because it removes support for cipher suites with known weaknesses, mandates forward secrecy, and reduces connection establishment latency. SSH, the Secure Shell protocol, encrypts administrative sessions used to manage servers remotely, replacing the insecure Telnet protocol. IPsec, the Internet Protocol Security suite, encrypts traffic at the network layer and is the foundation of most site-to-site and client VPN implementations. S/MIME and PGP provide end-to-end encryption for email, protecting message content from interception at any point between sender and recipient.

On-path attacks, historically called man-in-the-middle attacks, represent an elevated threat to data in transit beyond passive eavesdropping. In an on-path attack, the attacker positions themselves between communicating parties and relays traffic while having the ability to read and potentially modify it. Certificate validation is the primary defense against on-path attacks in TLS-protected communications. When a client connects to a server, the server presents a digital certificate issued by a trusted certificate authority. The client validates the certificate's authenticity, the validity period, and the chain of trust back to a root certificate authority before establishing the encrypted session. HTTP Strict Transport Security, abbreviated HSTS, instructs browsers to refuse unencrypted connections to a site for a defined period, preventing SSL stripping attacks that attempt to downgrade HTTPS connections to HTTP. Replay attacks, in which an attacker captures a legitimate encrypted session and retransmits it to impersonate the original sender, are defeated by TLS sequence numbers and session keys that are unique to each connection.

VPNs protect data in transit for users accessing organizational resources from external networks. A client VPN creates an encrypted tunnel from the user's device to the organizational network, ensuring that all traffic traverses a protected path even when the underlying network, such as a public coffee shop Wi-Fi, is untrusted. Site-to-site VPNs connect entire networks at different geographic locations over encrypted tunnels, replacing the need for expensive dedicated WAN circuits.

Data in use refers to data that is actively being processed by a CPU, loaded into RAM, displayed on a screen, or manipulated by an application. This state is the most difficult to protect because data must be decrypted and accessible to the processor to be processed. The protection mechanisms applied to data at rest and in transit do not apply to data in use: a fully encrypted database must decrypt records before presenting them to an application, and a TLS-encrypted connection delivers plaintext to the application layer after decryption. This creates a window of vulnerability that attackers specifically target.

Memory scraping attacks involve malicious code reading the contents of system RAM to extract sensitive data while it is in the clear. The Target breach exemplified this: attackers installed custom malware on point-of-sale terminals that scraped payment card data from memory at the moment it was decrypted for processing, bypassing all encryption on the data in transit and at rest. Data Execution Prevention and the NX bit in CPUs prevent data regions of memory from being executed as code, limiting some attack vectors. Address Space Layout Randomization randomizes the memory addresses at which system components and libraries are loaded, making it significantly harder for attackers to locate target data structures in memory for exploitation.

Cold boot attacks exploit the physical properties of DRAM memory, which retains its contents for seconds to minutes after power is removed, particularly when the RAM is cooled. An attacker with physical access to a system can abruptly remove power, rapidly cool the RAM modules, transfer them to a different system, and image the memory contents. This attack can extract full disk encryption keys that were loaded in RAM during operation. Countermeasures include memory encryption technology present in newer processors, physical security controls to prevent access to systems, and configuring systems to clear memory on shutdown.

Shoulder surfing is a low-technology attack against data in use in which an adversary reads sensitive information from a user's screen by viewing it directly or with optical aids. Privacy screens, physical screen filters that limit the viewing angle, mitigate this threat in public environments such as airports and coffee shops. Screen capture malware records or transmits images of the screen contents, potentially capturing sensitive data being viewed or entered. Hardware keyloggers, small devices inserted between keyboard and system, and software keyloggers running in the background capture keystrokes including passwords and sensitive data as users type it. Clipboard hijacking malware monitors the system clipboard, reading sensitive data that users copy and paste, such as passwords from password managers or account numbers from documents.

Hardware-based trusted execution environments provide the most robust protection available for data in use by creating isolated, encrypted memory enclaves where code and data are protected even from the operating system and hypervisor. Intel Software Guard Extensions, abbreviated SGX, allows applications to designate specific regions of memory as secure enclaves. Code and data inside an SGX enclave are encrypted by the CPU and cannot be read by any other process, the operating system, or the hypervisor, even if those components are compromised. AMD Secure Encrypted Virtualization encrypts the memory of individual virtual machines using keys managed by the processor, preventing the hypervisor from reading VM memory contents. This is particularly valuable in multi-tenant cloud environments where the cloud provider operates the hypervisor. Apple's Secure Enclave, a dedicated security processor in iOS and macOS devices, stores cryptographic keys for biometrics and payment systems in isolated hardware where they cannot be extracted even with full software access to the device.

Homomorphic encryption represents a theoretical approach to protecting data in use by enabling computation on encrypted data without decrypting it. If practical at scale, homomorphic encryption would allow cloud services to process sensitive data and return results without ever seeing the underlying plaintext, fundamentally changing the security calculus for data in use. Current homomorphic encryption implementations are orders of magnitude slower than standard computation, limiting their practical application, but ongoing research is progressively improving performance.

Data sovereignty intersects with all three states of data. Where data is physically stored when at rest determines which legal jurisdiction's laws govern it. Data in transit may cross national borders, potentially subjecting it to interception by foreign intelligence services or to legal requirements of the transit countries. GDPR's provisions governing cross-border transfers of personal data require that data transferred outside the European Economic Area be protected by mechanisms such as Standard Contractual Clauses or Adequacy Decisions that ensure equivalent protection to that required within the EU.

Key management is critical across all states of data. Encryption is only as strong as the protection of the keys used for encryption. Hardware Security Modules provide tamper-resistant, dedicated key storage that prevents key extraction even by administrators with full system access. Key rotation policies limit the amount of data exposed if a key is compromised. Key escrow arrangements ensure that encrypted data can be recovered if a key is lost. Separating key storage from encrypted data storage prevents an attacker who obtains one from immediately compromising the other.

The data lifecycle encompasses creation, storage, use, sharing, archiving, and destruction. Security controls must be applied at each stage. When data is created or collected, it must be classified and labeled immediately. When stored, encryption and access controls must be applied. When in use, trusted execution environments and least-privilege access limit exposure. When shared or transmitted, encryption of data in transit is mandatory. When archived for long-term retention, encryption and access controls must be maintained. When destruction is appropriate, secure deletion or physical destruction must be verified and documented. A gap in protection at any stage of the lifecycle creates a vulnerability that attackers can exploit.
