Protecting data requires a layered strategy that addresses the multiple ways sensitive information can be exposed, stolen, or misused. No single control is sufficient. Organizations that rely solely on perimeter security, or solely on encryption, or solely on access controls, will find that determined adversaries can breach the one layer they have relied upon. The Security+ exam tests knowledge of a comprehensive toolkit of data protection techniques, and practitioners must understand when each tool is appropriate, how it works mechanically, and what threats it is designed to counter.

Data Loss Prevention, universally abbreviated DLP, is a category of technology designed to identify, monitor, and control the movement of sensitive data to prevent unauthorized disclosure. DLP systems apply policy rules that define what constitutes sensitive data, using mechanisms such as regular expression pattern matching for structured data like credit card numbers and Social Security numbers, keyword lists for domain-specific sensitive terms, document fingerprinting for specific files, and machine learning classifiers for unstructured sensitive content. When DLP detects policy-violating data movement, it can take actions ranging from logging and alerting to quarantining and blocking, depending on the configured response.

Network DLP operates inline between users and the internet or between network segments, inspecting outbound traffic for sensitive data patterns. When a user attempts to send an email containing sixteen digit numbers matching the Luhn algorithm for credit card validation, a network DLP system can intercept that email, quarantine it for review, and alert a security administrator, all before the message leaves the organization. Network DLP also monitors web uploads, file transfers, cloud synchronization traffic, and FTP connections. Because network DLP operates on all traffic passing through a chokepoint, it provides broad coverage but may not inspect encrypted traffic without TLS inspection capabilities.

Endpoint DLP operates through software agents installed on individual workstations and laptops. These agents monitor activities at the device level, including files being copied to USB storage devices, data being attached to email in client applications, content being uploaded through web browsers, print jobs being sent to local or network printers, and screen captures. Endpoint DLP can block a user from copying a file containing PII to a USB drive, even if the user has local administrator rights, because the DLP agent intercepts the operation at the file system level. This makes endpoint DLP effective against both malicious insiders deliberately exfiltrating data and well-intentioned employees who inadvertently move sensitive data to unsecured storage.

Cloud DLP integrates directly with cloud service providers and software-as-a-service applications. Cloud DLP can scan cloud storage buckets for sensitive data that should not be stored there, monitor access to sensitive files in cloud collaboration platforms, and enforce policies on sharing and downloading of sensitive content. Google Cloud DLP, Microsoft Purview, and similar offerings allow organizations to extend their on-premises DLP policies into cloud environments where traditional network inspection is not applicable.

Information Rights Management, often called IRM or Digital Rights Management in the consumer context, takes a fundamentally different approach to data protection by embedding persistent access controls directly into the document or file itself. Where traditional access controls protect the container where a file is stored and become irrelevant once the file is copied outside that container, IRM encrypts the file and attaches usage rights that travel with the file wherever it goes. An IRM-protected document might allow the recipient to view the content but not print it, copy text from it, or forward it to others. Documents can be configured to expire on a specific date, after which they are automatically rendered unreadable. Some implementations enforce geographic restrictions, preventing documents from being opened outside approved countries. Microsoft Purview Information Protection and Adobe PDF DRM are widely deployed commercial IRM implementations. The critical distinction for exam purposes is that access controls protect where data is stored, while IRM protects the data itself regardless of where it travels.

Access controls are the foundational mechanism for limiting who can read, modify, create, or delete data. Role-Based Access Control assigns permissions based on the job role of the user. A database administrator role receives administrative database permissions, while a read-only analyst role receives only select query rights on specific tables. When a user changes jobs, their role assignment changes, automatically adjusting their access without requiring individual permission changes. Attribute-Based Access Control extends role-based control by incorporating additional context into access decisions, including user attributes such as department and clearance level, resource attributes such as data classification and sensitivity level, and environmental attributes such as time of day and user location. Discretionary Access Control, implemented in file systems through NTFS permissions on Windows and POSIX permissions on Linux, allows data owners to set permissions on their own files. Mandatory Access Control uses classification labels to control access, enforcing that only users with the appropriate clearance level and need-to-know can access data labeled at a given classification. The principle of least privilege requires that users receive only the minimum access necessary for their legitimate job functions. Separation of duties requires that sensitive operations, such as initiating and approving a financial transaction, be divided between different individuals to prevent any single person from abusing their access undetected.

Encryption remains the most fundamental data protection control. AES-256 is the standard for data at rest, providing symmetric encryption that is computationally infeasible to break with current technology. TLS 1.3 protects data in transit. Key management is as important as the encryption algorithm itself, because encryption whose keys are poorly managed provides much weaker protection than its mathematical strength suggests. Hardware Security Modules provide tamper-resistant storage for cryptographic keys, ensuring that keys cannot be extracted even by administrators with full access to the systems those keys protect. Key rotation policies specify how frequently encryption keys are changed, limiting exposure if a key is compromised. Key escrow stores copies of encryption keys with a trusted third party or in a separate secure location, ensuring data can be recovered if a primary key is lost.

Database security deserves specific attention because databases are typically the highest-value targets for attackers, concentrating large quantities of sensitive data in a single location. Transparent Data Encryption encrypts the database files on disk at the storage layer, ensuring that anyone who obtains the database files without going through the database engine cannot read the data. TDE is implemented in major database platforms including Microsoft SQL Server, Oracle Database, and MySQL. Column-level encryption applies encryption to specific sensitive fields within database tables, such as Social Security number and credit card number columns, rather than encrypting the entire database. Column-level encryption provides finer granularity and may be preferable when only specific fields are sensitive while other data in the same tables must be accessible for analytics without decryption overhead.

Database Activity Monitoring provides real-time surveillance of all queries and operations against a database, alerting on unusual access patterns that may indicate a data breach or insider threat. A DAM system can detect a database account that suddenly runs queries returning thousands of rows where it normally retrieves only individual records, a pattern consistent with bulk data exfiltration. DAM can also detect SQL injection attempts, privilege escalation operations, and access to tables outside the normal scope of a user's job function. Database user management is also critical: applications should connect to databases using accounts with only the minimum permissions required for their function, typically restricted to specific stored procedures rather than direct table access. DBA accounts used for administrative tasks should be separate from application accounts and should require multi-factor authentication.

Data masking replaces real sensitive data with realistic but fictitious substitute data. Organizations use static data masking to create copies of production databases with masked data for development and testing environments, ensuring that developers never work with real customer PII or payment card data. Dynamic data masking applies substitution at query time, returning masked values to users without the required access level while returning real values to authorized users querying the same table. Masking preserves the format and referential integrity of the data so that applications behave correctly with masked data, allowing realistic testing without exposing real sensitive information.

Tokenization replaces sensitive data values with randomly generated substitute values called tokens, with the mapping between the token and the original value stored in a secure token vault. Tokenization is extensively used in payment card processing to reduce PCI DSS scope. When a customer's payment card is processed, the card number is replaced with a token that is stored in the merchant's systems. The token has no mathematical relationship to the original card number and is useless if stolen. The real card number is stored only in the token vault operated by a payment processor or specialized tokenization service provider. Because the merchant's systems store only tokens rather than actual PANs, vast portions of their infrastructure are removed from PCI DSS scope, significantly reducing compliance burden and the value of a breach.

Privacy-enhancing technologies represent a growing category of approaches that enable useful work with sensitive data while protecting individual privacy. Differential privacy adds carefully calibrated mathematical noise to aggregate statistical results, allowing analysts to query datasets and receive accurate aggregate statistics while preventing the mathematical reconstruction of any individual's specific data. Differential privacy is used by Apple and Google to collect usage statistics from user devices without being able to identify individual user behavior. K-anonymity ensures that any record in a dataset is indistinguishable from at least k minus one other records based on quasi-identifier fields, preventing re-identification through those quasi-identifiers. Federated learning allows machine learning models to be trained on distributed data that never leaves its original location, with only model parameter updates rather than raw data being shared.

Data minimization is a privacy principle requiring that organizations collect only the personal data that is strictly necessary for the specific purpose for which it is collected, retain it only for as long as necessary to fulfill that purpose, and delete it when it is no longer needed. GDPR enshrines data minimization as a core requirement. From a security perspective, data minimization reduces the potential impact of a breach by ensuring that data no longer needed is not retained as an ongoing liability.

Secure data disposal is the final stage of the data lifecycle and requires as much attention as protection during the active lifecycle. NIST Special Publication 800-88, Guidelines for Media Sanitization, provides the authoritative framework for data disposal. Clear is the first sanitization level, using software overwriting techniques to overwrite data with new values, making data recovery by standard means infeasible. Clear is appropriate for data that is not particularly sensitive and for media that will be reused within the organization. Purge is a more thorough sanitization that uses techniques including multiple-pass overwriting, degaussing for magnetic media, and cryptographic erase commands on self-encrypting drives, making data recovery infeasible even using laboratory techniques. Purge is appropriate for sensitive data and for media being transferred outside organizational control. Destroy is the most thorough disposal method, involving physical destruction of the media through shredding, disintegrating, melting, incinerating, or pulverizing to render it completely unusable. Destroy is required for the most sensitive data and for media that is too badly damaged to be reliably sanitized through purging.

Cryptographic erasure is a disposal technique particularly relevant for encrypted SSDs and cloud storage. Rather than overwriting all data, cryptographic erasure destroys the encryption key that was used to encrypt all data on the medium. Without the key, the encrypted data is computationally indistinguishable from random noise and cannot be recovered. Cryptographic erasure is typically much faster than software overwriting for large drives and is particularly useful for SSDs, where wear-leveling algorithms can make complete overwriting difficult to guarantee. Organizations that contract with cloud providers or storage vendors for disposal of physical media should obtain certificates of destruction documenting the sanitization method used and attesting that disposal was performed in compliance with the organization's requirements.

Cloud data protection requires understanding the shared responsibility model. Cloud providers encrypt data at rest on their infrastructure using provider-managed keys, but this protects data from physical media theft and some insider threats at the provider, not from the provider itself or from compromised provider credentials. Bring-your-own-key arrangements allow customers to supply and manage their own encryption keys within the cloud provider's key management infrastructure, ensuring that the provider cannot access customer data without the customer's cooperation. Client-side encryption, in which data is encrypted before it is uploaded to cloud storage, is the only approach that ensures the cloud provider has no ability to read the data under any circumstances, as the provider receives only ciphertext and never possesses the decryption keys.

Geographic restrictions and geolocation-based access controls supplement classification-based access controls by determining whether access to data is permitted based on the physical location of the requesting device. An organization may configure its data access policies to allow access to highly sensitive data only from devices within corporate facilities, using subnet-based geolocation for wired connections or GPS and wireless access point database lookups for mobile devices. Geofencing policies automatically apply different access permissions based on whether a user's device is inside or outside a defined geographic boundary, providing additional protection for sensitive data against access from untrusted locations.
