Mobile devices present a uniquely challenging security environment. They are compact enough to be concealed anywhere on a person, they move constantly across network boundaries ranging from corporate Wi-Fi to public hotspots to cellular networks, they carry sensitive personal and organizational data, and they are persistently internet-connected in ways that make remote attack a constant possibility. Managing mobile security requires a combination of technical controls, platform-enforced policies, and organizational governance frameworks. The Security+ exam addresses mobile device vulnerabilities across several categories: jailbreaking and rooting, sideloading, malicious apps, Bluetooth attacks, NFC attacks, Wi-Fi risks, SIM swapping, and mobile device management.

Jailbreaking refers to the process of removing manufacturer-imposed software restrictions on iOS devices. Apple's iOS is designed as a closed ecosystem where all applications must be installed from the App Store and all code must be signed by Apple-approved developers. Jailbreaking exploits vulnerabilities in iOS to replace or circumvent the kernel security features that enforce these restrictions, enabling the installation of applications from outside the App Store, disabling code-signing enforcement, bypassing the application sandbox that isolates apps from each other and from the operating system, and circumventing MDM controls. A jailbroken device is also vulnerable to malware that never underwent App Store security review. The Secure Enclave, Apple's dedicated security processor that protects biometric data and cryptographic keys, may also have its protections weakened by some jailbreak techniques. MDM solutions can detect jailbroken status through integrity checks and respond by blocking access to corporate resources, requiring remediation before re-enrollment.

Rooting is the Android equivalent of jailbreaking — gaining root-level administrator privileges on an Android device. Android's more open ecosystem means that rooting is generally easier to accomplish, custom replacement operating systems called ROMs are widely available, and the security implications are comparable to jailbreaking. A rooted device running a custom ROM may lack the security patches present in the manufacturer's official builds or may have SELinux — Android's mandatory access control system — disabled. Android's inherent fragmentation compounds this: because many manufacturers are slow to release OS updates for older device models, large numbers of Android devices in production use remain on OS versions containing known vulnerabilities for which patches exist on newer versions but not for the specific hardware in question.

Sideloading is the installation of applications from sources other than the official platform app store. On Android, sideloading is enabled by default through the ability to install APK files directly, and users must explicitly grant permission to install from unknown sources — a permission that many users grant without understanding the implications. On iOS, sideloading without jailbreaking is not possible for the general population, though enterprise distribution and TestFlight provide legitimate limited exceptions for managed devices and beta testing respectively. Sideloaded applications bypass platform security review and may contain malware, excessive permission requests, or hidden functionality that would cause rejection from official stores.

Malicious applications that pass initial store review represent a persistent threat even within official app stores. Platform security teams review submissions, but review processes are not perfect and review can be bypassed through delayed activation of malicious functionality or dynamic code loading. Common malicious behaviors include requesting far more permissions than the application's stated functionality requires — a flashlight app requesting access to contacts, SMS, microphone, camera, and precise location harvests data without providing legitimate reasons for those accesses. Premium SMS fraud silently subscribes users to paid text messaging services. Banking trojans monitor device activity for access to financial applications and overlay fake login screens to harvest credentials. Ad fraud applications generate fake advertising clicks. Users should scrutinize permission requests during installation, preferring to deny permissions that do not align with the application's stated purpose.

Mobile operating systems themselves contain vulnerabilities exploited in sophisticated targeted attacks. The Pegasus spyware developed by the NSO Group exploited a series of iOS zero-click vulnerabilities — meaning no user interaction was required for infection — to surveil journalists, activists, and government officials worldwide. The Stagefright family of vulnerabilities in Android's media processing library allowed code execution by sending a crafted multimedia message that was processed automatically without the recipient opening it. These nation-state-grade capabilities demonstrate that even users who follow every best practice can be compromised by sufficiently resourced adversaries targeting the platform itself.

Bluetooth attacks exploit the short-range wireless protocol that connects accessories, headsets, keyboards, and peripherals to mobile devices. Bluejacking sends unsolicited messages to nearby Bluetooth-enabled devices and is primarily a nuisance rather than a data theft vector. Bluesnarfing exploits the OBEX Push Protocol to gain unauthorized access to a Bluetooth device's data — contacts, calendar entries, messages, and files — without the device owner's knowledge or consent. Bluebugging escalates further to full remote control of the target device, enabling the attacker to make calls, send messages, and access data. The Blueborne vulnerabilities disclosed in 2017 were a family of flaws in Bluetooth protocol stack implementations across multiple operating systems and device types that allowed unauthenticated code execution and worm-like propagation between devices in Bluetooth range without any pairing requirement. Bluetooth Low Energy, used in fitness trackers, medical devices, and IoT sensors, introduces its own vulnerability surface. Disabling Bluetooth when not in use eliminates the wireless attack surface entirely.

Near field communication attacks exploit the very short-range wireless communication used for contactless payment and access control. Relay attacks use two devices to extend the effective range of an NFC transaction: one device positioned near the legitimate card intercepts the NFC communication and relays it over a longer-range channel to a second device positioned near the payment terminal, enabling fraudulent transactions while the real card remains in the victim's pocket. Card emulation attacks use a device programmed to impersonate a legitimate card using previously captured data.

Wi-Fi risks for mobile devices include automatic reconnection to familiar network names without verifying the network is the legitimate one. An attacker who creates a wireless access point using the same SSID as a network the target device has previously connected to — called an evil twin access point — may cause the device to automatically associate and route all traffic through the attacker's infrastructure. Open Wi-Fi networks at airports, coffee shops, and hotels transmit all unencrypted traffic in the clear, and captive portal pages may serve malicious content. Using a VPN on untrusted networks mitigates most Wi-Fi risks by encrypting all traffic before it leaves the device.

The SS7 signaling protocol underpins telecommunications infrastructure globally and contains vulnerabilities that allow attackers with access to the signaling network — typically governments, criminal groups, or insiders at telecom operators — to intercept SMS messages and track device location. This has practical consequences because SMS-based two-factor authentication depends on the assumption that an SMS message can only be received by the legitimate device owner. SS7 attacks break this assumption. SIM swapping, also called SIM hijacking, is a social engineering attack against the mobile carrier rather than the device itself. The attacker contacts the victim's carrier, impersonates the victim using personally identifiable information gathered from social media or prior data breaches, and convinces a customer service representative to transfer the victim's phone number to a SIM card the attacker controls. From that point, the attacker receives all voice calls and SMS messages intended for the victim, including authentication codes from banks, email providers, and other high-value services. Defenses include establishing a carrier-level SIM lock or PIN that must be verified before any SIM change is processed, and replacing SMS-based MFA with authenticator apps or hardware security keys for high-value accounts.

Grayware refers to applications that are not overtly malicious but engage in privacy-invasive behaviors such as collecting and selling excessive data, displaying intrusive advertising, or making design choices intended to extract value from users without their meaningful understanding. Stalkerware is a related category: commercial applications marketed for monitoring spouses, partners, or children that operate covertly, hide themselves from the device's application list, and upload location, messages, and other data to the purchaser. These applications are increasingly recognized as tools enabling domestic abuse, and major platform operators have adopted policies restricting their promotion and distribution.

Mobile Device Management is the organizational technology that enforces security policy across a fleet of mobile devices. MDM platforms can remotely enforce full-disk encryption, mandate screen lock with minimum PIN complexity, restrict which applications can be installed and from which sources, deploy corporate applications, revoke corporate data remotely through selective or full device wipe when a device is lost or stolen, require VPN use, detect jailbroken or rooted devices, and implement geofencing policies that restrict what actions are permitted based on device location. Mobile Application Management, a subset of MDM functionality, specifically manages the security of applications and their data without necessarily controlling the entire device, which is particularly relevant in bring-your-own-device scenarios. Organizations must choose between COPE, meaning corporate-owned and personally enabled devices that the organization fully controls, BYOD, which allows personal devices with limited MDM management, and CYOD, which allows employees to choose from a list of approved devices that are then managed as corporate equipment. Each model represents a different balance between user privacy, IT control, and organizational risk exposure.

For the Security+ exam, candidates should understand the security implications of jailbreaking and rooting, the difference between sideloading and official app store installation, the specific distinctions between Bluejacking, Bluesnarfing, and Bluebugging, how SIM swapping bypasses SMS-based MFA, and the capabilities and models of MDM deployment.
