Hardening is the process of configuring a system or device to reduce its attack surface and improve its security posture beyond the default out-of-the-box configuration. Default configurations prioritize ease of use and compatibility, not security. Hardening targets are the specific system types that require deliberate security configuration: mobile devices, workstations, switches, routers, cloud infrastructure, servers, industrial control systems, and Internet of Things devices. Each target type has a distinct hardening approach driven by its architecture, function, and threat model.

Mobile device hardening addresses a category of systems that users carry into untrusted environments, connect to unknown networks, and use for both personal and business purposes. Enforcing device encryption is the first requirement — both iOS and Android support full-device encryption natively, but encryption must be enabled and enforced through Mobile Device Management policy to ensure it is actually active on enrolled devices. A PIN or biometric screen lock with an auto-lock timeout must be required so that a lost or stolen device is not immediately accessible to anyone who finds it. MDM enrollment is essential because it provides the management platform through which all other policies are delivered, monitored, and enforced — without MDM enrollment, the organization has no reliable way to assess or control the security posture of a mobile device accessing corporate resources. Developer mode and USB debugging, known as ADB on Android, must be disabled because these modes bypass security protections designed for production use and enable unauthorized code execution and data extraction. VPN use should be enforced on untrusted networks, and MDM platforms can push per-app VPN configurations that automatically route traffic from corporate applications through an encrypted tunnel. Remote wipe capability must be configured and tested so that when a device is reported lost or stolen, IT can erase corporate data promptly. Application installation should be restricted to approved sources — on iOS, supervised mode can prevent installation from outside the App Store entirely, while Android MDM policy can disable the unknown sources setting that permits sideloading. Geofencing capabilities can restrict device functionality based on geographic location, such as automatically disabling the camera when a device enters a facility where photography is prohibited. Bluetooth and NFC should be disabled when not actively in use, since both represent short-range wireless attack surfaces.

Workstation hardening focuses on removing unnecessary attack surface and enforcing security controls on the systems that most employees use daily. Removing local administrator rights from standard user accounts is one of the highest-impact hardening measures available, because the overwhelming majority of malware attacks succeed by exploiting the fact that the logged-in user has administrative privileges. When administrator rights are removed, malware executing in the user's context cannot install software, modify system files, or disable security tools. A separate administrative account should be used only when elevation is actually required. Endpoint detection and response software, often abbreviated EDR, must be deployed and active on all workstations to detect malicious behavior in real time and enable forensic investigation. The host-based firewall should be configured with a default-deny posture permitting only explicitly required inbound and outbound connections. Full-disk encryption using BitLocker on Windows or FileVault on macOS protects data when a laptop is lost or stolen. Screen lock should be enforced after a defined inactivity period and require authentication to resume. USB storage ports should be disabled when not operationally required, because removable storage is a common vector for both data exfiltration and malware introduction. Application allowlisting through Windows Defender Application Control, known as WDAC, or AppLocker allows only pre-approved executables to run, blocking most malware and unauthorized software regardless of how it arrives on the system. PowerShell Constrained Language Mode limits the capabilities of PowerShell scripts and reduces the effectiveness of script-based attacks. Secure Boot should be enabled in the UEFI firmware to prevent bootkit malware from loading before the operating system.

Switch hardening addresses the network devices that form the foundation of local area network infrastructure. The default VLAN, VLAN 1, is used by many switches as the native VLAN for trunk links and must be changed to a different VLAN because VLAN hopping attacks exploit default VLAN configurations. Unused switch ports should be administratively disabled and placed in a parking VLAN that has no connectivity to any production network, preventing unauthorized devices from simply plugging in and gaining network access. Port security should be configured on access ports to limit the number of MAC addresses permitted on each port and optionally to restrict access to specific known MAC addresses, limiting the damage if an unauthorized device is connected. DHCP snooping prevents rogue DHCP servers from distributing false IP configuration information to clients by building a trust table of legitimate DHCP servers and dropping DHCP responses from untrusted ports. Dynamic ARP Inspection uses the DHCP snooping binding table to validate ARP packets and prevent ARP poisoning attacks where an attacker associates their MAC address with a legitimate IP address to intercept traffic. BPDU Guard should be enabled on all access ports to prevent an attacker from connecting a switch and attempting to become the Spanning Tree root bridge, which would give the attacker control over the Layer 2 topology. Cisco Discovery Protocol should be disabled on access ports facing user devices because it advertises platform details including software version and capabilities that an attacker can use for reconnaissance. Dynamic Trunking Protocol should be disabled or set to off mode on all access ports to prevent VLAN hopping attacks that rely on negotiating a trunk link. SNMPv3 with authentication and encryption must replace older SNMP versions that transmitted community strings in cleartext. Telnet must be disabled in favor of SSH for all device management access.

Router hardening protects the devices that make Layer 3 forwarding decisions and often sit at key network boundaries. IP directed broadcasts allow attackers to send a single packet that the router will broadcast to all hosts on a target subnet — disabling this feature mitigates smurf amplification attacks. ICMP redirects should be disabled because they can be used to manipulate the routing decisions of hosts, directing traffic through an attacker-controlled path. Proxy ARP should be disabled unless specifically required because it causes the router to answer ARP requests on behalf of devices on other subnets, which can enable man-in-the-middle attacks in certain configurations. Ingress and egress filtering using access control lists prevents traffic with spoofed source addresses from entering or leaving the network. Dynamic routing protocols such as OSPF should be configured to authenticate routing updates using MD5 or SHA authentication to prevent route injection attacks where an attacker injects false routing information to redirect traffic. All unused routing protocols and services should be explicitly disabled. Management access should be restricted to specific known source IP addresses, typically a dedicated management network, and a login banner should be configured to provide legal notice that unauthorized access is prohibited.

Cloud infrastructure hardening applies the principle of minimum attack surface to infrastructure resources in public cloud environments. The Center for Internet Security publishes CIS Benchmarks for AWS, Microsoft Azure, and Google Cloud Platform that provide specific hardening guidance for cloud-native services. CloudTrail in AWS and Azure Monitor provide audit logging of all API calls and configuration changes, which must be enabled to support security monitoring and incident response. Threat detection services such as AWS GuardDuty and Microsoft Defender for Cloud analyze logs and activity for indicators of compromise and should be enabled. Security groups and network security groups must be configured with restrictive rules — allowing port 22 or 3389 from any source using 0.0.0.0/0 is a critical misconfiguration that directly exposes management interfaces to the entire internet. Multi-factor authentication must be enforced for all accounts, especially root and global administrator accounts that have the highest privileges. S3 Block Public Access settings in AWS prevent storage buckets from being accidentally exposed to public internet access. Encryption must be enforced at rest using cloud-native encryption services and in transit using TLS. VPC Flow Logs capture network traffic metadata that is essential for security monitoring and incident investigation. Access keys and service account credentials should be rotated regularly and IAM roles with temporary credentials should be preferred over long-lived access keys. AWS Config rules and Azure Policy provide continuous compliance checking against defined security standards.

Server hardening reduces the attack surface of operating system instances that provide business services. Servers should run under minimally privileged service accounts rather than the highest-privilege system accounts unless specifically required by the application. Unnecessary server roles and features should be removed — a web server should not have the print spooler or desktop experience features installed. Services that are not required for the server's function should be disabled. Network Time Protocol synchronization must be properly configured because accurate time is critical for Kerberos authentication, log correlation, and forensic investigation. Windows Defender Credential Guard protects NTLM hashes and Kerberos tickets in memory from extraction by tools like Mimikatz by isolating credential material in a virtualization-based security container. Linux file systems can be mounted with the noexec option to prevent execution of binaries from mounted filesystems and with nosuid to prevent setuid programs on those filesystems from running with elevated privileges.

Industrial Control System and SCADA hardening presents unique challenges because these environments prioritize availability over security, run proprietary operating systems and applications with long update cycles, and often cannot be patched during operations without risking production disruption. Compensating controls are essential in these environments. Network segmentation using a dedicated operational technology DMZ separates ICS networks from corporate IT networks, limiting the blast radius if the IT network is compromised. Unidirectional security gateways or data diodes enforce one-way data flow from the OT network to the IT network, making it physically impossible for an attacker on the IT network to send commands to OT systems. Application allowlisting configured specifically for control system applications prevents unauthorized software from executing. USB ports should be controlled or disabled to prevent introduction of malware through removable media. Specialized OT monitoring platforms such as Dragos and Claroty can monitor OT protocols and detect anomalous commands or device behavior without requiring agents on the fragile embedded systems.

Internet of Things hardening addresses devices such as smart cameras, sensors, building automation systems, and network-connected physical controls that often ship with poor security defaults and limited update capabilities. The most critical first step is changing default credentials before any IoT device is deployed, because attackers routinely scan the internet for devices using factory default usernames and passwords. A firmware update process must be established and followed to apply security patches when vendors release them. IoT devices should be segmented onto a dedicated VLAN that is isolated from sensitive data networks and internal systems, so that if an IoT device is compromised the attacker is confined to the IoT segment and cannot directly reach corporate resources. Unused features, services, and physical interfaces on IoT devices should be disabled. An inventory of all IoT devices including their manufacturer, model, firmware version, and expected lifecycle should be maintained so that end-of-support status can be tracked and devices can be replaced before they become unmanageable security liabilities.
