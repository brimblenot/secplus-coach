Wireless security protocols have evolved significantly over the decades since 802.11 networks became widespread, with each generation of protocols addressing weaknesses discovered in the previous one. Understanding the full history of wireless security protocols is essential for the Security+ exam because the exam tests knowledge of which protocols are acceptable, which are deprecated, and what specific vulnerabilities drove each transition.

Wired Equivalent Privacy, known as WEP, was the original 802.11 security protocol intended to provide security equivalent to a wired network. WEP used the RC4 stream cipher with either 40-bit or 104-bit keys combined with a 24-bit Initialization Vector. The fatal flaw in WEP was the short initialization vector space — with only 24 bits, the possible IV values were exhausted quickly on any moderately busy network, causing IV repetition. When the same IV is reused with RC4, mathematical analysis of the encrypted traffic reveals the keystream, which can then be used to derive the pre-shared key. Tools like aircrack-ng can crack WEP keys in minutes using passive traffic capture, making WEP completely unacceptable for any security purpose. WEP must never be used and is categorically forbidden in any environment with security requirements.

Wi-Fi Protected Access, known as WPA, was introduced as a transitional standard to address WEP's weaknesses without requiring complete hardware replacement. WPA used the Temporal Key Integrity Protocol, known as TKIP, which improved on WEP by using per-packet encryption keys derived from a master key through a mixing function, and added a message integrity check using the Michael algorithm. While TKIP addressed the key-scheduling weaknesses of WEP, it was designed to run on WEP-era hardware with firmware updates and therefore retained some architectural limitations. Weaknesses were later found in the Michael MIC algorithm and in the TKIP protocol itself. WPA with TKIP is deprecated and should not be used in any new deployments, though it may still be encountered on legacy hardware.

Wi-Fi Protected Access 2, known as WPA2, replaced WPA as the mainstream wireless security standard and is still widely deployed today. WPA2 introduced CCMP, the Counter Mode with CBC-MAC Protocol, which uses AES encryption rather than RC4. AES is a block cipher approved by NIST for protecting classified government information, making CCMP dramatically stronger than the RC4-based encryption used by WEP and WPA. The most significant vulnerability in WPA2 is the KRACK attack, discovered in 2017, which exploited weaknesses in the WPA2 four-way handshake process to allow an attacker in the communication path to decrypt traffic. KRACK was addressed through software patches on both client devices and access points. WPA2 also remains vulnerable to offline dictionary and brute-force attacks against pre-shared keys captured during the four-way handshake — an attacker who captures the handshake can take it offline and attempt to crack the pre-shared key at whatever speed their hardware supports.

Wi-Fi Protected Access 3, known as WPA3, is the current best wireless security standard and is the protocol organizations should deploy in new wireless infrastructure. WPA3 addresses the WPA2 handshake vulnerabilities through Simultaneous Authentication of Equals, known as SAE, which replaces the pre-shared key authentication used in WPA2-Personal. SAE is based on the Dragonfly key exchange algorithm, which is a variant of Diffie-Hellman key exchange. In SAE, both the client and the access point independently derive the session key using the pre-shared passphrase and a cryptographic exchange — the key itself is never transmitted over the air. This means an attacker who captures the WPA3 association exchange cannot take it offline and attempt to crack the pre-shared key, because there is no hash of the key in the captured traffic to attack. WPA3 also provides forward secrecy, meaning that compromise of the pre-shared key does not allow decryption of previously captured traffic, because each session uses a unique session key derived from that session's key exchange. WPA3-Enterprise mandates a 192-bit security suite for authentication and encryption, providing stronger security for environments protecting highly sensitive data. WPA3 also makes Protected Management Frames mandatory, which prevents management frame spoofing attacks including the deauthentication attacks that allow attackers to force clients to reconnect, potentially capturing authentication material.

WPA2 and WPA3 each operate in two modes. Personal mode, sometimes labeled PSK or Pre-Shared Key mode, uses a single passphrase shared among all users and devices on the network. Personal mode is appropriate for home and small business environments because it does not require any authentication infrastructure. The inherent weakness of Personal mode is that everyone uses the same passphrase: if one device is compromised or a current or former employee shares the passphrase, all traffic on the network is potentially exposed, and the only remediation is changing the passphrase on every device simultaneously. Enterprise mode, labeled 802.1X on access point configuration screens, authenticates each user individually using unique credentials verified by a RADIUS authentication server. Enterprise mode is the required choice for business environments because individual credentials mean that compromising one user's account does not expose any other user's traffic, and individual credentials can be revoked immediately when an employee leaves without requiring network-wide credential changes.

The 802.1X standard defines the framework for port-based network access control. The 802.1X process involves three roles. The supplicant is the client device attempting to connect to the network. The authenticator is the access point or switch that controls physical access to the network and mediates the authentication conversation. The authentication server, typically a RADIUS server, makes the actual authentication decision. When a supplicant attempts to connect, the authenticator places the port in an unauthorized state that permits only 802.1X traffic. The authenticator passes the supplicant's authentication credentials to the RADIUS server, which validates them against a directory such as Active Directory and returns an access-allowed or access-denied response. Upon successful authentication, the authenticator places the port in an authorized state and optionally assigns the supplicant to a specific VLAN based on the user's identity or group membership.

The Extensible Authentication Protocol, known as EAP, is the framework used within 802.1X to carry authentication information between the supplicant and the authentication server. EAP is extensible by design, supporting multiple specific authentication methods. EAP-TLS is the strongest EAP method: both the client and the authentication server authenticate using digital certificates issued by a trusted certificate authority. EAP-TLS completely eliminates password-based authentication, making it immune to password guessing and credential theft attacks, but it requires a certificate infrastructure capable of issuing and deploying client certificates to every device that needs network access. PEAP, which stands for Protected Extensible Authentication Protocol, creates an encrypted TLS tunnel between the supplicant and the authentication server, then uses MSCHAPv2 username and password authentication inside that protected tunnel. PEAP is more practical than EAP-TLS in environments that have not deployed client certificates, and is the most common EAP method in Windows enterprise environments. EAP-TTLS is similar to PEAP but supports a wider range of inner authentication methods inside the TLS tunnel including CHAP, PAP, and MS-CHAPv2, making it more flexible for multi-vendor environments. EAP-FAST is a Cisco-proprietary method that uses a Protected Access Credential, a cryptographic credential provisioned to each client, to establish a secure tunnel without requiring certificates on client devices.

CCMP, the Counter Mode with CBC-MAC Protocol, is the encryption and integrity mechanism used in WPA2 and WPA3. CCMP uses AES in counter mode for encryption, providing confidentiality, and uses AES in CBC-MAC mode for authentication and integrity verification, ensuring that the message has not been tampered with in transit. CCMP-256 uses 256-bit AES keys and is specified for use in WPA3-Enterprise with the 192-bit security suite. TKIP, the Temporal Key Integrity Protocol, should never be used in new configurations — it is the deprecated transitional encryption used in WPA and remains in some legacy devices for backward compatibility only.

RADIUS provides the centralized Authentication, Authorization, and Accounting framework that 802.1X enterprise wireless depends on. The AAA framework handles three distinct functions. Authentication verifies that the connecting user or device is who it claims to be, using credentials, certificates, or other factors. Authorization determines what resources and network segments the authenticated entity is permitted to access, often implemented through VLAN assignment based on user identity or group membership. Accounting maintains a record of connection sessions including start and end times, data transferred, and the identity of the authenticated user, supporting both billing and security audit requirements. In an enterprise wireless deployment, the access point acts as the RADIUS client forwarding authentication requests to the RADIUS server, which may itself communicate with a backend directory service such as Active Directory to validate credentials and retrieve group membership for authorization decisions.

Additional wireless security best practices reduce risk beyond the choice of authentication protocol. Disabling Wi-Fi Protected Setup, known as WPS, removes a significant vulnerability: WPS uses an eight-digit PIN for device enrollment, and because the PIN is verified in two halves, the effective PIN space is only 11,000 combinations, making brute-force attacks against WPS trivially fast. Using a strong unique passphrase of at least 20 randomly selected characters for WPA2-Personal substantially increases the difficulty of offline cracking attacks. Enabling management frame protection as defined by 802.11w prevents deauthentication and disassociation attack frames from being spoofed, eliminating one of the most common wireless denial-of-service and forced-reconnection attack techniques. Deploying separate SSIDs for corporate users, guest users, and IoT devices with different VLANs and security policies segments different trust levels while sharing the same physical access point infrastructure. A Wireless Intrusion Detection and Prevention System, abbreviated WIDS or WIPS, detects rogue access points, evil twin attacks, deauthentication floods, and other wireless attacks. Hidden SSIDs — configuring access points not to broadcast their SSID in beacon frames — provide only the illusion of security because the SSID is still visible in probe request and response frames when legitimate clients connect. Hidden SSIDs make the network invisible to casual users but are not a meaningful security control against any informed attacker. The 5 GHz band generally provides better security than 2.4 GHz because its shorter propagation range makes it harder to monitor from outside the building, though this is a secondary consideration compared to proper authentication and encryption configuration.
