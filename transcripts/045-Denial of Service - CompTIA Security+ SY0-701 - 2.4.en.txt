A denial of service attack occurs when an attacker deliberately overwhelms a system's resources to make it unavailable to legitimate users. The goal is not necessarily to break into a system but to prevent authorized users from accessing it, directly targeting the availability pillar of the CIA triad. Denial of service can be intentional or accidental. An administrator who inadvertently creates a network loop by connecting two switches to each other in a circle, without spanning tree protocol running, can take down an entire network segment. A user who downloads an enormous file over a limited bandwidth connection may consume all available capacity for production applications. Even a burst pipe above a data center can cause an unintentional denial of service. Intentional attacks, however, are the primary concern for security professionals.

A simple single-source denial of service attack sends so much traffic or so many requests to a target that the target's resources are exhausted. Attackers have found, however, that any one machine has limited bandwidth and a capable target can filter traffic from a single source IP address. To overcome these limitations, attackers evolved to the distributed denial of service, or DDoS, model. In a DDoS attack, the attacker coordinates hundreds, thousands, or even millions of devices located around the world to simultaneously send traffic toward a target. This makes filtering far more difficult because the attack traffic arrives from many source addresses across many geographic regions. Attackers build and maintain these armies of compromised machines, called botnets, by infecting devices with malware that allows remote command and control. The Zeus botnet, as one documented example, had over 3.6 million compromised machines under the operator's control at its peak. A single command from the botnet controller could instruct all of those devices to attack a target simultaneously. This asymmetric capability is what makes DDoS so powerful: an attacker with relatively modest infrastructure can bring down organizations with far greater resources and bandwidth.

Modern DDoS attacks are organized into three broad categories based on what layer of the network stack they target. Volumetric attacks aim to exhaust all available bandwidth by flooding the network with traffic. Protocol attacks consume the processing resources of servers and network devices such as firewalls and load balancers. Application layer attacks target specific functions within a web application or service, requiring far less raw bandwidth but causing significant disruption.

Volumetric attacks are the most straightforward to understand. A UDP flood sends large numbers of User Datagram Protocol packets to random ports on the target, forcing the host to process each one and generate ICMP Destination Unreachable replies, consuming bandwidth in both directions. An ICMP flood, sometimes called a ping flood, overwhelms the target with echo request packets. The most efficient volumetric attacks, however, exploit amplification, a technique that allows the attacker to send a small request and have a third-party server generate a much larger response directed at the victim. The attacker spoofs the victim's IP address as the source of the request, so the large response is automatically sent to the victim rather than back to the attacker.

DNS amplification is one of the most common and effective forms of amplification attack. The Domain Name System supports a query type that asks for all available records associated with a domain, which can produce a response many times larger than the query. When an attacker sends this small query to an open DNS resolver with the victim's IP spoofed as the source, the resolver sends back the large response to the victim. The amplification factor can be as high as 4,000 times, meaning a single gigabit per second of attack bandwidth directed at open resolvers can generate up to four terabits per second of traffic hitting the victim. NTP amplification exploits the monlist command in the Network Time Protocol, which returns a list of the last 600 clients that queried the server. This single small request can generate a response roughly 51,000 times larger than the query, making it one of the highest amplification factors available. Memcached amplification, exploiting the memcached caching system running over UDP, has demonstrated amplification factors in a similar range. By targeting publicly exposed memcached servers with spoofed requests, attackers have generated some of the largest DDoS attacks ever recorded. The operational model for a botnet-based amplification attack involves the attacker's command and control infrastructure instructing the botnet nodes to send spoofed DNS or NTP queries to lists of open resolvers, with the victim's IP address as the source. The resulting flood of amplified responses overwhelms the target without the attacker expending substantial outbound bandwidth.

Protocol attacks exploit weaknesses in TCP and other network protocol mechanics rather than simply filling up bandwidth. The SYN flood is the canonical example. The TCP three-way handshake requires a client to send a SYN packet, the server to respond with a SYN-ACK and allocate resources for the connection, and the client to complete the handshake with an ACK. In a SYN flood, the attacker sends enormous numbers of SYN packets using spoofed source IP addresses. The server allocates a half-open connection entry in its connection table for each one and waits for an ACK that will never come. When the connection table fills up, the server can no longer accept legitimate connections, causing a denial of service. SYN cookies are the primary defense against this attack: instead of maintaining state for half-open connections, the server encodes connection parameters into the initial sequence number of the SYN-ACK and only allocates resources once a valid ACK containing that encoded information is received, making it impossible for spoofed SYNs to exhaust the connection table. The Smurf attack, now largely mitigated on modern networks, sent ICMP echo requests to a network broadcast address with the victim's spoofed source IP. Every host on that network would send its echo reply to the victim, amplifying the attacker's single packet into a flood of replies.

Application layer attacks, sometimes called Layer 7 attacks, target the logic of web applications and services rather than network resources. An HTTP GET or POST flood sends enormous numbers of legitimate-appearing HTTP requests to the server, exhausting its ability to generate responses. Because the requests look valid, volumetric defenses that simply block traffic sources do not stop them without more sophisticated inspection. Slowloris is a particularly elegant application layer attack that requires minimal bandwidth. Rather than overwhelming the server with traffic, Slowloris opens many simultaneous TCP connections to the target and sends only partial HTTP request headers, pausing long enough between header lines to prevent the connection from timing out but never completing the request. Most web servers have a limit on the number of simultaneous open connections. When Slowloris exhausts this pool with incomplete requests, the server becomes unable to accept legitimate connections, causing a denial of service. A similar technique, the slow POST attack, sends HTTP POST requests with a legitimate Content-Length header indicating a large body, then delivers the body data one byte at a time, holding connections open indefinitely. DNS query floods directed at authoritative name servers can prevent a domain's names from resolving, effectively taking down all services under that domain without attacking the servers themselves.

Permanent denial of service, sometimes called phlashing, goes beyond temporary disruption and aims to damage the target hardware itself. An attacker who gains access to a device's firmware update mechanism can push a malicious firmware image that corrupts the hardware, requiring physical replacement. This has been demonstrated against industrial hardware and some network devices.

DDoS-for-hire services, also called booter or stresser services, allow anyone to purchase DDoS attacks against a target for relatively small amounts of money. This has lowered the barrier to launching large attacks significantly. Attackers also use DDoS as a smokescreen to distract security teams while a separate intrusion or data theft takes place on a different part of the network. Extortionists threaten DDoS attacks unless a ransom is paid, a practice sometimes called a ransom DDoS or RDoS campaign.

Defending against denial of service and distributed denial of service attacks requires a layered approach. Rate limiting restricts the number of requests any single IP address or connection can make per second, reducing the impact of unsophisticated floods. Traffic scrubbing services from providers such as Cloudflare, Akamai, and AWS Shield route all incoming traffic through global scrubbing centers that distinguish attack traffic from legitimate traffic using machine learning and behavioral analysis, then forward only clean traffic to the customer's infrastructure. Blackholing, sometimes called null routing, is a last resort where an ISP drops all traffic destined for the victim's IP address, stopping the attack but also stopping legitimate users. Anycast network diffusion routes attack traffic across a large distributed network of nodes, spreading the load so that no single point is overwhelmed. SYN cookies defend against SYN floods without maintaining state for half-open connections. Ingress filtering, described in BCP38, asks ISPs to prevent packets with spoofed source addresses from leaving their networks, which when widely implemented would significantly reduce the effectiveness of amplification attacks. Load balancing distributes incoming traffic across multiple servers so that no single host bears the full load of an attack. Web application firewalls can detect and block application-layer DDoS patterns such as Slowloris and HTTP floods. Access control lists and firewall rules can block traffic matching known attack signatures. Capacity planning and over-provisioning ensure that the network and server infrastructure can absorb a moderate attack while still serving legitimate users.
