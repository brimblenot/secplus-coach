Mitigation refers to the actions taken to reduce the impact, likelihood, or scope of a security event, whether that event has already occurred or represents a potential future threat. Effective mitigation is not a single action but a collection of complementary techniques applied across systems, networks, and processes. The Security+ exam expects candidates to understand both what each mitigation technique does and when it is appropriate to apply each one.

Patching is the most straightforward and consistently impactful mitigation technique. Software vendors release patches to correct vulnerabilities in operating systems, applications, firmware, and device drivers. An unpatched vulnerability with a working public exploit represents a readily actionable risk that can often be eliminated entirely by applying the vendor-provided fix. Patch management as a process involves several steps: inventorying all software and firmware versions across the environment to identify what patches are applicable, testing patches in a non-production environment to verify they do not break critical functionality, deploying patches in scheduled maintenance windows to minimize disruption, verifying successful installation, and documenting the change for audit purposes. Large organizations use automated patch deployment tools such as Windows Server Update Services for Microsoft products, Microsoft Endpoint Configuration Manager for broader enterprise management, and Ansible or similar configuration management tools for heterogeneous environments. The tension in patch management is between the speed required for critical vulnerabilities that are actively being exploited and the caution required for patches that might destabilize production systems. Vulnerabilities that are actively exploited in the wild typically require emergency patching outside the normal schedule, with expedited testing or even direct deployment in cases where the risk of exploitation outweighs the risk of a patch-related issue.

Encryption limits what an attacker can do with data they have obtained. Full disk encryption, implemented with BitLocker on Windows, FileVault on macOS, and LUKS on Linux, ensures that a stolen or lost laptop or storage device yields only unreadable ciphertext without the decryption key. File-level encryption using the Windows Encrypting File System allows individual files and folders to be protected independently of full disk encryption. Application-level encryption protects data within specific applications regardless of whether filesystem encryption is in place. Encrypting data in transit using TLS prevents interception of data as it moves between systems. The combination of encryption at rest and in transit reduces the value of a breach even when an attacker has gained access to systems or storage.

Monitoring provides the visibility needed to detect attacks, investigate incidents, and verify that security controls are working. Security Information and Event Management systems, commonly called SIEM platforms, aggregate log data from across the environment including operating systems, network devices, firewalls, authentication systems, and applications. The SIEM correlates events across sources to identify patterns that suggest malicious activity, such as failed authentication attempts followed by a successful login from a new location, and generates alerts for security analysts to investigate. Endpoint Detection and Response platforms monitor host-level activity including process execution, file system changes, registry modifications, and network connections, providing behavioral visibility that complements log-based SIEM detection. Network Detection and Response monitors network traffic for anomalous patterns. User and Entity Behavior Analytics baselines the normal behavior patterns of individual users and systems, then generates alerts when behavior deviates significantly from the established baseline, which can detect insider threats and compromised accounts that use valid credentials in abnormal ways.

Isolation removes a compromised or vulnerable system from network connectivity while maintaining some level of controlled access for investigation and remediation. Network isolation can be implemented through firewall rule changes that block all traffic to and from the affected system except for connections from specific administrative systems needed for forensic analysis and remediation. Physical isolation involves disconnecting the network cable from the affected device. Isolation is a critical step in incident containment because it prevents the attacker from issuing further commands through their command and control channel, stops lateral movement from the compromised host to other systems, and halts active data exfiltration.

Containment is the broader incident response objective that isolation supports. In addition to isolating affected systems, containment involves blocking the attacker's lateral movement paths by changing compromised credentials across all systems where those credentials were used, disabling affected services that are not needed for business operations, implementing emergency firewall rules that block traffic patterns associated with the attack, and preserving forensic evidence on affected systems before beginning remediation.

Quarantine is typically the automated response executed by an Endpoint Detection and Response platform when a host is identified as potentially compromised. The EDR platform moves the host to a restricted network segment or applies firewall rules that block all traffic except communication with the EDR management infrastructure, allowing the security team to conduct forensic analysis and execute remediation steps remotely while preventing the affected host from communicating with attacker infrastructure or internal systems.

Compensating controls are alternative security measures applied when a primary security control cannot be implemented. A legacy system that cannot be patched because the vendor no longer supports it or because a critical application will not run on a patched version presents a common scenario requiring compensating controls. For such a system, the organization might implement network isolation that restricts the system to only the specific IP addresses and ports it requires for its function, deploy an application-layer firewall that inspects and filters traffic to and from the system, and implement enhanced monitoring with alerting on any unusual activity involving the system. Compensating controls are a formal concept in compliance frameworks including PCI DSS, which explicitly provides a mechanism for documenting and approving compensating controls when primary controls cannot be implemented.

Exceptions and exemptions are the formal processes by which an organization acknowledges that a security control is not being applied and documents the rationale. A risk acceptance decision requires that a business owner explicitly acknowledge the residual risk created by the exception, that the exception be documented in the organization's risk register, that a review date be set to reassess whether the exception remains appropriate, and ideally that compensating controls be identified to reduce the risk during the exception period. Exceptions should be time-limited wherever possible, with a defined plan to eliminate the exception or transition to full compliance.

Application removal addresses security risk by eliminating software entirely rather than attempting to secure it in place. Every application installed on a system represents potential attack surface: the application may have vulnerabilities, it may run as a privileged service, it may open network ports, or it may process data that could contain malicious input. Removing applications that are no longer required for business purposes reduces this surface permanently and eliminates the ongoing maintenance burden of keeping those applications updated. Application removal is more complete than disabling a service because it removes not only the running service but also the associated binary files, configuration data, and scheduled tasks that might be leveraged by an attacker.

Application isolation runs applications in sandboxed environments that limit what the application can access even if it is exploited. Modern browsers implement tab-level sandboxing that confines a compromised web page to a restricted process context. Mobile operating systems on iOS and Android enforce per-application sandboxes that prevent applications from accessing other applications' data. Windows AppContainer and macOS App Sandbox provide similar isolation for desktop applications. Application virtualization platforms run applications in isolated containers on the server, streaming the user interface to the client without installing the application or its dependencies on the endpoint.

Deny listing, also called blacklisting, blocks specific known-malicious applications, IP addresses, domains, email senders, or file hashes from being used or accessed. Deny listing is reactive because it can only block things that have been identified as malicious. New malware samples, newly compromised infrastructure, and novel attack techniques are not blocked until they are identified and added to the deny list. This creates an inherent lag between when a threat becomes active and when deny listing provides protection.

Allow listing, also called whitelisting, takes the inverse approach by permitting only explicitly approved applications, IP addresses, domains, and behaviors. An endpoint configured with application allow listing can only execute programs whose hash, certificate, or filesystem path is on the approved list. All other execution attempts are blocked by default, regardless of whether the attempted program is known to be malicious. This proactively blocks novel malware, zero-day payloads, and living-off-the-land tools that are not yet known to threat intelligence feeds, because they are not on the approved list. Windows Defender Application Control and AppLocker implement hash-based, certificate-based, and path-based allow listing for applications and scripts. The operational challenge of allow listing is maintaining the approved list as software changes, which requires careful change management processes and can create friction for users who need to run new or updated software.

Scanning provides automated discovery and assessment of vulnerabilities and configuration weaknesses. Vulnerability scanners use a database of known vulnerability signatures to probe systems for the presence of unpatched software, weak configurations, and exposed services. Credentialed scans authenticate to each target system and inspect installed software versions and configuration settings directly, providing more accurate results than uncredentialed scans that can only observe what is exposed over the network. Web application scanners probe web applications for common vulnerabilities including SQL injection, cross-site scripting, and misconfigured access controls. Configuration compliance scans compare system configurations against security baselines such as CIS Benchmarks to identify settings that deviate from the recommended secure configuration. Regular scanning provides ongoing visibility into the evolving vulnerability landscape across the organization's systems.

Least privilege enforcement as an ongoing practice involves periodically reviewing the access rights assigned to all accounts and revoking any that exceed current requirements. Access creep is the tendency for accounts to accumulate permissions over time as users move between roles, as systems are reconfigured, and as access is granted for specific projects that then concludes. Regular access recertification campaigns require account owners and managers to review and confirm that each permission assignment remains appropriate, revoking those that are no longer justified. Just-in-time access for privileged operations provides elevated permissions only for the duration of a specific administrative task, automatically revoking them when the task is complete.

Multi-factor authentication is both a primary security control and a powerful mitigation for credential compromise. Even when an attacker has obtained valid credentials through phishing, password spraying, credential stuffing, or malware, MFA prevents those credentials from being used for unauthorized access because the attacker cannot satisfy the second factor requirement. Deploying MFA broadly, particularly for remote access, administrative accounts, and cloud service access, dramatically reduces the operational impact of credential theft.
