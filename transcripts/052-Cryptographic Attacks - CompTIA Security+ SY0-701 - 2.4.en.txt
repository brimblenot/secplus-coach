Cryptography underlies the security of nearly every communication and transaction in modern computing, from web browsing over HTTPS to wireless network encryption to digital signatures on software updates. When cryptographic algorithms and protocols are correctly implemented using appropriate key lengths, they are computationally infeasible to break through direct mathematical attack. As a result, attackers focus their efforts not on breaking the mathematics of AES or RSA directly but on attacking the implementation of cryptography, the protocols that negotiate it, the way keys and passwords are managed, or the physical properties of the hardware performing cryptographic operations. Understanding the major classes of cryptographic attacks is essential for the Security+ exam and for evaluating the security of real systems.

Brute force attacks attempt every possible key or password value until the correct one is found. The feasibility of a brute force attack is determined entirely by the size of the search space. A symmetric key with 256 bits has 2 to the power of 256 possible values, a number so large that no feasible amount of computing power, including all computers on earth running until the heat death of the universe, can search it exhaustively. Six-character passwords using only lowercase letters have only a little over 300 million possible values and can be cracked in seconds on modern graphics processing units. Eight-character passwords using uppercase, lowercase, digits, and special characters have approximately 700 trillion possibilities and can be cracked in hours to days depending on the hashing algorithm used. This is why password length is the single most important password security property: every additional character of length multiplies the search space by the character set size.

Dictionary attacks use pre-assembled lists of words, common passwords, and known breach passwords rather than exhaustively searching all character combinations. The rockyou.txt wordlist, derived from a 2009 breach of the RockYou social gaming platform that exposed 14 million accounts in plaintext, is the baseline wordlist used in most password cracking workflows and contains the most common passwords people actually use. Targeted wordlists augment the base wordlist with words specific to the target organization, its employees' names, its products, and its location. Tools such as Hashcat and John the Ripper perform dictionary attacks at speeds measured in billions of hash checks per second on modern GPU hardware, making offline dictionary attacks against poorly protected hashed credential stores extremely effective.

Hybrid attacks combine dictionary attacks with rule-based transformations. Common rules append or prepend numbers and symbols to dictionary words, apply capitalization patterns, substitute letters with visually similar characters such as replacing the letter a with the at sign and the letter e with the number three, and combine multiple words. These rules dramatically expand the effective wordlist coverage while still focusing effort on passwords that real humans actually choose, which follow predictable patterns far more often than security policy language suggests.

Password spraying is a technique that avoids account lockout by inverting the traditional relationship between accounts and password guesses. Rather than trying many passwords against one account, which typically triggers lockout after a small number of failures, password spraying tries a single password against every account in the organization and then waits before trying the next password. Corporate environments frequently have many accounts using seasonal passwords such as Summer2024 with an exclamation mark or the company name followed by a year, and a spraying attack can find these without ever attempting enough guesses against any single account to trigger lockout. This makes spraying nearly undetectable by traditional lockout-based defenses and highly effective in large Active Directory environments.

Credential stuffing automates the process of trying username and password pairs stolen from one service against other services, exploiting the fact that a substantial fraction of users reuse the same password across multiple sites. Automated tools submit breach credential pairs at high volume against login forms for banking, email, and other high-value services. Credential stuffing attacks have caused significant breaches at organizations whose own security was adequate: the attacker did not need to compromise their systems directly, only to find their users' passwords in a breach of another service. Multi-factor authentication is the most effective defense because the replayed credential pair is insufficient for access even if it is correct.

Rainbow table attacks precompute a massive lookup table mapping hash values back to their corresponding plaintext inputs. Rather than computing hashes on demand during an attack, which takes time, the rainbow table is consulted by looking up the target hash and finding the plaintext that generated it in seconds. Rainbow tables for common algorithms such as MD5 and NTLM cover all passwords up to a certain length and character set with extraordinary speed. Password salting completely defeats rainbow table attacks. A salt is a random value unique to each password that is combined with the plaintext before hashing, so that even if two users have the same password they will have different hashes. Because rainbow tables must be precomputed for a specific input, adding a unique per-user salt means the attacker would need a separate rainbow table for every possible salt value, which is computationally infeasible. Properly salted password databases must be attacked with per-hash dictionary or brute force approaches rather than table lookups.

The birthday attack is a probabilistic technique for finding hash collisions based on the counterintuitive mathematics of the birthday problem. In a group of just 23 people, there is approximately a 50 percent probability that two people share a birthday, despite there being 365 possible birthdays. The probability of a collision grows not linearly with the number of trials but with the square root of the space size, so finding any two inputs that produce the same hash requires far fewer trials than finding a specific hash match. For a hash function with an output of n bits, the birthday bound means collisions can be found in approximately 2 to the n over 2 trials. MD5 has a 128-bit output and has demonstrated practical collisions. SHA-1 has a 160-bit output and Google's SHAttered project in 2017 demonstrated a practical collision, producing two different PDF files with identical SHA-1 hashes. The practical consequence of collisions in hash functions used for digital signatures is that an attacker who can find a collision can potentially create two documents with the same hash, get one signed by a certificate authority or code signing infrastructure, and then substitute the other, forging the signature on the malicious document.

Collision attacks extend the birthday concept to generate two different inputs with the same hash value as an attack on specific targets. The December 2008 MD5 collision attack against certificate authorities demonstrated this concretely: researchers created a fraudulent certificate authority certificate that carried the same MD5 hash as a certificate legitimately signed by a trusted CA, allowing them to issue arbitrary trusted certificates.

Hash length extension attacks exploit the Merkle-Damgard construction used internally by MD5, SHA-1, and SHA-256. This construction processes input in fixed-size blocks and carries state between blocks. An attacker who knows the hash output of a message and the length of the original message but not the message content itself can compute the hash of the original message with additional data appended, without knowing the original message. This allows forging authentication tokens that include a hash of a secret concatenated with a message, which some poorly designed APIs use for message authentication. The defense is to use HMAC, the Hash-based Message Authentication Code, which applies the hash function twice with key mixing in a way that is not vulnerable to length extension.

Downgrade attacks force two communicating parties to negotiate a weaker cryptographic protocol or cipher suite than they would otherwise use. POODLE, Padding Oracle On Downgraded Legacy Encryption, exploited fallback logic in browsers and servers that would retry failed TLS connections using SSL version 3. SSLv3 uses CBC mode with padding that is vulnerable to an oracle attack where the attacker modifies ciphertext blocks and observes whether the server responds with a valid decryption or a padding error, allowing byte-by-byte decryption of the ciphertext without the key. BEAST, Browser Exploit Against SSL and TLS, targeted a weakness in CBC mode as implemented in TLS 1.0 that could be exploited as a chosen-boundary attack. CRIME, Compression Ratio Info-leak Made Easy, exploited TLS compression to perform a chosen-plaintext attack against compressed and encrypted traffic. DROWN, Decrypting RSA with Obsolete and Weakened eNcryption, allowed servers that still supported SSLv2 alongside TLS to have their TLS traffic decrypted by exploiting the SSLv2 export-grade key exchange mechanism. The universal defense is to disable all legacy protocol versions: SSLv2, SSLv3, TLS 1.0, and TLS 1.1 should be disabled, with TLS 1.2 as the minimum and TLS 1.3 preferred.

Padding oracle attacks specifically target block cipher implementations in CBC mode that reveal information about whether decryption produced valid padding through error messages or timing differences. By submitting modified ciphertext and observing whether the server returns a padding error or a content error, an attacker can learn information about the plaintext and decrypt it byte by byte without the key. The defense is authenticated encryption using modes such as AES-GCM, which checks message integrity before decryption and does not reveal padding information, or constant-time comparison functions that prevent timing-based oracle leakage.

Side-channel attacks recover cryptographic keys through physical measurements of a device performing cryptographic operations rather than through mathematical analysis of the algorithm. Timing attacks observe small variations in how long operations take, revealing information about key bits. Power analysis attacks measure the power consumption of a device during cryptographic operations, which correlates with the values being processed. Electromagnetic analysis captures radio frequency emissions from the device that similarly reveal internal state. Side-channel attacks are most relevant to hardware security modules, smart cards, embedded devices, and other constrained hardware.

The emerging threat from quantum computing affects cryptographic security over a longer time horizon. Shor's algorithm, executable on a sufficiently large quantum computer, efficiently solves the integer factorization and discrete logarithm problems that underpin RSA and Diffie-Hellman key exchange, rendering these algorithms insecure. Grover's algorithm provides a quadratic speedup for searching, which effectively halves the security level of symmetric algorithms, reducing AES-256 to the equivalent of 128 bits against a quantum attacker. The National Institute of Standards and Technology has been evaluating and standardizing post-quantum cryptographic algorithms designed to resist quantum attacks, with CRYSTALS-Kyber for key encapsulation and CRYSTALS-Dilithium for digital signatures among the first to be standardized.

A robust defense against cryptographic attacks requires selecting algorithms with proven security margins such as AES-256 for symmetric encryption and SHA-256 or SHA-3 for hashing, storing passwords with modern adaptive hashing functions such as bcrypt, scrypt, or Argon2 that incorporate salt and have configurable work factors that make offline cracking expensive, using authenticated encryption modes such as AES-GCM that provide both confidentiality and integrity, disabling deprecated protocols and cipher suites throughout the infrastructure, implementing key rotation policies that limit the data encrypted under any single key, supplementing password authentication with multi-factor authentication, and monitoring for deployment of deprecated algorithms using TLS scanning and configuration assessment tools.
