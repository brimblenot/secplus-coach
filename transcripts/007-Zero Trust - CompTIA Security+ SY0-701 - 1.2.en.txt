Zero trust is a security model and architecture philosophy built on the foundational principle of "never trust, always verify." In a zero trust model, no user, device, application, or network connection is granted trust simply because of its location or because it was previously authenticated. Every access request, regardless of whether it originates from inside the corporate network, a remote location, or a cloud environment, is treated as potentially hostile and must be explicitly authenticated, authorized, and continuously validated before access is granted.

Understanding why zero trust emerged requires understanding the failure of the traditional perimeter-based security model. In the traditional model, organizations built a strong defensive perimeter around their network, typically using firewalls and VPNs, and assumed that anything inside the perimeter was trustworthy. This model worked reasonably well when all employees worked in a single physical location, all applications ran in an on-premises data center, and the network boundary between internal and external was clearly defined. None of those conditions hold in modern computing environments.

The modern enterprise has dissolved the traditional perimeter. Employees work from home, coffee shops, airports, and hotels. Applications have moved from on-premises servers to cloud providers like AWS, Azure, and Google Cloud. Mobile devices access corporate resources from cellular networks outside any corporate perimeter. Business partners and contractors connect to internal systems from their own networks. Insider threats, which are threats from employees or contractors who already have legitimate internal access, cannot be addressed by a perimeter at all. An attacker who successfully phishes an employee's credentials or breaches one internal system can move laterally across a flat, implicitly trusting internal network with little resistance. The 2020 SolarWinds supply chain attack and the 2021 Colonial Pipeline ransomware incident both demonstrated the catastrophic impact of lateral movement through implicitly trusted internal networks.

Zero trust eliminates the concept of an implicitly trusted zone. Instead, trust must be earned and continuously verified based on the identity of the user, the health of the device, the sensitivity of the resource being requested, and the behavioral context of the request. Zero trust is not a single product but an architectural approach that combines multiple security technologies and principles.

The zero trust architecture is organized around two functional planes: the Control Plane and the Data Plane. Understanding these two planes is essential for the exam.

The Control Plane is where security policy decisions are made. It contains the intelligence and logic of the zero trust system. Within the Control Plane, two key components work together. The Policy Engine evaluates every access request by examining multiple contextual signals: the identity of the user (verified through strong authentication), the health and compliance status of the device making the request, the specific resource being requested, the time of day, the geographic location of the request, behavioral patterns, and threat intelligence data. The Policy Engine compares all of these signals against the organization's defined security policies and makes a decision to grant access, deny access, or revoke previously granted access. The Policy Administrator is the component that communicates the Policy Engine's decision to the enforcement point. If access is granted, the Policy Administrator creates access tokens or credentials and provides them to the enforcement mechanism.

The Data Plane is where policy enforcement actually occurs. The Policy Enforcement Point, commonly abbreviated PEP, sits between the user or device and the resource they are trying to access. The PEP intercepts every access request, passes it to the Control Plane for a policy decision, and then either allows or blocks the request based on the decision it receives. The PEP may be implemented as a software agent on devices, a network proxy, an API gateway, a micro-gateway in a cloud environment, or a combination of these. The key characteristic of the PEP is that all data traffic flows through it; it enforces the access decision but does not make the decision itself.

Adaptive identity is a zero trust concept in which the strength of the authentication and authorization required is dynamically adjusted based on contextual risk signals. Rather than applying the same authentication requirements to every login, an adaptive identity system evaluates risk in real time. If a user is logging in from their usual device at their usual location during normal business hours, the system might require only a password and a push notification. If the same user attempts to log in from a new country at 3 AM and then immediately requests access to sensitive financial data, the system might require a much stronger authentication challenge or deny access entirely. This approach reduces friction for low-risk access while increasing security for high-risk situations.

Microsegmentation is a critical zero trust network control that divides the internal network into very small, isolated segments. In a traditional flat network, once an attacker gains access to any internal system they can often communicate freely with any other internal system. Microsegmentation creates strict access controls between internal network segments so that even an attacker who compromises one system cannot easily move laterally to others. Each microsegment has its own access policy, and traffic between segments requires explicit authorization just as traffic from outside the network does. Software-defined networking (SDN) and next-generation firewall technologies are commonly used to implement microsegmentation.

Multi-factor authentication is a fundamental requirement of zero trust. Because zero trust eliminates the concept of a trusted network location, identity becomes the primary security boundary. MFA ensures that compromising a single credential is not sufficient to gain access, because the attacker also needs the second factor. Phishing-resistant MFA methods, such as hardware security keys using the FIDO2/WebAuthn standard, are the most robust because they are not susceptible to real-time phishing attacks that capture and replay OTP codes.

The principle of least privilege is applied rigorously in zero trust. Users receive only the minimum access permissions necessary to perform their specific job functions, and those permissions are scoped to specific resources for specific time periods rather than being broadly granted. Just-in-time (JIT) access provisioning, in which elevated privileges are granted only when needed and automatically revoked after a defined period, is a common pattern in mature zero trust implementations.

Continuous validation means that zero trust does not treat authentication as a one-time event at login. Sessions are periodically re-evaluated, and if the risk signals change (a device falls out of compliance, the user's location changes unexpectedly, anomalous behavior is detected), the session may be terminated and the user required to re-authenticate. This is in contrast to traditional session-based authentication where a session token, once issued, remains valid for its full lifetime regardless of changing circumstances.

Device health verification, also called endpoint posture checking, ensures that devices are in a known-good, compliant state before being granted access to resources. A zero trust endpoint policy might require that the device has current operating system patches applied, that endpoint protection software is installed and active, that disk encryption is enabled, that the device is enrolled in mobile device management (MDM), and that the device has not been jailbroken or rooted. Network Access Control, or NAC, is a technology that enforces device compliance before allowing a device to connect to the network, and is an important component of implementing device health verification at the network access layer.

Security zones remain relevant within zero trust as a way of thinking about the origin and destination of traffic flows. An untrusted zone encompasses traffic originating from the internet or external networks. A trusted zone encompasses corporate-owned devices and authenticated users with verified compliance status. An internal zone encompasses data center resources and applications. Zero trust applies explicit verification to all traffic between zones, including traffic from trusted to internal zones, eliminating the assumption that internal-to-internal traffic is automatically safe.

SASE, which stands for Secure Access Service Edge (pronounced "sassy"), is a cloud-delivered architecture that converges wide-area networking capabilities (SD-WAN) with network security services (CASB, SWG, ZTNA, FWaaS) into a single integrated cloud platform. SASE enables zero trust principles for distributed workforces by ensuring that users anywhere in the world connect through a consistent, policy-enforced security stack rather than backhauling traffic through a central corporate data center. ZTNA within SASE stands for Zero Trust Network Access and replaces traditional VPN by granting access only to specific applications that a user is authorized for, rather than placing the user's device on the full internal network.

Software-Defined Perimeter, or SDP, implements zero trust by dynamically creating one-to-one, encrypted network connections between authenticated users and specific resources. SDP makes all services dark and invisible by default; they do not respond to unauthenticated network probes. Only after the user's identity and device have been verified does the SDP controller provision a connection to the specific resource the user is authorized to access. This dramatically reduces the attack surface compared to traditional VPN, where the entire network may be accessible once connected.

Zero trust is particularly relevant to cloud security and hybrid work environments because it does not depend on network location as a trust signal. In a cloud environment, workloads may run anywhere, users may connect from anywhere, and there is no physical perimeter to defend. Identity-centric zero trust, in which every access decision is based on verified identity, device health, and behavioral context, provides consistent security across on-premises, cloud, and hybrid environments. This shift means that identity infrastructure, particularly a robust identity provider with MFA and conditional access policies, has become the most critical security boundary in modern organizations.
