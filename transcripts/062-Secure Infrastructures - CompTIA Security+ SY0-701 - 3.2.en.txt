Designing a secure infrastructure requires more than deploying a firewall at the network perimeter. Modern attackers expect perimeter defenses and have developed techniques to bypass them — phishing emails that deliver malware from the inside, compromised credentials that grant authenticated access, supply chain attacks that introduce malicious code through trusted software updates. A secure infrastructure applies multiple overlapping layers of protection so that an attacker who successfully bypasses or evades one control encounters another, and then another, before reaching their ultimate objective. This principle is called defense in depth, and it is the organizing philosophy for secure network design.

Defense in depth means that no single control is relied upon to stop every attack. Physical security controls protect access to facilities and hardware. Network perimeter controls — firewalls, IDS/IPS — filter traffic entering and leaving the organization. Network segmentation limits how far a threat can spread once inside the perimeter. Host-based controls — endpoint detection and response, host firewalls, anti-malware — protect individual systems even when network controls are bypassed. Application security controls — input validation, authentication, authorization — protect the application layer. Data controls — encryption, data loss prevention — protect sensitive data even when application and network controls fail. Monitoring and logging ensure that when an attack does occur, it is detected and can be investigated. Each layer independently provides some protection, and together they create a far more resilient posture than any single control could achieve alone.

Network segmentation is one of the most impactful secure design choices an organization can make. Segmentation divides the network into distinct zones, limiting the blast radius of a compromise. The foundational segmentation model places the network into three zones: the untrusted external network — the internet — a demilitarized zone, or DMZ, and the trusted internal network. The DMZ is a semi-trusted middle zone that hosts services accessible from the internet but that should not have unrestricted access to internal systems.

In a traditional three-zone DMZ architecture, public-facing servers — web servers, email servers, public DNS servers — are placed in the DMZ. A stateful firewall separates the internet from the DMZ, permitting inbound connections to specific ports on DMZ servers — typically port 80 and port 443 for web traffic — while blocking all other inbound connections. A second stateful firewall separates the DMZ from the internal trusted network. The rules governing the boundary between the DMZ and the internal network are critical. Traffic from the internal network can initiate connections to DMZ servers — administrators need to manage and monitor those servers from inside. The DMZ must be allowed to send traffic to the internet for legitimate purposes — email delivery, software updates, DNS resolution. Critically, DMZ servers must not be permitted to initiate connections into the internal trusted network. If a web server in the DMZ is compromised, this rule prevents the attacker from using that server as a pivot point to directly attack internal systems. Any data exchange between the DMZ and the internal network should occur through controlled mechanisms — a database server in the internal network that the DMZ web server queries through a tightly controlled firewall rule, rather than the web server having open access to the internal network. This architecture significantly limits what an attacker can do if they successfully compromise a DMZ host.

Screened subnets extend this concept. A screened subnet sits between an outer firewall facing the internet and an inner firewall facing the trusted internal network, creating a protected zone where both firewalls must be compromised for an attacker to reach internal systems. This two-firewall design is a core pattern for high-security network architecture.

The principle of implicit deny underpins all effective firewall design. By default, all traffic is denied unless explicitly permitted by a rule. This is the opposite of permitting all traffic and trying to deny specific attacks, which is an impossible task as attack types are unlimited. Implicit deny means that new services can only be accessed if a deliberate, reviewed decision is made to allow them. Least privilege applied to network traffic means that firewall rules permit the minimum necessary traffic — the specific source addresses, destination addresses, protocols, and ports needed for a legitimate business function — rather than overly permissive rules that allow broad traffic flows for administrative convenience.

Security zones are a logical construct that extends segmentation beyond simple inside-versus-outside. Zones might include an internet zone, a DMZ zone, a screened zone for particularly sensitive DMZ services, an internal zone for general corporate systems, a server zone for backend infrastructure, a database zone for data stores, a management zone for administrative access, and an IoT zone for connected devices with poor security posture. Each zone has defined rules governing what traffic can flow between zones, making security policies easier to understand, audit, and maintain than large flat rule bases governing individual hosts. Naming conventions for zones — trusted, untrusted, screened — make the intent of security rules immediately clear and reduce the likelihood of misconfiguration.

Bastion hosts are highly secured, hardened systems designed to be the single, controlled entry point into a protected network segment. The SSH bastion, also called a jump server or jump host, is the most common form. All administrative access to servers within a protected zone must pass through the bastion: an administrator's workstation connects via SSH to the bastion first, and from the bastion initiates another SSH connection to the target server. The bastion itself is minimal — it runs only the software absolutely necessary for its function, nothing more. It is patched immediately when patches are available. Multi-factor authentication is required to connect to the bastion. All sessions through the bastion are logged, and ideally recorded in full, providing a complete audit trail of every administrative action taken on protected systems. Session recording is a forensic capability that may be essential for incident investigation and regulatory compliance. Privileged Access Management solutions such as CyberArk and BeyondTrust provide enterprise-grade bastion functionality with GUI interfaces, session recording, just-in-time access provisioning that grants administrative access for a defined time window and then revokes it automatically, and integration with ticketing systems to ensure that administrative actions are tied to change control records.

Zero trust network architecture is a security model based on the principle of never trust, always verify. Traditional network security implicitly trusted any device that was inside the network perimeter — once a device was on the corporate LAN, it could access most internal resources without additional authentication. Zero trust removes this implicit trust entirely. Every access request — regardless of whether it originates from inside or outside the network — is authenticated, authorized against a specific policy, and verified before access is granted. Authorization is evaluated per-request, not granted once for an entire session. Zero Trust Network Access, or ZTNA, is the technology implementation of zero trust principles for network access, replacing traditional VPN in many architectures. Where a VPN grants a remote user broad access to the internal network after authenticating once, ZTNA grants access only to the specific applications and resources the user is authorized to access, evaluated continuously based on user identity, device posture, location, and behavior.

Virtual Private Cloud design in cloud environments mirrors the DMZ and segmentation concepts of on-premises networks. Organizations create a VPC that defines their private IP address space within the cloud provider. Within the VPC, subnets are designated as public or private. Public subnets have route table entries that allow traffic to flow to and from the internet through an internet gateway — these subnets host resources like load balancers and web servers that must be accessible from the internet. Private subnets have no direct internet route — they host backend servers, databases, and application tier resources. Security groups act as stateful firewalls at the instance level, controlling which traffic can reach each virtual machine or container. Network ACLs provide a stateless subnet-level filtering layer. VPC Flow Logs capture metadata about traffic flows for monitoring, anomaly detection, and forensic investigation. VPN connections or AWS Direct Connect, Azure ExpressRoute, and Google Cloud Interconnect provide private, encrypted connectivity between the cloud VPC and on-premises networks for hybrid architectures.

Infrastructure change management ensures that all changes to network and security infrastructure go through a formal review and approval process before being implemented. Unauthorized or poorly tested changes are a significant source of security gaps — a firewall rule added to troubleshoot a problem that is never removed afterward, a security group in a cloud environment opened broadly during testing and left open in production. Change management processes require that proposed changes are reviewed for security implications, tested in non-production environments, approved by appropriate stakeholders, implemented according to a defined plan with rollback procedures, and documented. Change control integrates with infrastructure as code practices where changes must be submitted as code modifications and reviewed through pull request processes, creating an auditable history of all changes.

Physical network security is an often-overlooked component of secure infrastructure. Network cabling should be routed through locked conduits and wiring closets rather than being accessible in open ceiling spaces or under desks. Wiring closets housing switches and patch panels should be locked, with access limited to authorized personnel and access logged. Out-of-band management networks provide dedicated, separate network paths for administrative access and console connections to infrastructure devices — separate from the production network that carries user traffic. Out-of-band management means that even if the production network is compromised or unavailable, administrators can still connect to and manage infrastructure devices through the management network. Servers and network equipment often have dedicated management interfaces — IPMI, iDRAC, iLO — that provide console access regardless of the state of the primary network interfaces.

Layer 2 security controls protect against attacks that target the switching infrastructure. Port security on managed switches limits the number of MAC addresses allowed on a port and takes a defined action — typically shutting the port down — if more MAC addresses are observed than the configured limit. Sticky MAC learning allows switches to dynamically learn the MAC address of the device connected to each port and then save that learning, automatically enforcing that only the expected device can connect. DHCP snooping configures the switch to validate DHCP messages, maintaining a binding table of legitimate IP address, MAC address, and port assignments, and blocking DHCP offers from ports not designated as trusted DHCP server ports — preventing rogue DHCP servers from redirecting client traffic. Dynamic ARP Inspection validates ARP packets against the DHCP snooping binding table, dropping ARP responses that claim incorrect IP-to-MAC mappings and blocking ARP spoofing or ARP poisoning attacks that redirect traffic through an attacker's system. IP Source Guard validates that the source IP address of traffic leaving a port matches the IP address assigned to that port according to the DHCP snooping binding table, preventing IP address spoofing at the switch level.

Spanning Tree Protocol guards protect against attackers who attempt to introduce unauthorized switches into the network to manipulate the spanning tree topology. BPDU Guard shuts down a port immediately if it receives a Bridge Protocol Data Unit — a spanning tree message — because access ports connected to end devices should never receive spanning tree messages. Root Guard prevents a connected switch from claiming the role of root bridge in the spanning tree, which could allow an attacker to redirect all network traffic through a switch they control.

Network monitoring provides the visibility needed to detect threats and investigate incidents. NetFlow and IPFIX generate records of network conversations — source and destination IP addresses, ports, protocols, timestamps, and byte counts — without capturing full packet content. Flow data is invaluable for detecting anomalous traffic patterns, unauthorized communications between zones, data exfiltration, and lateral movement. Full packet capture using network taps or SPAN ports provides complete forensic data for incident investigation, though the storage requirements are substantial. Baseline establishment — understanding what normal traffic patterns look like for the organization — is a prerequisite for anomaly detection. Anomaly detection tools compare observed traffic against baselines and alert when significant deviations occur.

Infrastructure hardening follows a consistent checklist regardless of the type of device or system. Change all default credentials before deploying any device. Disable and remove all services, ports, and features that are not required for the device's function — every unused service is a potential attack surface. Apply all available security patches. Document all configuration changes. Scan configurations regularly using automated tools to detect drift from the established hardened baseline. Repeat vulnerability scanning after any significant configuration change. The goal is not to achieve a one-time hardened state but to maintain that state continuously as the environment evolves.
