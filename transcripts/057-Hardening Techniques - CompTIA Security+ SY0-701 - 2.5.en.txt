System hardening is the process of reducing a system's attack surface by removing unnecessary functionality, applying secure configurations, and closing known vulnerabilities. The guiding principle of hardening is minimal footprint: a system should have installed only what is necessary for its intended function, configured only what is required for its authorized use, and running only the services needed to fulfill its role. Every unnecessary service, open port, default account, or unused feature represents a potential vector through which an attacker might gain access, so hardening systematically identifies and eliminates each one.

Operating system hardening begins with applying all available security patches promptly, as an unpatched OS is the most common vector for exploitation. Manufacturers such as Microsoft release monthly security updates that address known vulnerabilities, and deviating from the current patch level leaves systems exposed to attacks for which public exploits may already exist. Beyond patching, OS hardening requires auditing and securing user accounts. Default accounts such as the Guest account on Windows should be disabled, and default administrator account names should be renamed or replaced with accounts whose names do not reveal their privilege level. Password policies should enforce a minimum length of twelve or more characters with complexity requirements. Account lockout policies should trigger after a small number of failed authentication attempts to limit online brute force. All user accounts should be granted only the privileges required for their function, with elevated rights granted only when needed and immediately revoked when the task is complete. Administrative accounts should be separate from the daily-use accounts of the same person, so that email, web browsing, and other routine activities are performed under a non-privileged identity.

The host-based firewall is a critical OS hardening control for any system that connects to a network. Unlike a perimeter firewall that controls traffic between network segments, the host-based firewall controls traffic to and from the individual system and applies its rules regardless of which network the system is connected to. This makes it essential for laptop computers that move between trusted corporate networks and untrusted public networks. Windows Defender Firewall, iptables, and nftables on Linux systems provide host-based firewall functionality. The firewall should be configured to deny all inbound connections by default and allow only the specific services and ports required for the system's function. Outbound rules can similarly restrict which processes are permitted to make network connections, helping to detect or block malware that attempts to communicate with command and control infrastructure.

Endpoint Detection and Response deployment is a foundational hardening step for any modern endpoint. EDR platforms go substantially beyond traditional antivirus by monitoring system behavior continuously. Where antivirus compares file hashes against a signature database, EDR watches process execution trees, detects when legitimate processes are being used in unusual ways, monitors memory for injection of code into other processes, tracks network connections made by each process, and applies machine learning to identify patterns consistent with known attack techniques. When EDR detects suspicious activity, it can automatically quarantine the affected system, terminate malicious processes, and initiate rollback to a known-good state without waiting for human intervention. The combination of behavioral analysis, memory inspection, and automated response makes EDR effective against both known malware and novel threats that do not match any existing signature.

Data encryption is a hardening control that protects the confidentiality of stored information regardless of other access controls. Full disk encryption using BitLocker on Windows, FileVault on macOS, or LUKS on Linux encrypts the entire storage volume including the operating system, user files, and any application data. An attacker who steals a laptop or removes a storage device finds only encrypted data without the decryption key, which is typically protected by a PIN, password, or TPM chip. File-level encryption using the Windows Encrypting File System provides more granular protection for specific files and folders without encrypting the entire volume. Encryption of network traffic using TLS ensures that data transmitted between systems cannot be captured and read by anyone who intercepts the network communication.

Host-based intrusion detection and prevention systems extend visibility into the operating system itself. Host-based IDS monitors system calls, file system changes, registry modifications, and network connections, generating alerts when patterns consistent with known attacks are detected. Host-based IPS can take automated blocking action when intrusion attempts are detected, such as terminating processes that are attempting to modify protected registry keys or blocking network connections from processes that should not be making outbound connections. This functionality is often integrated into the EDR platform.

Application hardening focuses on ensuring that the software running on a system is both current and configured securely. Applications should be updated to the current version promptly, as outdated application versions frequently contain known vulnerabilities. Unused features, modules, and extensions should be removed or disabled, as each represents additional code that could contain vulnerabilities. Debug modes and diagnostic endpoints should be disabled in production because they often expose sensitive information or allow operations not intended for production use. Error handling should be configured to return generic error messages to users while logging detailed diagnostic information locally, preventing information disclosure that could assist an attacker in mapping the application's internals. Applications should communicate over TLS for all network connections, and older protocol support should be disabled.

Web server hardening addresses the specific security requirements of HTTP-serving software. Directory listing should be disabled so that requests to a directory without a default document return an error rather than a listing of the directory contents, which would expose the server's file structure. Server version banners in HTTP response headers should be suppressed because they reveal the exact software version and help attackers identify applicable vulnerabilities. Unnecessary HTTP methods should be disabled; most web applications require only GET and POST, and methods such as TRACE, PUT, and DELETE should be blocked unless specifically required. Security headers should be configured: HTTP Strict Transport Security instructs browsers to only use HTTPS for the domain; Content Security Policy restricts what resources the page is permitted to load and from where; X-Frame-Options prevents the page from being embedded in iframes to defend against clickjacking; and X-Content-Type-Options prevents browsers from MIME-sniffing responses away from the declared content type.

Network device hardening applies to routers, switches, firewalls, wireless access points, and other infrastructure equipment. The highest priority action for any newly deployed network device is changing all default passwords, as these are publicly documented by vendors and are among the first things an attacker will try. Telnet, which transmits all data including credentials in cleartext, should be disabled and replaced with SSH for command-line device management. HTTP management interfaces should be disabled and replaced with HTTPS. SNMP versions one and two use community strings as their only authentication mechanism, which provides weak security; SNMPv3 provides authentication and encryption and should be used exclusively where SNMP is required. Services that are not needed should be disabled, including Cisco Discovery Protocol if not required, the Finger protocol, and Dynamic Trunking Protocol on access ports. Access control lists should restrict management access to the device to specific trusted IP addresses, preventing any internet host from attempting to authenticate to the management interface. 802.1X port authentication should be implemented to ensure that devices can only connect to switch ports after authenticating with valid credentials. BPDU guard on access ports prevents unauthorized switches from participating in the spanning tree topology. DHCP snooping validates DHCP traffic to prevent rogue DHCP servers from providing false configuration information to clients. Dynamic ARP Inspection, which depends on DHCP snooping, validates ARP packets to prevent ARP poisoning attacks.

Wireless network hardening requires selecting the strongest available security protocol. WPA3 is the current standard and provides the Simultaneous Authentication of Equals handshake that resists offline dictionary attacks. Where WPA3 is not available, WPA2 should be used with a complex passphrase of at least twenty characters. WPA is insufficient, and WEP is completely broken and should never be used. WPS should be disabled entirely because the PIN-based authentication can be brute-forced in hours using publicly available tools. Default SSID names that identify the hardware vendor or model should be changed to names that do not reveal infrastructure details. Default administrative credentials on the access point itself must be changed immediately. In enterprise environments, WPA2-Enterprise or WPA3-Enterprise using 802.1X with a RADIUS server provides per-user authentication with individual credentials, so that a departing employee's access can be revoked without changing the passphrase for all users. EAP-TLS, which requires certificates on both clients and the access point, is the most secure EAP method and prevents evil twin attacks because the rogue access point cannot present a valid server certificate.

Mobile device hardening requires enforcing PIN or biometric authentication, enabling full device encryption which is the default on modern iOS and Android devices, enrolling devices in Mobile Device Management to enforce security policies and enable remote wipe, disabling developer mode and USB debugging which provide privileged access to the device, and using VPN when connecting over untrusted networks. MDM profiles can enforce these settings and prevent users from modifying them.

Default password changes are a foundational hardening requirement that applies to every device and every application. Factory-default credentials are published by vendors in documentation accessible to anyone, and attackers systematically scan for devices using default credentials. Every password on every managed device and application must be changed before the device or application is put into production use. Discovered default credentials should be stored in a privileged access management system or password manager and never reused across devices.

CIS Benchmarks, published by the Center for Internet Security, are free, consensus-developed security configuration guides for specific versions of operating systems, applications, and cloud platforms. Each benchmark includes specific configuration settings with pass/fail tests that can be run to verify compliance. Level 1 benchmarks represent a balanced security posture that provides substantial security improvement without significantly impacting usability or performance. Level 2 benchmarks represent a high security posture appropriate for environments handling the most sensitive data, and some Level 2 settings may impact performance or compatibility.

Security Technical Implementation Guides, or STIGs, are security configuration standards developed and published by the Defense Information Systems Agency for use in US Department of Defense environments. STIGs are more stringent than CIS Level 2 benchmarks and are required for systems connected to DoD networks. STIG requirements are published for a wide range of operating systems, applications, and network devices.

A security baseline documents the minimum acceptable security configuration for a particular system type and provides the standard against which all systems of that type are assessed. Baselines are enforced through Group Policy in Active Directory environments for Windows systems, through configuration management tools such as Ansible, Chef, Puppet, or Salt for mixed environments, and through Mobile Device Management for mobile devices. Automated compliance scanning tools compare running configurations against the defined baseline and report any deviations, enabling continuous enforcement rather than point-in-time assessment. Deviations from baseline should trigger a review to determine whether they represent an intentional configuration change that needs to be approved and documented or an unauthorized modification that needs to be investigated and remediated.

Patch management for firmware, drivers, and embedded systems is frequently overlooked but equally important. Network equipment firmware, storage controller firmware, server BMC and iDRAC firmware, and IoT device firmware all contain vulnerabilities that are addressed by vendor updates. These devices often do not have automated update mechanisms and require manual intervention to update, and they may not be included in standard vulnerability scanning, creating blind spots in the patching posture. An inventory of all firmware versions across the environment, combined with regular review of vendor security advisories, is required to maintain coverage across these less-visible components.
